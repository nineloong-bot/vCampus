# 2 程序系统的分析

## 2.1 可行性分析

**技术可行性。** 本项目采用 Java 21 与 Maven 多模块工程，客户端界面使用 JDK 自带的 Swing 库，
网络通信使用 JDK 自带的 Socket 与对象序列化机制，数据库使用 Microsoft Access 并借助开源 JDBC
驱动 UCanAccess 访问，测试框架使用 JUnit 5、Mockito 与 AssertJ。所依赖的技术全部为成熟、免费、
文档完备的开源组件，不需要采购任何商业软件，也不需要专用硬件。项目组在前期已通过课程与自学
掌握 Java 语言、JDBC、Swing 与多线程编程的基本方法，技术上完全可行。

**经济可行性。** 系统仅运行在普通 PC 上，开发工具（JDK、Maven、Git、Access）均可免费获取。
数据库为单文件 Access 库，无需独立数据库服务器，部署成本极低。项目由课程组织，人力和时间投入
在课程安排范围内，经济上可行。

**操作可行性。** 客户端为桌面图形界面，操作方式与校内常用的信息管理系统一致，学生使用一卡通号
登录后即可在统一主界面中切换被授权模块；管理员的操作集中在各模块的管理页面上。用户不需要额外
培训即可上手，操作上可行。

**法律与安全可行性。** 系统仅在课程环境内使用测试数据，不采集真实个人信息；密码以 PBKDF2 哈希
加随机盐的形式存储，日志中禁止记录密码、盐、会话令牌等敏感信息。系统不涉及第三方商业接口，
合规性可控。

**进度可行性。** 项目采用"先搭公共骨架、再并行开发业务模块、最后统一集成"的推进方式，五个必做
模块由五名成员分别端到端负责，公共协议、客户端连接、Swing 外壳、事务与锁等公共部件指定专人
维护。按四周短学期进度计划，各阶段的阶段目标均可达成。

## 2.2 需求分析

### 2.2.1 总体功能需求

虚拟校园系统是一个面向校内学生、教师与管理员的综合信息管理系统，采用 C/S 架构，包含服务器端
与客户端两个可独立运行的程序。系统必须实现以下五个必做模块：

| 序号 | 模块 | 主要功能 |
| --- | --- | --- |
| 1 | 用户管理 | 注册／注销、登录／登出、授权与角色、账户状态管理、密码策略、安全审计 |
| 2 | 学生学籍管理 | 院系／专业／班级组织管理、学生录取建档、学号与一卡通号生成、学籍查询与变更、资料核对与审核 |
| 3 | 选课系统 | 学期与选课阶段管理、课程库与教学班管理、选课／退课／换课、重修、课表、修读结果导入、调整期审计 |
| 4 | 图书馆 | 图书检索、书目与馆藏管理、借书／还书／续借、借阅记录、借阅规则与罚金管理 |
| 5 | 校园商城 | 商品浏览与搜索、购物车与下单、模拟第三方支付、卖家入驻与店铺管理、商品与库存管理、管理员审核 |

### 2.2.2 角色与权限需求

系统基础角色只有三种，权限由服务端统一鉴权，客户端菜单隐藏不作为安全边界。

| 角色 | 用户管理 | 学籍管理 | 选课系统 | 图书馆 | 校园商城 |
| --- | --- | --- | --- | --- | --- |
| 学生 `STUDENT` | 本人账户 | 本人学籍及允许的申请 | 查询、选课、退课、课表 | 检索、借阅及本人记录 | 浏览、购物；可申请成为店主 |
| 教师 `TEACHER` | 本人账户 | 模块已有的教师能力 | 查询及教师课表 | 检索与教师借阅能力 | 浏览与购物 |
| 管理员 `ADMIN` | 用户、角色、状态、审计 | 学籍管理与审核 | 学期、课程、教学班及调整管理 | 馆藏、借阅与管理功能 | 店铺申请审核、店铺与商品管理 |

店主不是全局角色，而是通过入驻申请审批产生的业务能力，不改变用户的基础角色。

### 2.2.3 非功能需求

| 类别 | 需求 |
| --- | --- |
| 性能 | 支持多客户端并发访问；普通查询与写入在本机环境下的响应时间在秒级以内 |
| 并发正确性 | 课程名额不得超选；同一图书副本只能被一人借出；有限库存不得超卖；并发录取必须产生唯一且连续的编号 |
| 可靠性 | 关键写操作必须在数据库事务中完成，失败整体回滚，不留下半完成状态 |
| 安全性 | 密码只保存 PBKDF2 哈希；会话令牌不可预测且只保存在客户端内存；所有业务命令必须在服务端重新鉴权 |
| 幂等性 | 所有写命令必须携带全局唯一 `requestId`，重复提交不产生重复业务效果 |
| 可维护性 | 分层清晰，接口与实现分离；每个 Java 文件原则上不超过 200 行；接口、类与公开方法提供 JavaDoc |
| 可扩展性 | 新增业务模块只需注册新的处理器与命令，不修改既有模块内部实现 |
| 可用性 | 每个查询页面必须实现加载、正常、空结果、错误与断线五种界面状态 |

## 2.3 开发设计环境

### 2.3.1 JDK 与构建工具

| 项目 | 选型 | 说明 |
| --- | --- | --- |
| JDK | Java SE 21（`maven.compiler.release = 21`） | 使用 record、`var`、文本块等语言特性，不使用预览特性 |
| 构建 | Apache Maven 3.9+（聚合多模块工程） | 父 POM 固定在仓库根 `pom.xml` |
| 源码编码 | UTF-8 | `project.build.sourceEncoding` 与 `project.reporting.outputEncoding` 均为 UTF-8 |

课程材料建议兼容 JDK 1.8；本项目经小组确认统一使用 JDK 21，启动脚本会检测运行环境 Java 版本不低于 21。

### 2.3.2 开发工具与版本控制

| 项目 | 选型 | 说明 |
| --- | --- | --- |
| IDE | Visual Studio Code / IntelliJ IDEA / Eclipse | 任意支持 Maven 的 Java IDE |
| 版本控制 | Git | 采用特性分支开发，功能完成后合并到主分支 |
| 代码托管 | Gitee / 自建远端 | 课程要求推荐使用 Gitee |
| 代码规范 | 《Java 编码规范》 | 每个接口或类必须从属于包；接口、类与公开方法必须提供 JavaDoc |

### 2.3.3 数据库与 JDBC 驱动

| 项目 | 选型 | 说明 |
| --- | --- | --- |
| 数据库 | Microsoft Access（`vCampus.accdb`） | 单文件数据库，随课程要求统一使用 Access |
| JDBC 驱动 | UCanAccess 5.1.3（`io.github.spannm:ucanaccess`） | 纯 Java 驱动，程序直接连接数据库文件，无需配置 ODBC 数据源 |
| 连接串 | `jdbc:ucanaccess://<数据库文件路径>` | 路径由服务端配置项 `database.path` 给出 |
| 初始化 | `vcampus-database/schema/*.sql` 与 `seed/*.sql` | 按 `001_common` → `010_user` → `020_student` → `030_course` → `040_library` → `050_shop` 的顺序安装 |
