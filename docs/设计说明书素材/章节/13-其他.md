# 13 其他

## 13.1 构建与部署

### 13.1.1 构建命令

```bash
mvn clean verify        # 编译、单元测试、集成测试与覆盖率检查
mvn package             # 打包
mvn javadoc:aggregate   # 生成聚合 API 文档
```

构建产物输出到 `vcampus-distribution/lib`，包含两个可运行 JAR：`vCampusClient.jar` 与
`vCampusServer.jar`。两个 JAR 均通过 Maven Shade 插件把运行期依赖一并打入，运行环境只需安装
Java 21 或更高版本。

### 13.1.2 发行包结构

| 序号 | 路径 | 内容 |
| --- | --- | --- |
| 1 | `lib/vCampusServer.jar` | 服务器端可运行程序 |
| 2 | `lib/vCampusClient.jar` | 客户端可运行程序 |
| 3 | `config/server-with-data.properties` | 服务器端配置（含数据库路径） |
| 4 | `config/client.properties` | 客户端配置（服务器地址与端口） |
| 5 | `config/logback.xml` | 日志配置 |
| 6 | `data/vCampus.accdb` | Access 数据库 |
| 7 | `database/schema`、`database/seed` | 结构与初始化数据脚本 |
| 8 | `scripts/start-server-with-data.bat` / `.sh` | 启动服务器端 |
| 9 | `scripts/start-client.bat` / `.sh` | 启动客户端 |
| 10 | `scripts/reset-data.bat` / `.sh` | 重置演示数据 |
| 11 | `scripts/测试账号与密码.txt` | 测试账号说明 |
| 12 | `docs/` | 设计文档、使用说明与 UI 评审记录 |

### 13.1.3 部署与启动步骤

1. 在服务器主机安装 Java 21 或更高版本；
2. 确认 `config/server-with-data.properties` 中的 `database.path` 指向有效的数据库文件，
   首次运行可设置 `database.createIfMissing = true`；
3. 运行 `scripts/start-server-with-data.bat`，等待服务器端监听 `8888` 端口；
4. 在客户端主机上确认 `config/client.properties` 中的 `server.host` 与 `server.port` 指向
   服务器端地址与端口；
5. 运行 `scripts/start-client.bat`，使用测试账号登录。

默认已内置 1000 名测试学生及教师、课程、图书与商城数据。管理员账号 `TESTADMIN`、
学生 `213260001`、教师 `TESTTEACHER001` 的初始密码均为 `Test12345`。

## 13.2 配置项

### 13.2.1 服务器端配置（`server-with-data.properties`）

| 序号 | 配置项 | 默认值 | 取值范围 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | `server.port` | `8888` | 1–65535 | 服务监听端口 |
| 2 | `server.maxConnections` | `100` | 1–10000 | 任务队列容量 |
| 3 | `server.workerThreads` | `8` | 1–1024 | 工作线程数 |
| 4 | `database.path` | `data/vCampus.accdb` | 非空 | 数据库文件路径，相对基准目录解析 |
| 5 | `database.resourceRoot` | `database` | 目录 | schema 与 seed 脚本所在目录 |
| 6 | `database.createIfMissing` | `true` | `true` / `false` | 数据库缺失时是否从脚本生成 |
| 7 | `session.timeoutMinutes` | `30` | 1–1440 | 会话空闲超时（分钟） |
| 8 | `inventory.reservationMinutes` | `15` | 1–1440 | 商城库存预留有效时长 |
| 9 | `dedup.retentionHours` | `24` | 1–720 | 请求幂等记录保留时长 |

配置在启动时严格校验：缺少必填项、数值越界、数据库文件不存在或脚本目录无效都会抛出
`ConfigurationException`，阻止启动并给出可操作的中文提示，不允许带病启动。

### 13.2.2 客户端配置（`client.properties`）

| 序号 | 配置项 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 1 | `server.host` | `127.0.0.1` | 服务器地址 |
| 2 | `server.port` | `8888` | 服务器端口 |
| 3 | `connection.timeoutSeconds` | `10` | 建立连接超时 |
| 4 | `request.timeoutSeconds` | `10` | 请求响应超时 |
| 5 | `reconnect.attempts` | `3` | 断线重连尝试次数 |

## 13.3 日志与审计

### 13.3.1 日志

服务器端使用 SLF4J + Logback，日志配置位于 `config/logback.xml`。日志上下文应包含
`traceId`、`requestId`、`sessionId`、`userId`、`command` 与客户端地址，便于按一次请求串联排查。

| 序号 | 禁止入日志的信息 | 原因 |
| --- | --- | --- |
| 1 | 密码明文与 PBKDF2 哈希 | 敏感凭据 |
| 2 | 密码盐与迭代次数 | 敏感凭据 |
| 3 | 会话令牌 | 可被用于冒充登录 |
| 4 | 银行卡号与完整支付请求 | 敏感支付信息 |

### 13.3.2 安全审计

关键操作写入 `tblAuditLog`，记录操作账户、动作码、目标类型与标识、结果代码、客户端地址与时间。
审计记录只增不改、不做物理删除。典型动作码包括登录成功与失败、登出、密码修改、账户状态变更、
角色调整、学生账户开通、学籍变更、图书借还、商城审核与支付等。

## 13.4 测试

| 序号 | 测试层次 | 内容 | 工具 |
| --- | --- | --- | --- |
| 1 | 单元测试 | 领域规则、编号生成、罚金计算、密码哈希、命令处理器的参数与权限分支 | JUnit 5、AssertJ、Mockito |
| 2 | 数据库集成测试 | 仓储读写、唯一约束、外键、事务回滚、序列分配 | JUnit 5 + 独立 Access 副本 |
| 3 | 网络集成测试 | 通过真实 Socket 完成登录与业务命令的端到端调用 | JUnit 5 |
| 4 | 并发测试 | 多线程竞争同一教学班名额、同一副本、同一库存 | JUnit 5 多线程用例 |
| 5 | 覆盖率 | 使用 JaCoCo 统计，领域与服务代码行覆盖率目标不低于 80% | JaCoCo |
| 6 | 人工测试 | 按模块编写人工验收清单，覆盖正常流程与异常场景 | 见 `docs/testing/` |

每个命令的测试至少覆盖成功、参数错误与权限不足三种情况；集成测试使用独立的 Access 副本，
不污染演示库。

关键并发验收场景：

1. 20 人竞争最后一个课程名额不得超选；
2. 同一图书副本只能有一人借出成功；
3. 有限库存不得超卖；
4. 20 个并发新生录取请求必须得到唯一且连续的一卡通号与班内学号，回滚不得消耗序号；
5. 使用初始密码登录不得访问业务命令，改密后旧受限会话立即失效。

## 13.5 安全设计

| 序号 | 安全措施 | 说明 |
| --- | --- | --- |
| 1 | 口令派生 | 密码使用 `PBKDF2WithHmacSHA256` 加随机盐与迭代次数派生后存储 |
| 2 | 会话令牌 | 服务端用 `SecureRandom` 生成 32 字节随机令牌，客户端仅保存在内存中 |
| 3 | 服务端鉴权 | 所有命令在服务端重新鉴权，客户端菜单隐藏不作为安全边界 |
| 4 | 受限会话 | 使用初始密码登录后只能执行查询当前用户、修改密码与登出三条命令 |
| 5 | 登录失败锁定 | 连续登录失败达到阈值后锁定账户一段时间，并记录审计 |
| 6 | 会话撤销 | 账户禁用、注销或重置密码时立即撤销该用户的全部会话 |
| 7 | 错误信息收敛 | 不向客户端泄露 SQL、文件路径或异常堆栈，未知异常返回 `traceId` |
| 8 | 日志脱敏 | 密码、盐、会话令牌与支付信息禁止写入日志 |
| 9 | 输入校验 | 服务端对必填项、长度、格式与取值范围做统一校验，返回字段级错误 |

## 13.6 已知限制与后续工作

| 序号 | 事项 | 现状 | 后续建议 |
| --- | --- | --- | --- |
| 1 | 商城发货与确认收货 | `PREPARING` / `SHIPPED` / `COMPLETED` 状态与 `shippedAt`、`completedAt` 字段已在数据库预留，卖家订单查询为只读，尚无对应的协议命令与服务实现 | 补充卖家发货、买家确认收货命令与订单状态写服务 |
| 2 | 订单取消 | 当前仅支持支付超时自动取消，尚无买家主动取消订单命令 | 增加主动取消命令并复用库存释放逻辑 |
| 3 | 角色调整命令 | `USER_UPDATE_ROLE` 已退役，调用一律返回校验失败；`UserRoleDialog` 为遗留界面 | 确认是否恢复该能力，或移除遗留界面 |
| 4 | 事件推送 | `MessageType.EVENT` 已定义但尚未使用 | 如需订单状态变更实时提醒，可基于该类型实现推送 |
| 5 | 数据库并发上限 | 事务由 `TransactionManager` 全局串行提交，写吞吐受单点限制 | 教学规模下足够；如需扩展可改为按连接池隔离事务 |
| 6 | 座位与教室冲突 | 教学班时间冲突仅按学生已选课程判定，未做教室资源冲突检测 | 如需排课功能，补充教室资源冲突校验 |
| 7 | 密码复杂度策略 | 当前仅约束长度与初始密码强制修改，未强制复杂度组合 | 可增加大小写、数字与符号的组合校验 |

## 13.7 小结

本文档完成了虚拟校园系统的软件设计说明：在总体层面确定了 C/S 运行架构、Maven 多模块工程结构、
客户端与服务端的四层划分以及跨模块调用边界；在协议层面确定了以 `Message` 为唯一信封、
`ResponseBody` 统一应答、`ErrorDetail` 统一错误的通信契约，并规定了幂等、超时与重试语义；
在并发层面确定了"单接收线程 + 有界工作线程池 + 资源锁 + 串行事务 + 乐观锁"的模型与各模块的
资源键及加锁顺序；在数据层面确定了 37 张表的命名规范、字段类型、索引与约束，以及编号生成规则；
在模块层面分别给出了用户管理、学籍管理、选课系统、图书馆与校园商城的界面设计、业务流程、
类分析、业务接口、数据库表与错误码。

本文档可作为各模块编码、单元测试、集成测试与最终验收的统一依据。文档中所有接口、类与数据库
对象均与仓库源代码和数据库脚本保持一致；实现发生变更时，应同步更新本文档对应章节。
