# 1 引言

## 1.1 编写目的

本文档是"虚拟校园系统（vCampus）"的软件设计说明书，用于在需求分析与编码实现之间建立可执行的
技术约定，指导项目组完成系统的详细设计、编码、测试与交付。

本文档的预期读者包括：

- 项目组全体成员：作为各模块设计、编码与自测的统一依据；
- 指导教师与助教：作为阶段检查、组间互评与最终验收的依据；
- 后续维护人员：作为理解系统结构、扩展业务模块的入口文档。

本文档描述系统的总体结构、客户端与服务器端的逻辑分层、公共通信协议、并发与事务模型、数据库
结构与约束、各业务模块的界面、类与业务接口设计，并给出关键业务流程和错误处理约定。

## 1.2 背景

- **待开发软件系统的名称：** 虚拟校园系统（vCampus）。
- **项目任务提出者：** 东南大学计算机科学与工程学院《专业技能实训》课程组。
- **开发者：** 本项目小组（详见 1.5 节）。
- **用户：** 校内学生、教师与系统管理员。
- **运行环境：** 采用 C/S 架构。服务器端为独立 Java 进程，加载 Access 数据库并提供 Socket 服务；
  客户端为 Java Swing 桌面程序，通过 TCP 长连接访问服务器端。客户端不直接访问数据库。
- **课程要求：** 依据《软件实践安排(202509)》，必做模块为"用户管理、学生学籍管理、选课系统、
  图书馆、商店"；本项目在此基础上将"商店"实现为校园多商户商城，未实现银行、医院、宿舍、
  在线课堂等选做模块。
- **最终交付物：** 可运行的 `vCampusClient.jar`、`vCampusServer.jar`，数据库 `vCampus.accdb`，
  以及启动脚本、使用说明、源代码与 JavaDoc 文档。

## 1.3 定义

| 术语 / 缩写 | 全称或原词组 | 说明 |
| --- | --- | --- |
| C/S | Client / Server | 客户端／服务器架构，本项目客户端与服务端通过 Socket 通信 |
| Message | — | 客户端与服务器端之间传输的统一消息封装，可序列化 |
| DTO | Data Transfer Object | 数据传输对象，用于跨进程或跨层传递数据 |
| VO | Value Object | 值对象，不可变的数据载体 |
| POJO | Plain Old Java Object | 普通 Java 对象 |
| Repository | — | 数据访问层，负责数据库读写，向上提供领域语义的方法 |
| Port | — | 模块对外发布的调用接口，用于跨模块协作，替代直接访问其它模块的仓储 |
| Handler | — | 服务端消息处理器，负责解析请求、鉴权并调用业务服务 |
| EDT | Event Dispatch Thread | Swing 的事件分发线程，所有界面更新必须在其上执行 |
| CardLayout | — | Swing 布局管理器，本项目用于主界面的页面切换 |
| PBKDF2 | Password-Based Key Derivation Function 2 | 口令派生函数，本项目用于密码哈希 |
| UUID | Universally Unique Identifier | 通用唯一识别码，本项目内部主键统一使用 36 位 UUID |
| 一卡通号 | — | 学生的统一身份编号，也是学生登录系统的登录名 |
| 学号 | — | 学生在本专业、年级、班级内的编号 |
| SKU | Stock Keeping Unit | 商品规格与库存的最小单位 |
| rowVersion | — | 数据行的版本号，用于乐观锁并发控制 |
| 幂等 | Idempotence | 同一请求重复提交不产生重复业务效果 |
| 资源锁 | Resource Lock | 以 `resourceType + resourceId` 为键的逻辑互斥锁 |
| UCanAccess | — | 通过 JDBC 访问 Microsoft Access 数据库的开源驱动 |
| 受限会话 | Restricted Session | 使用初始密码登录后仅可改密的临时会话 |
