# 9 公共模块设计说明

## 9.1 设计目标与范围

公共模块（`vcampus-common`）承载同时被客户端与服务器端使用的接口、类和资源，是两侧保持契约
一致的基础。模块的设计目标为：

1. 定义唯一的通信协议，使客户端与服务器端对消息结构与命令语义的理解完全一致；
2. 集中放置跨模块共享的 DTO 与枚举，避免各模块重复定义造成字段不一致；
3. 定义统一的错误模型与错误码命名规范，使客户端能够稳定地把服务端错误映射为中文提示；
4. 不依赖 Swing、JDBC 或任何服务端实现，保证可以同时被两侧引用。

公共模块不包含任何业务逻辑与数据库访问代码。

## 9.2 用于网络传输的类必须可序列化

所有需要在网络上传输的对象都必须实现 `java.io.Serializable`，并显式声明 `serialVersionUID`。
本项目采用 Java 记录（`record`）实现不可变载荷，记录自身的字段一经构造不可修改，集合字段在
紧凑构造器中做防御性拷贝，避免跨线程共享可变状态。

```java
public record Message(
        String requestId,
        MessageType type,
        String command,
        String sessionToken,
        Serializable body,
        long timestamp) implements Serializable {
    @Serial
    private static final long serialVersionUID = 1L;
}
```

## 9.3 Message 消息封装

`Message` 是客户端与服务器端之间传输的唯一信封类型，所有请求、响应与事件都使用它承载。

| 序号 | 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | `requestId` | `String` | 非空；UUID；写命令全局唯一 | 请求唯一编号，同时作为幂等键与响应关联键 |
| 2 | `type` | `MessageType` | 非空 | 消息类型：`REQUEST` / `RESPONSE` / `EVENT` |
| 3 | `command` | `String` | 非空；形如 `MODULE_ACTION` | 命令名，服务端据此路由到处理器 |
| 4 | `sessionToken` | `String` | 登录前为空 | 会话令牌，服务端据此解析当前用户身份 |
| 5 | `body` | `Serializable` | 可序列化 | 请求体为模块请求 DTO，响应体为 `ResponseBody` |
| 6 | `timestamp` | `long` | 非空 | 消息创建时间（毫秒时间戳） |

### 9.3.1 MessageType 消息类型

| 序号 | 取值 | 说明 |
| --- | --- | --- |
| 1 | `REQUEST` | 客户端发往服务器端的请求 |
| 2 | `RESPONSE` | 服务器端对某个 `requestId` 的应答 |
| 3 | `EVENT` | 服务器端主动推送的事件（当前版本保留，尚未使用） |

## 9.4 ResponseBody 响应体

所有响应统一使用 `ResponseBody` 承载，使客户端可以先用统一代码判断成败，再按命令解析数据。

| 序号 | 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | `success` | `boolean` | 非空 | 是否成功 |
| 2 | `code` | `String` | 非空 | 结果代码，成功为 `SUCCESS`，失败为模块错误码 |
| 3 | `message` | `String` | 非空 | 面向用户的结果说明 |
| 4 | `data` | `T extends Serializable` | 成功时非空 | 业务数据，类型由命令约定 |
| 5 | `error` | `ErrorDetail` | 失败时非空 | 结构化错误详情 |

```java
public static <T extends Serializable> ResponseBody<T> success(T data) {
    return new ResponseBody<>(true, "SUCCESS", "成功", data, null);
}

public static <T extends Serializable> ResponseBody<T> failure(
        String code, String message, ErrorDetail error) {
    return new ResponseBody<>(false, code, message, null, error);
}
```

## 9.5 ErrorDetail 错误详情

| 序号 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| 1 | `code` | `String` | 稳定错误码，客户端的提示映射以此为键 |
| 2 | `message` | `String` | 错误说明文本 |
| 3 | `fieldErrors` | `Map<String,String>` | 字段级校验错误，键为字段名；构造时做不可变拷贝 |
| 4 | `traceId` | `String` | 服务端生成的追踪编号，用于在日志中定位同一次失败 |
| 5 | `retryable` | `boolean` | 是否建议客户端重试 |

`ErrorDetail` 只携带对客户端安全的错误信息，严禁把 SQL 语句、文件路径或异常堆栈放入其中；
未知异常统一转换为 `COMMON_INTERNAL_ERROR` 并返回 `traceId`。

## 9.6 通用请求与响应载体

| 序号 | 类名 | 类型 | 说明 |
| --- | --- | --- | --- |
| 1 | `EmptyRequest` | 枚举（单例 `INSTANCE`） | 无参数命令的请求体 |
| 2 | `EmptyResponse` | 枚举（单例 `INSTANCE`） | 无返回数据命令的响应体 |
| 3 | `EntityIdRequest` | 记录 | 以单一实体标识为参数的命令请求体，字段 `entityId` 非空且非空白 |

## 9.7 分页对象

| 序号 | 类名 | 字段 | 说明 |
| --- | --- | --- | --- |
| 1 | `PageResult<T>` | `items`、`page`、`pageSize`、`total` | 不可变分页结果；`items` 在构造时做不可变拷贝 |

列表类命令一律返回 `ArrayList` 或 `PageResult`，保证客户端可以按统一方式处理分页与空结果。

## 9.8 模块 DTO 一览

公共模块按业务模块划分子包，各子包内均为请求 DTO、查询对象、视图对象与枚举。

| 序号 | 子包 | 主要内容 |
| --- | --- | --- |
| 1 | `common.user` | 登录／注册／改密／查询等请求与响应 DTO、`UserRole`、`AccountStatus` |
| 2 | `common.student` | 录取建档、学籍查询与变更、资料申请与审核等 DTO 与枚举 |
| 3 | `common.course` | 学期、选课阶段、课程、教学班、选课与退课、重修、成绩导入等命令 DTO、查询对象与视图对象 |
| 4 | `common.library` | 图书、馆藏副本、借阅记录、借阅规则等 DTO 与查询对象 |
| 5 | `common.shop` | 商城请求 DTO、视图对象、状态枚举与 `ShopErrorCode` |

约束：禁止使用无类型的 `Map<String,Object>` 作为业务载荷；禁止把数据库实体对象或 Swing 组件
放入 `Message`。

## 9.9 错误码规范

错误码采用 `<模块>_<原因>` 的形式，全部使用大写字母与下划线。

| 序号 | 前缀 | 归属 |
| --- | --- | --- |
| 1 | `COMMON_` | 公共错误，如参数校验失败、权限不足、并发修改、内部错误 |
| 2 | `USER_` | 用户管理模块 |
| 3 | `STUDENT_` | 学籍管理模块 |
| 4 | `COURSE_` | 选课系统模块 |
| 5 | `LIBRARY_` | 图书馆模块 |
| 6 | `SHOP_` | 校园商城模块 |

公共错误码至少包括：`COMMON_VALIDATION_FAILED`、`COMMON_FORBIDDEN`、
`COMMON_CONCURRENT_MODIFICATION`、`COMMON_REQUEST_IN_PROGRESS`、`COMMON_INTERNAL_ERROR`、
`COMMON_UNKNOWN_COMMAND`、`COMMON_SERVER_BUSY`、`COMMON_SERVER_ERROR`。

## 9.10 序列化兼容性约定

1. 客户端与服务器端必须使用同一份 `vcampus-common` 产物，保证同一类的字段与 `serialVersionUID`
   完全一致。
2. 新增字段只能追加，不得修改既有字段的名称、类型或顺序；删除字段必须同步升级两侧。
3. 所有传输类显式声明 `serialVersionUID = 1L`，避免编译器自动生成值随代码变化而失效。
4. 集合字段一律在构造时拷贝为不可变集合，防止反序列化后出现共享可变状态。
