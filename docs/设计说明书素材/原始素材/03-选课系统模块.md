## 1. 模块背景

选课系统模块（课程中心）是虚拟校园 C/S 教学项目中五个必做业务模块之一，采用「模块化单体 + Swing 客户端 + TCP 对象流协议 + Access 数据库」的总体架构，按 `handler → service → repository` 分层实现，客户端不得直接访问数据库。模块负责学期、课程目录（课程库）、教学班与上课时间、选课阶段、普通选课、开课后的退改补、课表与重修选课，并向其他模块发布只读的选课查询端口（`CourseQueryPort`）。模块**不录入、保存或展示具体成绩**，仅保存外部权威来源导入的 `PASSED`/`FAILED` 粗粒度修读结果，用于判断重修资格。模块与用户/学籍模块通过 `CourseAuthorizationGateway`、`CourseStudentGateway` 等适配边界协作，不读取学籍或用户模块的 Repository（生产运行时通过 `CourseRuntimeAdapters` 适配用户模块的 `AuthorizationPort`/`UserIdentity`/`UserQueryPort` 与学籍模块的 `StudentQueryPort`）。并发一致性依赖「应用资源锁 + 数据库事务 + `rowVersion` 乐观锁 + 唯一索引」四者共同保证，不依赖 Access 的 `SELECT FOR UPDATE`。

## 2. 需求分析

### 2.1 学期管理

- 管理员维护学期代码（如 `2026-2027-1`）、学期名称、开课/结课日期与学期状态 `PLANNED`/`ACTIVE`/`CLOSED`。
- 学期在数据库中另保有 `enrollmentStartAt`/`enrollmentEndAt`/`adjustmentStartAt`/`adjustmentEndAt` 四个时间窗字段（`030_course.sql` 现状），用于 `COURSE_GET_TERM_PHASE` 的「当前阶段」只读快照；学生写操作的开放判定自 2026-09-04 设计起已切换为管理员手动控制的选课阶段，学期时间窗不再决定选课是否开放。
- 学期为只读查询对全部已登录角色开放；创建/修改仅管理员。

### 2.2 选课阶段管理

- 新增 `tblCourseSelectionPhase`，管理员手动创建、命名、开放和关闭选课阶段，阶段类型为 `ENROLLMENT`（正常选课）或 `ADJUSTMENT`（退改补选课）。
- 阶段状态语义：`DRAFT` 草稿（刚创建）、`PREVIEW` 预选课（只读可见）、`OPEN` 正式开放、`CLOSED` 已关闭。代码中 `CREATE` 只产生 `DRAFT`；`CHANGE_STATUS` 可把状态改为 `DRAFT`/`PREVIEW`/`OPEN`/`CLOSED`。
- 全系统在任意时刻最多存在一条可见开放记录（`phaseStatus IN ('PREVIEW','OPEN')`），由事务内再次查询 + 资源锁 + `rowVersion` 共同保证；开放前必须校验所属学期为 `ACTIVE`。
- 学生端选课页主标题使用当前开放阶段的 `displayTitle`；无开放阶段时回退为「选课」并只保留只读查询能力。

### 2.3 课程库（课程目录）

- 管理员维护课程代码（唯一，最长 24 字符）、课程名称（最长 128 字符）、学分（`DECIMAL(4,1)`，大于 0）、总学时（`LONG`，大于 0）、课程简介、启用标志 `isActive`（逻辑停用，不物理删除）。
- 提供关键词 + 启用状态的分页目录查询（`COURSE_CATALOG_SEARCH`），仅管理员。

### 2.4 教学班

- 管理员按「学期 + 课程 + 授课教师 + 教学班名称」创建教学班，设置容量 `capacity`（≥1）、状态 `DRAFT`/`OPEN`/`CLOSED`/`CANCELLED`，并维护一到多条上课时间（星期、起止节次、起止周次、教室）作为聚合一起写入。
- 授课教师必须为活动账户且角色为 `TEACHER`，通过 `CourseAuthorizationGateway.requireUserRole(userId,"TEACHER")` 校验。
- 已存在选课记录（含已退选留存记录）时，禁止修改教学班的所属学期、所属课程或上课安排；容量不得低于当前 `enrolledCount`。
- 提供按学期、关键词、上课星期、仅看有余量等条件的分页查询，面向 `STUDENT`/`TEACHER`/`ADMIN` 三类角色。

### 2.5 学生选课 / 退课 / 换课

- **普通选课**：仅学生本人；要求学籍为 `ACTIVE`、教学班为 `OPEN`、处于 `ENROLLMENT` 阶段、无重复选同一课程、无时间冲突、容量未满。
- **补选（调整期加选）**：仅 `ADJUSTMENT` 阶段开放，重新执行全部普通选课校验（容量、冲突、重复、学籍），并额外校验该课程尚未通过。
- **退课**：仅学生本人；需提交选课记录编号与 `expectedVersion`；要求记录属于本人且为 `ACTIVE`；只要存在开放阶段（`PREVIEW`/`OPEN`）且学期 `ACTIVE` 即可退课，退课后释放名额并保留 `DROPPED` 历史记录。
- **换课**：2026-09-04 设计取消了一体化原子改选交互，统一改为「先取消当前课程，再在刷新后的课程展开区选择其他教学班」；退选释放名额后，新教学班仍可能因容量、冲突或并发变化而失败，系统不恢复原教学班。服务端保留 `EnrollmentAdjustmentService.change` 原子实现与 `COURSE_CHANGE_TARGET_INVALID` 错误码，但**未在 `CourseHandlers` 注册 `COURSE_ADJUSTMENT_CHANGE` 命令**。
- 统一选课页按「每门课程一行」去重展示，展开后单选教学班；每门课程有独立操作按钮（选择课程 / 重修选课 / 补选课程 / 取消选课 / 置灰）。

### 2.6 重修

- 重修资格：同一课程至少存在一条 `FAILED` 历史修读结果，且不存在使重修失去意义的 `PASSED` 结果；`PASSED` 或无任何历史均不允许。
- 重修选课只在 `ENROLLMENT` 阶段开放，且仍需检查容量、时间冲突、重复选课与学籍资格。
- 普通选课遇到「有 `FAILED` 历史」的课程时，服务端返回 `COURSE_RETAKE_REQUIRED`，强制学生走重修命令。

### 2.7 课表

- 学生可查询本人当前学期的课表（有效选课对应的全部上课时间行）；教师可查询本人当前学期被指派教学班的课表。课表项包含课程代码/名称、教学班名称、教师、星期、节次、周次与教室。

### 2.8 修读结果（成绩）导入

- 管理员导入 `PASSED`/`FAILED` 粗粒度结果，**不含具体分数**；每条结果必须携带外部来源标识 `sourceReference` 用于去重与追溯。
- 导入对每条记录的 `sourceReference` 幂等：重复执行不产生重复 `CourseAttempt`；同一 `sourceReference` 若携带不同的学生/课程/学期/结果，导入整体失败并返回 `COURSE_OUTCOME_IMPORT_INVALID`。
- 导入前校验学生为活动学生账户。

### 2.9 调整期审计

- 退课、补选、改选（含失败尝试）写入不可变审计表 `tblEnrollmentAdjustment`，记录异动类型 `ADD`/`DROP`/`CHANGE`、原/目标教学班、操作结果 `SUCCEEDED`/`FAILED`、失败错误码与发生时间。
- 管理员可按学生、学期、异动类型、操作结果分页查询审计记录；业务规则失败（`CourseRuleException`）时尽力补写一条 `FAILED` 审计记录（审计写入失败不影响原始业务错误）。
- 交易与审计记录禁止物理删除。

### 2.10 权限矩阵（来自课程模块设计文档第 2 节）

| 用例 | 学生 | 教师 | 管理员 |
|---|---:|---:|---:|
| 查询教学班、查看课表 | 是 | 是 | 是 |
| 普通选课、退改补、重修 | 是 | 否 | 是（设计文档口径；实现中写命令仅注册 `STUDENT`） |
| 查看本人教学安排 | 否 | 是 | 是 |
| 维护学期、课程和教学班 | 否 | 否 | 是 |
| 导入通过/不通过结果 | 否 | 否 | 是 |
| 查看普通选课、退改补日志 | 否 | 否 | 是 |

> 实现口径补充：`CourseHandlers` 对学生写命令（`COURSE_ENROLL`、`COURSE_ADJUSTMENT_ADD`、`COURSE_DROP`、`COURSE_ADJUSTMENT_DROP`、`COURSE_RETAKE_ENROLL`）注册的角色集合只有 `STUDENT`；服务层还会再次校验会话身份与本人归属。客户端隐藏菜单不作为安全边界。

## 4. 业务流程

### 4.1 选课流程（含并发名额控制、锁键、时间冲突校验）

对应命令 `COURSE_ENROLL`，实现入口 `CourseServiceImpl.enroll` → `enrollLocked`。

1. 校验会话令牌可解析且角色为 `STUDENT`（`requireStudentSession`），否则 `COMMON_FORBIDDEN` / `AUTH_SESSION_EXPIRED`。
2. 读取学籍资格 `StudentEnrollmentEligibility`，状态非 `ACTIVE` 抛 `COURSE_STUDENT_INELIGIBLE`。
3. 按**声明的固定顺序**申请资源锁：`STUDENT:<studentId>` → `OFFERING:<offeringId>`（`ResourceLockManager.withLocks`）。
4. 锁内重新校验会话身份（`userId` 必须一致）、重新读取学籍资格（`studentId` 必须一致），防止锁等待期间身份或学籍变化。
5. 在数据库事务内加载教学班：`requireOffering`。
6. 历史结果校验：该课程存在 `PASSED` → `COURSE_ALREADY_PASSED`；非重修路径下存在 `FAILED` → `COURSE_RETAKE_REQUIRED`。
7. 教学班状态必须为 `OPEN`，否则 `COURSE_ENROLLMENT_NOT_OPEN`。
8. **阶段校验** `SelectionPhasePolicy.requireEnrollmentOpen(termId)`：必须存在 `OPEN` 状态的当前阶段、阶段 `phaseType=ENROLLMENT`、阶段 `termId` 与教学班一致、学期为 `ACTIVE`；不满足抛 `COURSE_ENROLLMENT_NOT_OPEN`。
9. 读取该学生该学期的有效选课，**重复课程校验**：任一有效记录所属课程与目标课程相同 → `COURSE_DUPLICATE_ENROLLMENT`。
10. **时间冲突校验** `ScheduleConflictPolicy.conflicts`：两份上课时间「星期相同 且 周次区间相交 且 节次区间相交」即冲突（周次与节次端点均为闭区间）→ `COURSE_SCHEDULE_CONFLICT`。
11. **容量校验**：`enrolledCount >= capacity` → `COURSE_OFFERING_FULL`。
12. 写入选课记录：`insertEnrollment`（`enrollmentType=NORMAL`、`enrollmentStatus=ACTIVE`）；若同一 `(studentId, offeringId)` 已存在 `DROPPED` 留存记录，则**重新激活原记录**（`rowVersion+1`、清空 `droppedAt`），否则新增；若已存在 `ACTIVE` 记录则报错。
13. **名额递增**：`changeEnrolledCount(offeringId, +1)`，同时 `rowVersion=rowVersion+1`、更新 `updatedAt`。
14. 提交事务并释放资源锁，返回 `EnrollmentView`。

并发名额控制说明：`OFFERING:<offeringId>` 资源锁使同一教学班的选课/退课串行化，事务内的 `enrolledCount >= capacity` 判定与 `enrolledCount+1` 处于同一临界区；Access 不支持 `SELECT FOR UPDATE`，因此一致性由「应用资源锁 + 事务 + 唯一索引 `uk_tblEnrollment_student_offering`」共同保证。验收基线为 20 个并发请求竞争最后一个名额时最多一人成功。

### 4.2 退课流程

对应命令 `COURSE_DROP`（兼容别名 `COURSE_ADJUSTMENT_DROP`），实现入口 `EnrollmentAdjustmentService.drop`。

1. 校验学生会话并读取学籍资格，得到初始操作者 `Actor(userId, studentId)`。
2. 申请资源锁 `STUDENT:<studentId>`。
3. 进入审计包装 `auditBusiness(type=DROP)`：业务失败且异常属于 `CourseRuleException` 时，尽力在独立事务中补写一条 `FAILED` 审计记录，然后原样抛出业务异常。
4. 事务外先按 `enrollmentId` 读取选课记录以确定原教学班（记录不存在或不属于本人 → `COMMON_FORBIDDEN`）。
5. 追加申请教学班锁 `OFFERING:<sourceOfferingId>`（多教学班时按资源键自然序排序后获取）。
6. 锁内重新校验会话与学籍资格。
7. 事务内 `requireOwnedActive`：记录必须属于本人；状态必须为 `ACTIVE`，否则 `COURSE_ENROLLMENT_NOT_ACTIVE`；`rowVersion` 必须等于客户端 `expectedVersion`，否则 `COMMON_CONCURRENT_MODIFICATION`。
8. **阶段校验** `SelectionPhasePolicy.requireDropOpen(termId)`：必须存在可见开放阶段（`PREVIEW`/`OPEN`）、阶段属于该学期、学期为 `ACTIVE`，不限制阶段类型；不满足抛 `COURSE_DROP_NOT_OPEN`。
9. 更新记录为 `DROPPED` 并写入 `droppedAt`，`rowVersion+1`（带期望版本条件更新）。
10. **名额释放** `changeEnrolledCount(sourceOfferingId, -1)`，教学班 `rowVersion+1`。
11. 写入 `tblEnrollmentAdjustment`：类型 `DROP`、`sourceOfferingId`、结果 `SUCCEEDED`。
12. 提交事务并释放锁。

### 4.3 换课 / 调整期流程

设计口径（2026-09-04）：学生端**不再提供一步式换课**，换班必须「先退后选」。

1. 学生在统一选课页对已选课程点击「取消选课」，经确认对话框提交 `DropCommand(enrollmentId, expectedVersion)`。
2. 服务端按 4.2 流程完成退选并释放名额。
3. 客户端刷新整个课程分页，重新计算每门课程与教学班的动作与原因。
4. 学生展开目标课程，单选一个可选教学班（动作应为 `LATE_ADD`），点击「选择课程」。
5. 服务端按补选流程处理：锁 `STUDENT` + `OFFERING:<targetOfferingId>`，`requireAdjustmentOpen` 要求当前阶段为 `OPEN` 且 `phaseType=ADJUSTMENT`；校验课程未通过、非重复课程、无时间冲突、容量未满；写入 `LATE_ADD` 有效记录、名额 `+1`、写 `ADD` 审计。
6. 任一步失败都不会恢复原教学班；学生需重新选择。

调整期加选（`COURSE_ADJUSTMENT_ADD`）编号步骤：

1. 校验学生会话与学籍资格，取得 `Actor`。
2. 加锁 `STUDENT:<studentId>`、`OFFERING:<offeringId>`。
3. 审计包装 `type=ADD`。
4. 锁内重新校验会话与学籍。
5. 事务内加载目标教学班：已通过该课程 → `COURSE_ALREADY_PASSED`；教学班非 `OPEN` → `COURSE_ENROLLMENT_NOT_OPEN`；`requireAdjustmentOpen` 不满足 → `COURSE_ADJUSTMENT_NOT_OPEN`。
6. 目标校验（`AdjustmentEnrollmentRules.requireTargetAllowed`，忽略自身记录参数为 `null`）：同课程已选 → `COURSE_DUPLICATE_ENROLLMENT`；与任一有效选课冲突 → `COURSE_SCHEDULE_CONFLICT`；容量已满 → `COURSE_OFFERING_FULL`。
7. 写入 `LATE_ADD` 有效记录，名额 `+1`，写 `ADD` 审计（`SUCCEEDED`）。

原子改选实现（`EnrollmentAdjustmentService.change`，`COURSE_CHANGE_TARGET_INVALID` 语义保留）：

1. 加锁 `STUDENT`，再按排序加锁原教学班与目标教学班。
2. `requireOwnedActive` 校验原记录归属、状态与版本（目标与原教学班相同 → `COURSE_CHANGE_TARGET_INVALID`）。
3. `requireAdjustmentOpen` 校验调整阶段开放。
4. `requireChangeTarget` 校验目标存在、与原教学班同属一个学期且为 `OPEN`，否则 `COURSE_CHANGE_TARGET_INVALID`。
5. `requireTargetAllowed` 在冲突与重复判定时忽略原记录本身。
6. 同一事务内：新增目标有效记录 → 停用原记录 → 原名额 `-1`、目标名额 `+1` → 写 `CHANGE` 审计；任一步失败整体回滚，原记录保持不变。

### 4.4 重修流程

对应命令 `COURSE_RETAKE_CHECK` 与 `COURSE_RETAKE_ENROLL`。

1. **资格检查（`COURSE_RETAKE_CHECK`）**：校验学生会话 → 读取学籍资格 → 加锁 `STUDENT:<studentId>` → 锁内重新校验会话与学籍 → 事务内读取该学生该课程的全部 `CourseAttempt`，筛出 `outcome=FAILED` 的 `attemptId` 列表；`eligible = 存在 FAILED && 不存在 PASSED`；返回 `RetakeEligibility(courseId, eligible, failedAttemptIds, reason)`，不可重修时 `reason` 为 `COURSE_RETAKE_NOT_ELIGIBLE`。
2. **重修选课（`COURSE_RETAKE_ENROLL`）**：校验学生会话 → 读取学籍资格 → 加锁 `STUDENT:<studentId>`、`OFFERING:<offeringId>` → 锁内重新校验会话与学籍。
3. 事务内执行 `enrollLocked(..., enrollmentType="RETAKE", requireFailedAttempt=true)`：
   1. 加载教学班；该课程存在 `PASSED` → `COURSE_ALREADY_PASSED`；
   2. `requireFailedAttempt` 为真但不存在 `FAILED` → `COURSE_RETAKE_NOT_ELIGIBLE`；
   3. 教学班状态非 `OPEN` → `COURSE_ENROLLMENT_NOT_OPEN`；
   4. **阶段校验** `requireEnrollmentOpen`：重修只在 `ENROLLMENT` 阶段开放，否则 `COURSE_ENROLLMENT_NOT_OPEN`；
   5. 重复课程校验 → `COURSE_DUPLICATE_ENROLLMENT`；
   6. 时间冲突校验 → `COURSE_SCHEDULE_CONFLICT`；
   7. 容量校验 → `COURSE_OFFERING_FULL`；
   8. 写入 `enrollmentType=RETAKE`、`enrollmentStatus=ACTIVE` 的选课记录，名额 `+1`。
4. 提交事务，返回 `EnrollmentView`。

### 4.5 修读结果导入流程

对应命令 `COURSE_IMPORT_OUTCOMES`（仅管理员）。

1. 命令体为空或条目为空 → `COURSE_OUTCOME_IMPORT_INVALID`。
2. 逐条调用 `students.existsActiveStudent(studentId)`；任一条不是活动学生，或该查询抛异常，均转换为 `COURSE_OUTCOME_IMPORT_INVALID`。
3. 按 `sourceReference` 生成资源锁键 `COURSE_OUTCOME:<sourceReference>`，去重后按 `resourceType + resourceId` 排序并一次性加锁。
4. 事务内逐条处理：`findAttemptBySourceReference` 命中时执行同名一致性校验（`studentId`/`courseId`/`termId`/`outcome` 必须完全一致，否则 `COURSE_OUTCOME_IMPORT_INVALID`）；未命中时 `insertAttemptIfAbsent` 插入，若因唯一索引冲突插入失败则重新读取并再做一致性校验（并发幂等）。
5. 全部成功提交事务；任何 `RuntimeException` 统一包装为 `COURSE_OUTCOME_IMPORT_INVALID` 并整体回滚。

## 8. 错误码清单

`COURSE_*` 全部错误码（来自 `server/course/domain/*Exception` 的 `CODE` 常量与 `CourseHandlers.userMessage` 的用户提示表）：

| 错误码 | 触发条件 | 用户提示（服务端返回） |
|---|---|---|
| `COURSE_ENROLLMENT_NOT_OPEN` | 无 `OPEN` 的 `ENROLLMENT` 阶段、学期非 `ACTIVE`、或教学班非 `OPEN` 时的正常选课与重修选课 | 当前未开放选课阶段 |
| `COURSE_ADJUSTMENT_NOT_OPEN` | 无 `OPEN` 的 `ADJUSTMENT` 阶段时执行补选/改选 | 当前未开放退改补选阶段 |
| `COURSE_DROP_NOT_OPEN` | 不存在可见开放阶段、阶段不属于该学期、学期非 `ACTIVE` 时退课 | 当前未开放可退选的选课阶段 |
| `COURSE_STUDENT_INELIGIBLE` | 学籍状态非 `ACTIVE`，或锁内重校验发现 `studentId` 变化 | 当前学籍状态不允许选课，请联系教务人员 |
| `COURSE_OFFERING_FULL` | `enrolledCount >= capacity` | 教学班容量已满，请选择其他教学班 |
| `COURSE_DUPLICATE_ENROLLMENT` | 同一学期已选择同一课程的另一教学班 | 本学期已选择该课程，请先查看当前选课 |
| `COURSE_SCHEDULE_CONFLICT` | 与任一有效选课的上课时间在星期、周次、节次上同时相交 | 所选教学班与当前课表冲突，请调整选择 |
| `COURSE_ENROLLMENT_NOT_ACTIVE` | 退课/改选的目标记录不是 `ACTIVE` 状态 | 选课记录已失效，请刷新后重试 |
| `COURSE_CHANGE_TARGET_INVALID` | 目标教学班不存在、不同学期、非 `OPEN`，或原目标相同（原子改选路径） | 目标教学班不可用于改选，请重新选择 |
| `COURSE_RETAKE_NOT_ELIGIBLE` | 重修时该课程无 `FAILED` 历史结果 | 未找到不通过的修读记录，暂不能重修 |
| `COURSE_RETAKE_REQUIRED` | 普通选课时该课程存在 `FAILED` 历史结果 | 该课程有未通过记录，请使用重修选课 |
| `COURSE_ALREADY_PASSED` | 该课程已存在 `PASSED` 结果时选课/补选/重修 | 该课程已通过，无需再次选课 |
| `COURSE_OUTCOME_IMPORT_INVALID` | 导入体为空、学生非活动、来源标识内容冲突或写入异常 | 导入内容无效或来源冲突，请核对后重试 |
| `COURSE_OFFERING_HAS_ENROLLMENTS` | 对已有选课记录的教学班修改所属学期/课程/上课安排 | 已有学生选课，不能修改所属学期、课程或上课安排 |
| `COURSE_SELECTION_PHASE_ALREADY_OPEN` | 已有其他可见开放阶段时再开放阶段 | 已有选课阶段开放，请先关闭后再开放新阶段 |
| `COURSE_SELECTION_PHASE_INVALID_STATE` | 阶段状态非法（领域异常已定义；当前状态转换由 `SelectionPhaseService` 与仓储层约束，未在业务路径抛出） | 选课阶段当前状态不允许该操作 |
| `COURSE_TERM_NOT_ACTIVE` | 为非 `ACTIVE` 学期开放阶段 | 只能为当前运行的学期开放选课 |

| 错误码 | 触发条件 | 用户提示 |
|---|---|---|
| `COMMON_FORBIDDEN` | 无有效会话、角色不符、退课/改选非本人记录、教师角色校验失败 | 没有执行该操作的权限，请重新登录或联系管理员 |
| `COMMON_CONCURRENT_MODIFICATION` | 乐观锁版本不匹配（学期/课程/教学班/阶段/选课记录的 `rowVersion`） | 数据已被其他操作修改，请刷新后重试 |
| `COMMON_VALIDATION_FAILED` | 请求体为 `null`、类型不匹配或 DTO 构造校验失败 | 请求内容无效 |
| `COMMON_INTERNAL_ERROR` | 未预期异常（响应含 `traceId`，不泄露 SQL/堆栈） | 服务暂时不可用，请稍后重试 |
| `AUTH_SESSION_EXPIRED` | 会话令牌缺失、空白或已失效 | 会话已过期，请重新登录 |
| `AUTH_INITIAL_PASSWORD_CHANGE_REQUIRED` | 受限首次改密会话调用课程命令 | 请先修改初始密码 |

## 9. 关键设计规则 / 约束

### 9.1 容量控制

- `enrolledCount` 是教学班的性能字段，只由选课（`+1`）与退课（`-1`）的同一事务维护，且每次变更都使教学班 `rowVersion+1`、`updatedAt` 刷新。
- 判定与递增位于同一临界区：先取 `OFFERING:<offeringId>` 资源锁，再在事务内读取 `enrolledCount` 与 `capacity` 比较，通过后插入记录并 `enrolledCount+1`。
- Access 不支持 `SELECT FOR UPDATE`，因此一致性由「应用资源锁 + 数据库事务 + 唯一索引 `uk_tblEnrollment_student_offering`」共同保证。
- 维护任务可按 `ACTIVE` 记录核对 `enrolledCount` 并生成异常报告；验收要求 20 个并发请求竞争最后一个名额时最多一人成功，且并发请求数可通过测试配置覆盖。
- 教学班容量不得下调到低于当前 `enrolledCount`。

### 9.2 乐观锁 `rowVersion`

- `tblTerm`、`tblCourseSelectionPhase`、`tblCourse`、`tblCourseOffering`、`tblEnrollment` 均带 `rowVersion`；仓储层更新语句一律形如 `UPDATE ... SET rowVersion=<expected+1> ... WHERE <id>=? AND rowVersion=?`，更新行数不为 1 即抛 `COMMON_CONCURRENT_MODIFICATION`。
- 客户端请求 DTO 显式携带 `expectedVersion`：`UpdateTermCommand`、`UpdateCourseCommand`、`UpdateOfferingCommand`、`UpdateSelectionPhaseCommand`、`ChangeSelectionPhaseStatusCommand`、`DropCommand`、`ChangeOfferingCommand`。
- 容量变更走 `enrolledCount=enrolledCount+?` 的原子自增（不做「读-改-写」覆盖），避免并发下计数丢失。
- 教学班更新不接受客户端提交的已选人数，服务端以数据库当前值为准。
- `UpdateOfferingCommand` 携带 `expectedVersion` 同时替换整组上课时间，属结构性替换。

### 9.3 资源锁键与加锁顺序

| 资源键 | 使用场景 |
|---|---|
| `STUDENT:<studentId>` | 学生选课、补选、退课、改选、重修、我的选课、课表、重修资格检查 |
| `OFFERING:<offeringId>` | 选课、补选、退课（原教学班）、改选（原与目标教学班）、重修 |
| `COURSE_SELECTION_PHASE:GLOBAL` | 阶段创建、修改标题、变更状态 |
| `COURSE_OUTCOME:<sourceReference>` | 修读结果导入（按来源标识去重后排序加锁） |
| `TERM:<termId>` / `TERM_CODE:<termCode>` | 学期更新 / 学期创建 |
| `COURSE:<courseId>` / `COURSE_CODE:<courseCode>` | 课程更新 / 课程创建 |
| `OFFERING_CREATE:<termId:courseId:className>` | 教学班创建（防止同名教学班并发重复创建） |

- **固定顺序**：学生类写操作统一按 `STUDENT:<studentId>` → `OFFERING:<offeringId>` 声明顺序加锁；多教学班场景（退课、改选）在已持有学生锁后，再把教学班键按 `String` 自然序排序后一次性获取，避免同一资源集反向加锁导致死锁。
- 阶段与导入等非学生资源集未公布固定顺序时，按 `resourceType + resourceId` 排序获取。
- 写命令另经 `RequestDeduplicator`（独立条带锁管理器 `StripedResourceLockManager`）以 `requestId` 做应用级幂等。

### 9.4 选课阶段状态机与开放互斥

- 状态取值：`DRAFT`（草稿）、`PREVIEW`（预选课，学生只读可见）、`OPEN`(正式开放）、`CLOSED`（已关闭）。
- 允许的创建与转换：`create` 只产生 `DRAFT`；`changeStatus` 可把 `phaseStatus` 设为 `DRAFT`/`PREVIEW`/`OPEN`/`CLOSED`（`ChangeSelectionPhaseStatusCommand` 只校验目标值属于该集合）。协议 JavaDoc 声明允许 `DRAFT → OPEN` 或 `OPEN → CLOSED`。
- **开放互斥**：全系统任意时刻最多一条可见开放记录（`phaseStatus IN ('PREVIEW','OPEN')`）。变更状态在 `COURSE_SELECTION_PHASE:GLOBAL` 资源锁内、同一事务中再次调用 `findOpenSelectionPhase`，若存在其他阶段的可见开放记录则抛 `COURSE_SELECTION_PHASE_ALREADY_OPEN`；并发开放两条阶段时最多一条成功。
- **学期前置条件**：把状态改为 `PREVIEW`/`OPEN` 前必须校验所属学期为 `ACTIVE`，否则 `COURSE_TERM_NOT_ACTIVE`。
- **写操作门禁**：`SelectionPhasePolicy` 是全部学生写操作的权威判定——
  - `requireEnrollmentOpen`：当前阶段必须 `OPEN` 且 `phaseType=ENROLLMENT`，阶段 `termId` 与教学班一致且学期 `ACTIVE`，否则 `COURSE_ENROLLMENT_NOT_OPEN`；
  - `requireAdjustmentOpen`：当前阶段必须 `OPEN` 且 `phaseType=ADJUSTMENT`，否则 `COURSE_ADJUSTMENT_NOT_OPEN`；
  - `requireDropOpen`：只要存在可见开放阶段且学期 `ACTIVE` 即可（不限阶段类型），否则 `COURSE_DROP_NOT_OPEN`；
  - 未知阶段类型或状态视为数据错误，抛 `IllegalStateException`，**不默认放行**。
- 学期变为 `CLOSED` 后，即使存在遗留的开放阶段记录，所有写操作也被拒绝。
- 阶段记录保留历史，已关闭阶段不重新开放，需要再次开放时新建阶段。

### 9.5 选课动作计算（学生端）

服务端按课程聚合教学班，先为每个教学班计算 `actionType` / `actionReason`，再由教学班状态聚合出课程级 `courseAction`：

- `ENROLL`：`ENROLLMENT` 阶段、学籍正常、该课程无 `FAILED` 历史且未选该课程。
- `RETAKE`：`ENROLLMENT` 阶段、学籍正常、该课程有 `FAILED` 历史且未选该课程。
- `LATE_ADD`：`ADJUSTMENT` 阶段、学籍正常且未选该课程。
- `SELECTED`：当前已有该教学班的有效选课记录。
- `UNAVAILABLE`：预选课阶段、已选择相同课程的其他教学班、学籍不允许、课程已通过、教学班未开放、容量已满或时间冲突；`actionReason` 为面向学生的中文原因（如「已选择相同课程」「学籍状态不允许选课」「该课程已通过，无需重修」「教学班未开放」「教学班容量已满」「时间冲突」）。
- 课程级：已选课程 → `CANCEL_SELECTION`；存在任一可选教学班 → `SELECT_COURSE`；全部不可选 → `DISABLED` 并汇总首个原因。
- `PREVIEW` 阶段不开放任何写操作，仅返回只读列表。
- 客户端动作仅供展示，**服务端写接口必须重新执行学籍、阶段、容量、重复、历史结果与时间冲突校验**，不得依赖列表快照。

### 9.6 时间冲突判定

- 冲突条件（`ScheduleConflictPolicy.conflicts`）：`dayOfWeek` 相同 **且** 周次区间相交（`a.startWeek ≤ b.endWeek && b.startWeek ≤ a.endWeek`）**且** 节次区间相交（`a.startPeriod ≤ b.endPeriod && b.startPeriod ≤ a.endPeriod`），周次与节次端点均为闭区间。
- 三个维度任一不重叠即不构成冲突。
- 客户端列表计算与提交时校验使用同一策略，保证「列表置灰」与「提交拒绝」一致。

### 9.7 幂等与唯一约束

- 所有写命令经 `CourseWriteExecutor` → `RequestDeduplicator.executeOnce`，以全局唯一 `requestId` 为幂等键；相同请求完成后返回原响应，处理中返回 `COMMON_REQUEST_IN_PROGRESS`（保留 24 小时）。
- 修读结果导入另以 `sourceReference` 为业务幂等键：`uk_tblCourseAttempt_sourceReference` 唯一索引 + 事务内先查后插 + 插入冲突后二次读取校验，保证重复导入不产生重复记录。
- `uk_tblEnrollment_student_offering` 保证同一学生对同一教学班只有一条记录（退课后补选为重新激活）。

### 9.8 事务与跨模块边界

- 所有多表写操作在单个 `TransactionManager` 事务内完成；改选路径的「新增目标 + 停用原记录 + 两侧人数 + 审计」任一步失败整体回滚，原记录保持不变。
- 课程模块只能通过 `CourseStudentGateway`（学籍资格）与 `CourseAuthorizationGateway`（会话与角色）访问其他模块，不得直接读取 `tblStudent`/用户仓储。
- 教师身份与教学班指派通过 `CourseRuntimeAdapters.authorization` 的 `hasRole` 谓词（活动账户 + `TEACHER` 角色）校验。
- 受限首次登录会话（`restricted=true`）不能调用任何课程命令。
- 会话过期、登出或账户禁用后，后续课程请求必须失败，客户端据此返回登录入口。

### 9.9 界面与契约一致性约束

- 客户端菜单隐藏不是安全边界；服务端在 `CourseHandlers` 中按命令逐一校验角色（`STUDENT`/`TEACHER`/`ADMIN` 集合）。
- Swing EDT 不执行网络等待：页面通过 `CourseUiGateway` 取得 `CompletableFuture`，用 `SwingUtilities.invokeLater` 更新控件；提交期间禁用按钮，失败保留已加载内容；`UiAsyncGuard` 丢弃过期结果。
- 客户端读超时 10 秒、写超时 15 秒；`AUTH_SESSION_EXPIRED`、`AUTH_ACCOUNT_DISABLED`、`AUTH_INITIAL_PASSWORD_CHANGE_REQUIRED` 触发鉴权失效监听器。
- 课程模块不保存或展示具体成绩，界面与 DTO 均无成绩字段。
