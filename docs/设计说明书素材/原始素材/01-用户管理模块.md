## 1. 模块背景

用户管理模块是「虚拟校园 vCampus」C/S 教学系统的基础支撑模块，负责全系统的身份与访问入口：登录、登出、密码修改、账户状态、基础角色、会话撤销与安全审计，并以服务端内部端口的形式为学籍模块提供学生账户创建能力。系统采用 Java 21 + Maven 多模块工程、Java Swing 客户端、模块化单体服务端、TCP 长连接 + Java 对象流，数据存储为 Access `vCampus.accdb`（UCanAccess JDBC）。学生以学籍模块生成的一卡通号作为登录标识 `loginId`，学生账户由管理员执行新生录取时在同一事务中创建，初始密码固定并由服务端仅以 PBKDF2 哈希形式保存，首次登录只获得受限会话，必须先修改初始密码。模块不维护学生学籍、教师档案、店铺资格或业务资源权限，也不生成一卡通号或学号；编号生成与新生录取事务由学籍模块负责。基础角色为 `STUDENT`、`TEACHER`、`ADMIN`，服务端对每一条命令重新鉴权，客户端菜单隐藏不作为安全边界。

## 2. 需求分析

### 2.1 功能点列表

| 编号 | 功能点 | 说明（依据） |
|---|---|---|
| F-01 | 教师账户申请（注册） | 未登录态公开命令 `USER_REGISTER`，请求不接受角色参数；服务端固定创建 `roleCode=TEACHER`、`accountStatus=PENDING`、`mustChangePassword=false` 的账户，并写审计 |
| F-02 | 学生账户内部创建 | 服务端内部 `UserAccountProvisioningPort`，不注册为 Socket 命令、不接受客户端调用；固定创建 `STUDENT`/`ACTIVE`/`mustChangePassword=TRUE`，`loginId` 为学籍模块传入的一卡通号 |
| F-03 | 登录 | `USER_LOGIN`。校验凭据后创建会话并返回令牌、账户投影、权限集合与 `mustChangePassword`；登录成功前统一对已存在与不存在的登录标识做失败计数与锁定 |
| F-04 | 登出 | `USER_LOGOUT`。撤销当前令牌；重复调用无害（令牌不存在时不做任何写入） |
| F-05 | 查看本人账户 | `USER_GET_CURRENT`。返回脱敏 `UserView`（不含密码、哈希、盐、失败计数） |
| F-06 | 修改密码 | `USER_CHANGE_PASSWORD`。校验旧密码、写入新哈希、清除 `mustChangePassword`、清零失败计数与锁定、撤销该用户全部会话 |
| F-07 | 首次强制改密 | `mustChangePassword=true` 的登录请求返回受限会话；受限会话只允许 `USER_GET_CURRENT`、`USER_CHANGE_PASSWORD`、`USER_LOGOUT`，调用其他受保护命令统一返回 `AUTH_INITIAL_PASSWORD_CHANGE_REQUIRED`。改密成功后撤销该受限会话并要求重新登录，不得把受限会话升级为普通会话 |
| F-08 | 授权（角色与权限） | 基础角色 `STUDENT`/`TEACHER`/`ADMIN`；权限由 `tblRolePermission` 按角色装载进会话快照；每个命令在服务端重新鉴权 |
| F-09 | 账户状态管理 | 状态机 `PENDING/ACTIVE/DISABLED/CANCELLED`；管理员通过 `USER_CHANGE_STATUS` 变更，受状态迁移矩阵、`rowVersion` 乐观锁与「最后一名有效管理员保护」约束 |
| F-10 | 管理员账户查询 | `USER_SEARCH`，关键字（登录标识模糊匹配）、角色、状态筛选 + 零基分页，返回脱敏 `UserSummary` 分页结果 |
| F-11 | 管理员初始化学生密码 | `USER_RESET_STUDENT_PASSWORD`，将目标学生密码重置为固定初始密码并使 `mustChangePassword=TRUE`，随后撤销该学生全部会话 |
| F-12 | 密码策略校验 | 长度 8–64，必须同时包含字母与数字；客户端校验用于提示，服务端强制再次校验 |
| F-13 | 登录失败锁定 | 连续 5 次密码错误后锁定；账户不存在时对规范化登录标识做内存级短期计数，避免泄露登录标识是否存在 |
| F-14 | 会话管理 | 服务端内存令牌（32 字节 `SecureRandom` + Base64URL）、空闲超时、同用户重复登录时替换旧会话并写 `USER_SESSION_REPLACED` 审计 |
| F-15 | 会话撤销 | 账户禁用、注销、密码重置、普通改密与首次改密后撤销该用户全部会话；禁用/注销在事务提交后撤销 |
| F-16 | 安全审计 | 注册、学生账户创建、登录成功/失败、登出、首次改密、普通改密、状态变更、密码重置、已退役角色命令的拒绝均写 `tblAuditLog`；审计对象为稳定结果码，禁止写入密码、哈希、盐、完整令牌与完整 DTO |
| F-17 | 请求幂等 | 所有写命令以全局唯一 `requestId` 为唯一幂等键，`tblRequestDedup` 保存响应快照 24 小时；处理中返回 `COMMON_REQUEST_IN_PROGRESS` |
| F-18 | 角色调整（已退役） | 设计文档定义了 `USER_UPDATE_ROLE`；**实现差异**：源码中该命令永久退役，处理器不做鉴权、不做幂等、不改数据，统一返回 `COMMON_VALIDATION_FAILED` |

### 3.2 界面约束（设计文档 §4、总体架构 §12）

- 登录和密码操作不得在 EDT 中等待网络；页面通过客户端服务取得 `CompletableFuture`，用 `SwingUtilities.invokeLater` 更新控件。
- 密码字段提交后立即清空字符数组。
- `LoginResult.mustChangePassword=true` 时不得创建或显示业务 `MainFrame`。
- 提交期间禁用按钮；失败时保留输入；并发冲突提示刷新；每个查询页面实现加载、正常、空结果、错误和断线状态。
- 统一页面组件：`PageNavigator`、`LoadingOverlay`、`NotificationService`、`ConfirmDialog`、`PagedTablePanel`、`FormValidator`、`ConnectionStatusPanel`。

## 4. 业务流程

### 4.1 登录流程（实现顺序）

1. 用户在 `LoginFrame` 输入登录标识（学生为一卡通号）与密码，点击「登录」；界面立即清空密码框字符、禁用按钮并显示「正在登录…」。
2. `LoginFrame` 调用 `UserClientService.login(loginId, password)`；客户端在该方法内构造 `LoginCommand`（构造器克隆密码并清零调用方数组），并清零界面传入的数组。
3. `UserClientService` 通过共享连接异步发送 `USER_LOGIN`，超时到期或响应返回后执行 `command::clearPassword` 清理密码副本。
4. 服务端 `UserLoginHandler` 校验消息体类型（非 `LoginCommand` 直接按 `COMMON_VALIDATION_FAILED` 拒绝并写拒绝审计），随后调用 `UserService.login(command, context)`；`finally` 块清零密码。
5. `AuthenticationService.login` 将 `loginId` 去空白并转大写（`Locale.ROOT`），在事务中按规范化登录标识查账户。
6. 若账户不存在：`UnknownLoginAttemptTracker` 对规范化登录标识做内存计数（连续 5 次失败即锁定，锁定与计数条目按锁定窗口过期清理），返回 `AUTH_INVALID_CREDENTIALS` 或 `AUTH_ACCOUNT_LOCKED`，并以独立短事务写 `USER_LOGIN` 失败审计。
7. 若账户存在：取得 `USER:<userId>` 资源锁，进入 `CredentialAuthenticator.authenticate`，在同一事务内完成：读取账户 → 若仍在锁定期返回 `AUTH_ACCOUNT_LOCKED` → 清除已过期锁定 → 校验 PBKDF2 哈希。
8. 密码错误：失败次数 +1（达到 5 次设置 `lockedUntil = now + 锁定窗口`），返回 `AUTH_INVALID_CREDENTIALS` 或 `AUTH_ACCOUNT_LOCKED`；写失败审计。
9. 密码正确：检查账户状态，非 `ACTIVE` 时返回 `AUTH_ACCOUNT_PENDING` 或 `AUTH_ACCOUNT_DISABLED`（状态信息只在密码验证成功后返回，避免泄露）；否则清零失败次数与锁定、更新 `lastLoginAt`、按角色装载权限集合、写 `USER_LOGIN` 成功审计，事务提交。
10. `AuthenticationService` 撤销该用户既有全部会话（若确有替换，另写 `USER_SESSION_REPLACED` 审计），生成新的不透明会话令牌，并按账户 `mustChangePassword` 决定该会话是否为受限会话。
11. 返回 `LoginResult(sessionToken, user, permissions, mustChangePassword)`。
12. 客户端 `requireLoginSuccess` 在成功响应上把令牌写入连接的会话字段；`UserUiCoordinator.acceptLogin` 分派：
    - `mustChangePassword=true` → 只打开 `InitialPasswordChangeDialog`，不创建 `MainFrame`；
    - 否则 → 创建 `MainFrame`，替换账户页，启动 `SessionMonitor`。
13. 登录失败时 `LoginFrame.finish` 用 `UserErrorMessages.login` 显示中文提示并重新聚焦密码框；若为锁定错误则进入 30 秒倒计时状态。

> 实现差异：`USER_LOGIN` 有意不进入持久化响应快照幂等器（响应含活跃会话令牌）；设计文档 §7 把 `USER_LOGIN` 标为幂等命令。

### 4.2 首次强制改密流程

1. 学生使用初始密码 `12345678` 登录，成功响应中 `mustChangePassword=true`（服务端据此把会话标记为受限会话）。
2. `UserUiCoordinator` 不创建 `MainFrame`，直接以应用模态方式打开 `InitialPasswordChangeDialog`，界面提示「为保护账户安全，请修改初始密码后重新登录」。
3. 用户填写旧密码、新密码、确认密码并提交。客户端先本地校验两次新密码一致，随后清空三个输入框。
4. `UserClientService.changePassword(old, new)` 构造 `ChangePasswordCommand`（克隆并清零调用方数组），发送 `USER_CHANGE_PASSWORD`，请求结束后执行 `clearPasswords()`。
5. 服务端 `UserHandlers.passwordChangeHandler` 校验消息体类型、执行 `authorization.requireSession` 取得操作人身份，然后经幂等器进入 `UserService.changePassword(token, command, context)`。
6. `AuthenticationService.changePassword`：`PasswordPolicy.validate(newPassword)`（长度 8–64 且同时含字母与数字，否则 `AUTH_PASSWORD_POLICY_VIOLATION`）→ 取得 `USER:<userId>` 锁 → 在锁内重新 `requireSession` 确认令牌仍属于同一用户 → 在单一事务中校验旧密码、写入新哈希、置 `mustChangePassword=false`、清零 `failedLoginCount` 与 `lockedUntil`、写 `USER_CHANGE_PASSWORD` 成功审计。
7. 旧密码不正确或账户不存在时事务内返回失败，抛出 `AUTH_INVALID_CREDENTIALS`；异常路径以独立短事务写失败审计。
8. 事务提交后调用 `sessions.revokeAllForUser(userId)`，撤销该用户全部会话（含当前受限会话），不得把受限会话升级为普通会话。
9. 客户端在成功响应后执行 `clearSession()` 清除本地令牌；`InitialPasswordChangeDialog.finishChange` 关闭对话框并回调 `onChanged`。
10. `UserUiCoordinator` 回到登录页并提示「密码修改成功，请使用新密码重新登录」；旧初始密码与受限会话均失效。
11. 若用户在首次改密页选择「退出登录」（或关闭窗口），客户端先发送 `USER_LOGOUT`（无论成败都清除本地会话），关闭对话框并返回登录页。

### 4.3 登出流程

1. 用户在 `AccountPanel` 点击「退出登录」，弹出 `LogoutConfirmationDialog` 二次确认（Esc 与默认按钮均为「取消」）。
2. 确认后 `AccountPanel.logout` 用 `AtomicBoolean` 保证只发起一次：先回调 `onSessionEnding`（停止 `SessionMonitor` 并标记会话正在结束），禁用按钮并显示「正在退出…」。
3. `UserClientService.logout()` 发送 `USER_LOGOUT`（`EmptyRequest`），并在 `whenComplete` 中无条件执行 `clearSession()`——即使服务端不可达也清除本地内存令牌。
4. 服务端 `UserHandlers.logoutHandler` 校验消息体类型后经幂等器调用 `UserService.logout(sessionToken, context)`；服务端在幂等路径中不做额外鉴权。
5. `AuthenticationService.logout` 调用 `sessions.revoke(token)`；仅当该令牌确实对应一个存活会话时，才在独立事务中写 `USER_LOGOUT`／`SUCCESS` 审计并记录客户端地址。因此重复登出无害，不会重复写审计。
6. 客户端回调 `onLoggedOut` → `UserUiCoordinator.returnToLogin`：结束会话监控、清除本地令牌、`dispose` 主窗口、重新显示登录页并提示「已退出登录」。
7. 附注（源码注释说明的已知限制）：登出以「先撤销令牌、后写审计」的顺序执行，若审计持久化失败，客户端可能收到失败响应，但令牌已经被撤销。

### 4.4 会话失效与会话替换（补充流程）

1. `MainFrame` 存活期间 `SessionMonitor` 每 2 秒调用一次 `USER_GET_CURRENT`。
2. 服务端 `SessionRegistry.requireSession` 校验令牌存在且未超过空闲超时，并刷新空闲到期时间；不满足即抛出 `AUTH_SESSION_EXPIRED`。
3. 客户端 `UserClientService.requireSessionSuccess` 把 `AUTH_SESSION_EXPIRED` 转换为 `SessionExpiredClientException`；`SessionMonitor` 识别该异常后停止轮询并回调一次。
4. `UserUiCoordinator.sessionExpired` 禁用主窗口，显示 `SessionReplacementWarningDialog`（他处登录、可能存在密码泄露、5 秒后返回登录页），随后清除本地会话、关闭主窗口并回到登录页。

## 6. 业务接口（命令表）

命令名取自 `UserHandlers` 构造器的实际 `router.register(...)` 调用，以及 `ServerMain.registerSecurityAudit`；权限取自处理器内实际的 `authorization.requirePermission(...)` 与角色判断。

| 命令名 | 请求 DTO | 响应 DTO | 允许角色 | 说明 |
|---|---|---|---|---|
| `USER_REGISTER` | `TeacherAccountApplicationCommand` | `UserView` | 公开（未登录） | 教师账户申请。固定创建 `TEACHER`/`PENDING`/`mustChangePassword=false`；请求不接受角色参数；`loginId` 规范化大写后须匹配 `[A-Z0-9_]{4,32}`；经持久化幂等器；写 `USER_REGISTER` 审计 |
| `USER_LOGIN` | `LoginCommand` | `LoginResult` | 公开（未登录） | 登录。返回会话令牌、`UserView`、权限集合与 `mustChangePassword`；**有意不进入持久化幂等器**；失败时统一给出「登录标识或密码错误」，状态类错误只在密码验证成功后返回 |
| `USER_LOGOUT` | `EmptyRequest` | `EmptyResponse` | 已登录会话 / 受限会话 | 撤销当前令牌；重复调用无害；经持久化幂等器；令牌确实存活时写 `USER_LOGOUT`/`SUCCESS` 审计 |
| `USER_GET_CURRENT` | `EmptyRequest` | `UserView` | 已登录会话 / 受限会话 | 处理器只做 `requireSession`（不做权限校验），因此受限会话可调用；不写审计 |
| `USER_CHANGE_PASSWORD` | `ChangePasswordCommand` | `EmptyResponse` | 已登录会话 / 受限会话 | 先鉴权再进入幂等器；校验旧密码、写入新哈希、清 `mustChangePassword`、清零失败计数与锁定、写 `USER_CHANGE_PASSWORD` 审计；提交后撤销该用户全部会话（含当前受限会话） |
| `USER_SEARCH` | `UserSearchQuery` | `PageResult<UserSummary>` | 需权限 `USER_READ_ALL`（管理员） | 关键字/角色/状态筛选 + 零基分页；受限会话先被拒为 `AUTH_INITIAL_PASSWORD_CHANGE_REQUIRED` |
| `USER_UPDATE_ROLE` | `UpdateUserRoleCommand` | `UserView`（永不返回成功） | 无（已退役） | **实现差异**：该命令永久退役，处理器在解析消息体后即按 `COMMON_VALIDATION_FAILED` 拒绝，不做鉴权、不做幂等、不改数据、不撤销会话；设计文档 §7 曾定义其为 `USER_ROLE_WRITE` 权限下的幂等命令 |
| `USER_CHANGE_STATUS` | `ChangeUserStatusCommand` | `UserView` | 需权限 `USER_STATUS_WRITE`（管理员） | 受状态迁移矩阵与 `rowVersion` 乐观锁约束；`DISABLED`/`CANCELLED` 时提交后撤销该用户全部会话；写 `USER_CHANGE_STATUS` 审计 |
| `USER_RESET_STUDENT_PASSWORD` | `ResetStudentPasswordCommand` | `UserView` | 需权限 `USER_PASSWORD_RESET` **且** 会话角色为 `ADMIN` | 目标必须为 `STUDENT`；重置为固定初始密码并使 `mustChangePassword=TRUE`；提交后撤销目标学生全部会话；写 `USER_PASSWORD_RESET` 审计 |
| `SECURITY_AUDIT_SEARCH` | `SecurityAuditQuery` | `PageResult<SecurityAuditView>` | 需权限 `USER_AUDIT_READ` **且** 会话角色为 `ADMIN` | 独立只读命令，与 `UserHandlers` 分开注册（`ServerMain.registerSecurityAudit`）；倒序分页；返回投影不含客户端地址 |

> 未注册为 Socket 命令的服务端内部能力：`UserAccountProvisioningPort.createStudentAccount(...)`（仅供学籍模块录取事务调用）、`UserQueryPort`（只读账户查询）、`AuthorizationPort.requireSession/requirePermission`（供其他模块鉴权）。

## 9. 关键设计规则与约束

### 9.1 密码与哈希

- 算法 `PBKDF2WithHmacSHA256`；迭代次数固定 `120_000`；盐 16 字节 `SecureRandom` 随机生成；输出 256 位，均以 Base64 存储。
- 恒时比较使用 `MessageDigest.isEqual`；`PBEKeySpec.clearPassword()` 在 `finally` 中调用。
- 密码策略：长度 8–64，且必须同时包含字母与数字（`Character.isLetter`/`Character.isDigit`）。客户端校验仅用于提示，服务端必须再次校验。
- 初始密码固定为 `12345678`：学生账户创建由学籍模块传入该初始密码，管理员「初始化学生密码」在服务端硬编码同一初始值，且只以哈希形式保存。
- 密码材质处理：`char[]` 而非 `String`；DTO 构造时克隆并清零调用方数组；访问器返回防御性副本；处理器与客户端服务在 `finally` 中清零；日志、审计与异常信息不得包含密码、哈希、盐或完整令牌。

### 9.2 登录标识

- `loginId` 写库前统一 `strip().toUpperCase(Locale.ROOT)`，并以大写值建立唯一索引 `uk_tblUser_loginId`。
- 教师申请与公开注册要求匹配 `[A-Z0-9_]{4,32}`；设计文档约束为「4–32 个大写字母、数字或下划线」。
- 学生 `loginId` 必须是一卡通号并匹配 `^2[123]3[0-9]{6}$`（`UserAccountProvisioningService` 常量），由学籍模块生成。

### 9.3 会话

- 令牌为 32 字节 `SecureRandom` 经 Base64URL（无填充）编码的不透明串；仅存于服务端内存 `ConcurrentHashMap`，客户端仅保存在内存（`ClientConnection` 的会话字段）。
- 会话快照包含身份、权限集合、`restricted` 标志与 `clientInstanceId`；权限集合在登录时按角色从 `tblRolePermission` 装载并快照化。
- 空闲超时默认 30 分钟（`SessionRegistry.DEFAULT_IDLE_TIMEOUT`），生产装配按 `config.sessionTimeoutMinutes()` 传入；每次 `requireSession`/`requireSnapshot` 都会刷新空闲到期时间。
- 受限会话由登录成功时的 `mustChangePassword` 决定；`AuthorizationService.requirePermission` 在权限检查之前先检查 `restricted()`，命中即抛 `AUTH_INITIAL_PASSWORD_CHANGE_REQUIRED`——因此受限会话只能调用 `USER_GET_CURRENT`、`USER_CHANGE_PASSWORD`、`USER_LOGOUT`。
- 同一用户再次登录会替换其既有全部会话，并写一条 `USER_SESSION_REPLACED` 审计（尽力而为）；客户端 `SessionMonitor` 每 2 秒探测一次并在发现失效时展示异地登录警告。
- 架构文档另规定：登录前空闲 5 分钟断开，登录后空闲 30 分钟过期。

### 9.4 账户锁定策略

- 账户存在时：事务内将 `failedLoginCount` 加一；达到 5 次即设置 `lockedUntil = now + LOCKOUT_DURATION`；成功验证密码后清零失败次数并清除锁定；锁定过期后自动清除。
- 账户不存在时：`UnknownLoginAttemptTracker` 以规范化 `loginId` 为键在内存中计数（阈值同为 5 次），条目按锁定窗口过期清理，不落库、不保存任何凭据或数据库数据；返回值与已存在账户保持一致（`AUTH_INVALID_CREDENTIALS`/`AUTH_ACCOUNT_LOCKED`），避免泄露登录标识是否存在。
- **实现差异**：设计文档 §3 规定「连续五次密码错误后设置 `lockedUntil = now + 15 minutes`」；源码 `CredentialAuthenticator.LOCKOUT_DURATION = Duration.ofSeconds(30)`，其注释说明 30 秒是团队确认的课程演示与调试锁定策略；登录页倒计时常量 `LoginFrame.DEMO_LOCKOUT_SECONDS = 30` 与之对应。正式说明书需明确采用 15 分钟还是 30 秒。
- 状态类信息（待启用、禁用、锁定）仅在密码验证成功后返回。

### 9.5 账户状态机与最后管理员保护

```
PENDING → ACTIVE → DISABLED
PENDING → CANCELLED
ACTIVE  → CANCELLED
DISABLED → ACTIVE
```

- 状态迁移矩阵在 `AdminUserService.canChangeStatus` 中以代码固化，非法迁移返回 `USER_STATUS_CONFLICT`。
- `protectOnlyAdministrator`：当变更会把一个 `ADMIN`/`ACTIVE` 账户移出有效管理员集合，且库中有效管理员数量 ≤ 1 时，抛出 `USER_LAST_ADMIN_PROTECTED`。
- 状态变为 `DISABLED` 或 `CANCELLED` 时，在事务提交后撤销该用户全部会话；密码重置同样在提交后撤销目标学生会话。
- 用户、学生、课程、图书、商品采用逻辑停用；交易与审计记录禁止物理删除（架构文档 §10）。

### 9.6 幂等与去重

- 所有写命令携带全局唯一 UUID `requestId`，登录前与登录后请求都只以 `requestId` 作为幂等键；`clientInstanceId` 仅用于追踪与诊断。
- `tblRequestDedup` 保存 24 小时；相同请求完成后返回原响应，仍在处理中返回 `COMMON_REQUEST_IN_PROGRESS`。
- 用户模块实际经幂等器的命令：`USER_REGISTER`、`USER_LOGOUT`、`USER_CHANGE_PASSWORD`、`USER_CHANGE_STATUS`、`USER_RESET_STUDENT_PASSWORD`。
- 明确不走幂等器的命令：`USER_LOGIN`（响应含活跃会话令牌）、`USER_GET_CURRENT`、`USER_SEARCH`、`USER_UPDATE_ROLE`。
- 受保护命令采用「先鉴权、后幂等」的顺序：请求先经过 `requireSession`/`requirePermission`，再进入响应快照去重，避免无效令牌命中缓存响应。
- 已知限制（源码注释）：幂等集成对「占用后因基础设施故障遗留 `PROCESSING` 行」没有恢复机制；密码修改故意保持「鉴权优先」语义，重放旧令牌可能返回 `AUTH_SESSION_EXPIRED` 而非缓存成功。
- 客户端：查询可在保持同一 `requestId` 时重试一次；写请求不得以新的 `requestId` 自动重试（架构文档 §6）。

### 9.7 事务、锁与并发

- 用户模块资源键（架构文档 §8）：`LOGIN_ID:<normalizedLoginId>`、`USER:<userId>`、`SESSION:<sessionToken>`。
- 公开注册：先取 `LOGIN_ID:<normalizedLoginId>` 锁，再在事务内先查后插，唯一索引作为第二道保护；20 个相同 `loginId` 并发创建只能成功一个。
- 登录失败计数：在 `USER:<userId>` 锁内、事务中重新读取并更新。
- 状态变更与密码重置：`AdminUserService.withAccountLocks` 按固定顺序取 `ADMIN:ACTIVE` → `USER:<userId>` 两把锁（`ADMIN:ACTIVE` 为源码实际使用的额外资源键，架构文档的用户模块资源键表中未列出，正式说明书需补齐或调整）。
- 改密：在 `USER:<userId>` 锁内、单一事务中校验旧密码、写入新哈希、清 `mustChangePassword`、清零失败计数与锁定并写审计；提交后撤销该用户全部会话。首次改密同样撤销当前受限会话，不得升级为普通会话。
- 乐观锁：`updateWithVersion` 使用 `WHERE userId=? AND rowVersion=?` 且 `rowVersion=rowVersion+1`，影响行数不为 1 抛 `ConcurrentModificationException` → 客户端 `COMMON_CONCURRENT_MODIFICATION`「记录已被修改，请刷新后重试」。
- 学生账户创建：学籍模块的录取协调器先取得编号序列锁，再在同一 `TransactionContext` 内调用 `UserAccountProvisioningPort`；用户模块实现**不得自行提交、回滚或开启嵌套事务**，仅补充取得 `LOGIN_ID:<campusCardNumber>` 锁，不改变既定锁顺序；失败审计只能在回滚完成后通过 `StudentAccountProvisioningFailureAudit.recordAfterRollback` 独立补记。
- 资源锁、数据库事务与 `rowVersion` 三者同时用于关键写操作；同一资源集不得在不同操作中反向加锁。

### 9.8 审计与日志

- 审计写入使用 `tblAuditLog` 追加，`auditId` 为服务端生成 UUID，只持久化稳定结果码。
- 业务事务内的成败审计随事务提交：登录成功、登出成功、改密成功、状态变更成功、密码重置成功、注册成功、学生账户创建成功。
- 事务外的补偿审计由 `UserAuditWriter` 以独立短事务「尽力而为」执行，失败只记录一条不含敏感信息的 WARN 日志，绝不替换已经确立的业务结果。
- 处理器层被拒绝的请求由 `UserHandlerRejectionAuditor` 写脱敏审计，且审计失败不影响返回给客户端的安全响应。
- 审计与日志禁止包含：密码、哈希、盐、完整会话令牌、银行卡信息、完整支付请求与完整 DTO；SLF4J 上下文包含 `traceId`、`requestId`、`sessionId`、`userId`、`command` 与客户端地址，日志滚动保留 14 天。

### 9.9 错误处理与响应安全

- 错误码采用 `<MODULE>_<REASON>` 形式；`ErrorDetail` 含 `code`、`message`、`fieldErrors`、`traceId`、`retryable`。
- `UserHandlerErrorMapper` 只放行白名单内的稳定错误码，其余统一转 `COMMON_INTERNAL_ERROR` 并生成 `traceId`，不泄露 SQL、路径或堆栈。
- 登录失败统一返回凭据无效，避免泄露登录标识是否存在；账户待启用、禁用和锁定仅在密码验证成功后返回明确状态。
- 响应体不得传输数据库实体或 Swing 组件，禁止使用无类型的 `Map<String,Object>` 作为业务载荷。
- 客户端 `UserErrorMessages` 沿异常因果链匹配错误码与网络异常类型（`ConnectException`、`SocketException`、`SocketTimeoutException`、`TimeoutException`），输出安全可操作的中文提示。

### 9.10 客户端线程与交互约束

- 登录、改密、登出等网络调用一律异步，Swing EDT 不得执行网络等待；控件更新统一经 `SwingUtilities.invokeLater`。
- `USER_LOGIN` 返回 `mustChangePassword=true` 时不得创建或显示业务 `MainFrame`。
- 提交期间禁用按钮并在失败时保留输入；`AccountPanel` 用 `AtomicBoolean` 保证登出只发起一次；`SessionMonitor` 用 `AtomicBoolean` 保证失效只投递一次且必须运行在 EDT。
- 页面级权限门控：`AccountPanel` 仅在管理员且持有 `USER_READ_ALL`/`USER_AUDIT_READ` 时挂载相应子页面；`UserManagementPanel` 仅在持有 `USER_STATUS_WRITE`/`USER_PASSWORD_RESET` 时显示对应操作按钮，且「初始化密码」只在选中学生账户时可见。以上仅为界面便利，服务端仍逐命令重新鉴权。
