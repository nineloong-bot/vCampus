## 1. 模块背景

图书馆模块是虚拟校园 vCampus 在用户模块（会话、身份、权限）之上的业务子系统，负责书目（`tblBook`）、实体馆藏副本（`tblBookCopy`）、借阅记录（`tblBookLoan`）与借阅规则（`tblLibraryPolicy`）的完整生命周期管理，向学生、教师提供馆藏检索、借阅、归还、续借、本人借阅记录查询，向图书管理员提供书目与副本维护、全量借阅查询与处置（归还／报失）、损坏与遗失赔偿登记、以及学生／教师借阅策略配置。模块以 C/S 结构运行：Swing 客户端通过 `LibraryClientService` 以异步 Socket 请求访问服务端，服务端由 `LibraryHandlers` 完成路由、权限校验与请求去重，再由 `LibraryServiceImpl` 在资源锁与数据库事务保护下执行业务规则，最终经 Repository 落到 Access 数据库 `vCampus.accdb`。设计上明确：模块不处理罚款支付——逾期只触发提示、禁止新增借阅与续借；罚金仅结算并登记为数值，供后续支付模块按 `loanId` 读取。管理员功能由用户模块权限 `LIBRARY_ADMIN` 控制，服务端不信任客户端传入的身份，一律依据 `sessionToken` 解析当前用户。

## 2. 需求分析

| 编号 | 需求 | 说明 | 主要角色 |
|---|---|---|---|
| R-01 | 图书检索 | 按关键词（可选择书名／作者／ISBN／分类／出版社或任意字段）、分类、是否仅看可借进行分页检索；普通检索只返回启用书目，管理员检索（`searchManagedBooks`）可包含停用书目 | 学生、教师、管理员 |
| R-02 | 书目详情 | 依据 `bookId` 返回书目元数据及全部副本（条码、馆藏位置、副本状态、`rowVersion`） | 学生、教师、管理员 |
| R-03 | 图书（书目）管理 | 新建书目（`CreateBookCommand` 可在建目时同时建立首个副本）、编辑元数据、启用／停用书目；`isbn` 唯一 | 管理员 |
| R-04 | 馆藏副本管理 | 为指定书目新增带馆藏条码与位置的副本；维护无有效借阅副本的状态（如损坏修复后恢复为可借、遗失找回） | 管理员 |
| R-05 | 借书 | 依据副本编号借阅；校验会话身份、逾期、在借上限、书目启用状态、副本可借状态；借出后副本置为 `BORROWED` | 学生、教师 |
| R-06 | 还书 | 借阅人本人归还自己的记录，登记归还情况（`NORMAL`／`MINOR_DAMAGE`／`MAJOR_DAMAGE`）；归还可借副本置回 `AVAILABLE`，损坏副本置为 `DAMAGED` | 学生、教师 |
| R-07 | 续借 | 本人对未逾期的有效借阅续借，按角色策略延长到期日并累加续借次数 | 学生、教师 |
| R-08 | 借阅记录 | 查询本人当前有效借阅（`ACTIVE`／`OVERDUE`）与全部历史（分页、可按状态过滤）；管理员可按账号、状态查询全量借阅 | 学生、教师、管理员 |
| R-09 | 借阅规则管理 | 分别读取与更新 `STUDENT`、`TEACHER` 的最大在借数、借期、最大续借次数、每次续借天数及分档罚金；规则存储在 `tblLibraryPolicy`，不硬编码 | 管理员 |
| R-10 | 超期与罚金 | 到期未还的动态显示为 `OVERDUE`；存在逾期记录的用户禁止新增借阅、禁止续借；归还或报失时按借阅时保存的角色、当前策略分档累计计算逾期罚金 | 学生、教师、管理员 |
| R-11 | 损坏／遗失处理 | 读者归还时可登记轻度／严重损坏；管理员可在借阅管理中办理归还或标记遗失，损坏／遗失赔偿与逾期罚金相加后与借阅结束、副本状态变更同事务登记 | 学生、教师、管理员 |
| R-12 | 权限与会话 | 普通命令要求有效会话；管理员命令要求权限 `LIBRARY_ADMIN`；所有写命令携带 `requestId` 幂等去重 | 全部 |

补充约束（来自 `docs/library/README.md`）：

- 学生／教师借阅分别使用 `STUDENT`、`TEACHER` 策略；管理员账号用于馆藏管理，不配置个人借阅策略。
- 停用书目不出现在普通检索中，管理员仍可查询并重新启用；停用书目禁止新增副本、借阅和续借，已有借阅仍可归还或由管理员处理。
- 借阅历史永久保留，不物理删除。
- 馆藏检索与管理员借阅管理每页 20 条，支持上一页／下一页，提交新筛选时回到第 1 页。
- 罚金金额为人民币元、最多两位小数，可设为 0 关闭该项罚金；当前只保存与展示，不调用支付、不扣减账户、不记录支付状态。

## 4. 业务流程

### 4.1 借书流程（含副本锁与规则校验）

1. 读者在 `BookDetailPanel` 选择可借副本，经 `LoanActionDialog` 确认借阅。
2. 客户端 `LibraryClientService.borrow(BorrowBookCommand)` 发送 `LIBRARY_BORROW`（携带 `requestId`、`sessionToken`、`copyId`）。
3. `LibraryHandlers` 调用 `LibraryAccessPort.requireSession(sessionToken)` 校验会话，并要求请求体为 `BorrowBookCommand`。
4. 若运行时提供 `RequestDeduplicator`，按 `requestId` 执行 `executeOnce`：已完成请求直接返回已保存的最终 `ResponseBody`，不重复借阅；首次请求继续处理。
5. `LibraryServiceImpl.borrow` 经 `LibraryIdentityPort.requireBorrower(sessionToken)` 解析出 `BorrowerIdentity(userId, roleCode)`（服务端不信任客户端身份）。
6. 事务内读取副本快照 `books.requireCopy(copyId)` 以取得 `bookId`。
7. 通过 `ResourceLockManager.withLocks` 按固定顺序获取三把资源锁：`LIBRARY_USER:<userId>`、`BOOK:<bookId>`、`BOOK_COPY:<copyId>`（固定条带顺序避免循环等待）。
8. 进入借阅事务后依次校验：
   - `loans.hasOverdueLoan(userId, now)`：存在 `OVERDUE` 或 `ACTIVE 且 dueAt < now` 的记录时抛 `UserHasOverdueLoansException`；
   - `policies.require(roleCode)` 读取该角色策略；
   - `loans.countEffectiveLoans(userId, now) >= policy.maxActiveLoans()` 时抛 `LoanLimitReachedException`；
   - 重新读取副本与书目；书目 `active == false` 时抛 `InactiveBookException`；
   - 副本状态非 `AVAILABLE` 时抛 `CopyUnavailableException`。
9. 校验通过后在同一事务内：插入 `LoanStatus.ACTIVE` 的借阅记录（`dueAt = now + policy.loanDays` 天，`renewCount = 0`，罚金为 0，`returnCondition = NORMAL`，记录 `borrowerRoleCode`），并把副本状态更新为 `BORROWED`（带 `rowVersion` 乐观锁）。
10. 任一校验失败即回滚并抛出业务异常，由 `LibraryHandlerErrorMapper` 转换为稳定错误码；去重器保存成功或失败的最终响应。
11. 客户端收到 `LoanView` 后刷新详情与相关页面；失败经 `LibraryFeedback` 弹出醒目错误窗口。

**一致性保证**：借阅记录与副本状态在同一数据库事务提交或回滚，不会出现“副本已借出但无借阅记录”或相反情形；同一副本的并发借阅只允许一个请求成功。

### 4.2 还书流程（含罚金计算）

1. 读者在 `CurrentLoansPanel` 选择本人借阅并点击“归还所选”（可一并选择归还情况），或管理员在 `LoanAdminPanel` 输入账号查询后选择记录执行“办理归还”／“标记遗失”。
2. 读者路径：`LibraryClientService.returnBook(ReturnBookCommand)` 发送 `LIBRARY_RETURN`；`LibraryServiceImpl.returnBook` 首先校验 `condition` 非空且不为 `LOST`（遗失只能由管理员经 `LIBRARY_RESOLVE_LOAN` 登记），否则抛 `IllegalArgumentException`。
3. 读取借阅快照 `loans.require(loanId)` 取得 `copyId`，随后按顺序锁定 `LOAN:<loanId>`、`BOOK_COPY:<copyId>`。
4. 事务内重新读取借阅记录并校验归属：`loan.borrowerUserId` 必须等于当前会话用户，否则抛 `LoanOwnershipException`（错误码 `AUTH_FORBIDDEN`）。
5. 状态校验：已归还（`status == RETURNED` 或 `returnedAt != null`）抛 `LoanAlreadyReturnedException`；非 `ACTIVE`／`OVERDUE` 抛 `LoanNotActiveException`（二者均映射为 `LIBRARY_LOAN_NOT_ACTIVE`）。
6. 读取副本，取当前时刻，并按记录中保存的 `borrowerRoleCode` 读取该角色策略中的 `PenaltyPolicy`。
7. 计算罚金：`penalty.overdueFine(loan.dueAt(), now)` 得到逾期罚金，`penalty.damageFine(command.condition())` 得到损坏赔偿（`NORMAL` 为 0）；两者相加即 `LoanView.totalFine()`。
8. 在同一事务内：更新借阅记录为 `RETURNED`（写入 `returnedAt`、`overdueFine`、`damageFine`、`returnCondition`，`rowVersion + 1`，用 `expectedVersion` 做乐观锁，失败抛 `ConcurrentModificationException("Loan changed: ...")`）；同步把副本置为 `AVAILABLE`（归还情况为 `NORMAL`）或 `DAMAGED`（轻度／严重损坏）。
9. 提交事务并返回 `LoanView`；界面刷新借阅与副本状态。借阅中的金额尚未结算，记录中的金额仅表示已登记的罚金。

**管理员处置流程（`LIBRARY_RESOLVE_LOAN`）**：命令须满足 `resolution ∈ {RETURNED, LOST}`；`resolution == LOST` 必须对应 `condition == LOST`，否则抛 `IllegalArgumentException`。事务内同样锁定 `LOAN` 与 `BOOK_COPY`，校验记录仍为 `ACTIVE`／`OVERDUE`，计算逾期罚金与赔偿后更新记录（`LOST` 时 `returnedAt` 为 `null`），并按情况把副本置为 `AVAILABLE`／`DAMAGED`／`LOST`。管理员不能直接把存在有效借阅的副本改成“可借”，必须从借阅管理发起。

### 4.3 续借流程

1. 读者在 `CurrentLoansPanel` 选择本人借阅，点击“续借所选”，经 `LoanActionDialog` 确认。
2. `LibraryClientService.renew(RenewLoanCommand)` 发送 `LIBRARY_RENEW`（`loanId` + `expectedVersion`），Handler 校验会话并执行 `requestId` 去重。
3. `LibraryServiceImpl.renew` 由 `sessionToken` 解析借阅人身份。
4. 事务内读取借阅快照，再读取该记录副本快照以获得 `bookId`。
5. 按顺序锁定 `LIBRARY_USER:<userId>`、`LOAN:<loanId>`、`BOOK:<bookId>`。
6. 进入续借事务，依次校验：
   - 记录归属：非本人抛 `LoanOwnershipException`；
   - 读取副本与书目，书目停用抛 `InactiveBookException`；
   - `loan.status == OVERDUE` 或 `dueAt` 早于当前时刻，抛 `LoanOverdueException`；
   - `loan.status != ACTIVE`（如已归还、已遗失）抛 `LoanNotActiveException`；
   - 读取角色策略，`loan.renewCount >= policy.maxRenewals` 抛 `RenewalLimitReachedException`。
7. 计算新的到期日 `dueAt = loan.dueAt + policy.renewalDays` 天，`renewCount + 1`，状态保持 `ACTIVE`，`rowVersion + 1`；以 `expectedVersion` 做乐观锁更新借阅记录。
8. 返回更新后的 `LoanView`，界面刷新显示新的应还时间与续借次数。

### 4.4 逾期判定流程

- **持久化任务**：`OverdueMaintenanceJob.runOnce()` 在事务中调用 `LoanRepository.markOverdue(now)`，把 `loanStatus = 'ACTIVE' AND dueAt < now` 的记录批量改为 `OVERDUE` 并 `rowVersion + 1`，返回受影响行数，可幂等重复执行。
- **动态判定**：查询与限制判断不依赖任务是否运行。`AccessLoanQueries.read` 在读取时把 `ACTIVE` 且 `dueAt < now` 的记录显示为 `OVERDUE`；`AccessLoanRepository.hasOverdueLoan` 直接以 `loanStatus = 'OVERDUE' OR (loanStatus = 'ACTIVE' AND dueAt < ?)` 判定。因此维护任务延迟不会绕过借阅限制。

## 8. 借阅规则与罚金阶梯

### 8.1 借阅规则（`seed/040_library_policy.sql` + `tblLibraryPolicy` 列默认值）

`seed/040_library_policy.sql` 插入两条记录，仅显式给出 6 列，其余罚金与分档列使用 DDL 默认值：

| 字段 | `STUDENT`（`library-policy-student`） | `TEACHER`（`library-policy-teacher`） |
|---|---|---|
| `maxActiveLoans` 最大在借 | 5 本 | 10 本 |
| `loanDays` 默认借期 | 30 天 | 60 天 |
| `maxRenewals` 最大续借 | 1 次 | 2 次 |
| `renewalDays` 每次续借 | 15 天 | 30 天 |
| `rowVersion` | 0 | 0 |
| `firstTierDays` / `secondTierDays` | 7 / 30（DDL 默认） | 7 / 30（DDL 默认） |
| `firstDailyFine` / `secondDailyFine` / `thirdDailyFine` | 0.5 / 1 / 2（DDL 默认） | 0.5 / 1 / 2（DDL 默认） |
| `minorDamageFine` / `majorDamageFine` / `lostFine` | 10 / 50 / 100（DDL 默认） | 10 / 50 / 100（DDL 默认） |

### 8.2 逾期罚金阶梯（默认值，来自 `borrowing-penalties.md` 与 `PenaltyPolicy.defaults()`）

| 项目 | 默认值 | 可配置字段 |
|---|---|---|
| 逾期第 1–7 天 | 0.50 元/天 | `firstTierDays` = 7、`firstDailyFine` = 0.50 |
| 逾期第 8–30 天 | 1.00 元/天 | `secondTierDays` = 30、`secondDailyFine` = 1.00 |
| 逾期第 31 天起 | 2.00 元/天 | `thirdDailyFine` = 2.00 |
| 轻度损坏 | 10.00 元 | `minorDamageFine` |
| 严重损坏 | 50.00 元 | `majorDamageFine` |
| 遗失 | 100.00 元 | `lostFine` |

计费规则：

- 两个分档截至天数与六项金额均可修改，金额单位为人民币元、最多两位小数，设为 0 即关闭该项罚金。
- 按实际到期时刻计算，逾期不足 24 小时按一天；各档累计，不追溯提高较早天数的单价。
- 例：逾期 31 天为 7×0.50 + 23×1.00 + 1×2.00 = 28.50 元。
- 损坏或遗失赔偿与逾期罚金相加（`LoanView.totalFine()`），在归还或遗失登记时与借阅结束、副本状态变更同事务提交。
- 归还损坏书籍后副本标记为“已损坏”，管理员修复后可在副本管理中恢复为可借。
- 修改策略仅影响之后的结算，已结束记录的金额不变，不补算历史罚金；借阅中的金额尚未结算，借阅记录中的金额仅表示已登记的罚金。

### 8.3 副本与借阅状态迁移

```text
AVAILABLE --借阅--> BORROWED
BORROWED  --归还--> AVAILABLE
BORROWED  --管理员报失--> LOST
LOST      --找回--> AVAILABLE / DAMAGED
AVAILABLE <--------> DAMAGED   （无有效借阅时由管理员维护）
```

```text
ACTIVE --超过 dueAt--> OVERDUE
ACTIVE / OVERDUE --归还--> RETURNED
ACTIVE / OVERDUE --管理员报失--> LOST
ACTIVE --续借--> ACTIVE（dueAt 延后，renewCount + 1）
```

`BORROWED` 和 `LOST` 不能通过普通副本状态编辑直接写入，必须由借阅业务产生。

## 9. 错误码清单

服务端错误码由 `LibraryHandlerErrorMapper.code(...)` 统一映射，提示语由 `message(...)` 给出（客户端 `LibraryFeedback` 还会对会话过期、权限不足、重复 ISBN／条码、副本有有效借阅、副本不可借、借阅已失效等做醒目模态展示）。

| 错误码 | 触发条件 | 提示语 |
|---|---|---|
| `LIBRARY_COPY_UNAVAILABLE` | 借阅时副本状态非 `AVAILABLE`（`CopyUnavailableException`） | 该馆藏副本当前不可借，请刷新后重试 |
| `LIBRARY_COPY_HAS_ACTIVE_LOAN` | 副本存在有效借阅时被要求改状态（`CopyHasActiveLoanException`） | 该副本仍有有效借阅，请到借阅管理中办理归还或标记遗失 |
| `LIBRARY_BOOK_INACTIVE` | 书目已停用时新增副本、借阅或续借（`InactiveBookException`） | 该书目已停用，不能新增副本、借阅或续借 |
| `LIBRARY_DUPLICATE_ISBN` | 新建／编辑书目的 `isbn` 已存在（`DuplicateIsbnException`） | 该 ISBN 已存在，请编辑现有书目 |
| `LIBRARY_DUPLICATE_BARCODE` | 新增副本的 `barcode` 已存在（`DuplicateBarcodeException`） | 该馆藏条码已存在，请使用新的条码 |

| `LIBRARY_LOAN_STALE` | 借阅乐观锁冲突，消息以 `Loan changed:` 开头 | 借阅状态已发生变化，请刷新借阅记录后重试 |

| `COMMON_CONCURRENT_MODIFICATION` | 其他 `ConcurrentModificationException` | 记录已被修改，请刷新后重试 |

## 10. 关键设计规则／约束

1. **单一权威事实**：借阅记录与副本状态在同一数据库事务中提交或回滚，二者始终一致；副本“已借出”“已遗失”只能由借阅业务产生，管理员不能在副本管理中直接写入。
2. **并发控制**：借阅锁定 `LIBRARY_USER`、`BOOK`、`BOOK_COPY`；归还与管理员处置锁定 `LOAN` 和 `BOOK_COPY`；续借锁定 `LIBRARY_USER`、`LOAN`、`BOOK`。资源锁按固定条带编号顺序取得，避免不同业务路径形成循环等待。
3. **乐观锁**：`Book`、`BookCopy`、`Loan`、`LoanPolicy` 均使用 `rowVersion`；写命令携带 `expectedVersion`，冲突时返回具体 stale 错误码，客户端应刷新页面后再决定是否重试。
4. **事务串行化**：`TransactionManager` 串行执行 Access 数据库事务，规避 UCanAccess 单文件数据库在并发打开／关闭连接时的驱动锁死问题。网络请求仍可并发，但数据库写入按事务排队。
5. **幂等性**：所有写命令（借阅、归还、续借、书目与副本管理、管理员处置、策略更新）都使用 `requestId` 去重，服务端保存成功或失败的最终 `ResponseBody`；客户端因网络问题重发同一请求不会重复借阅或重复修改状态。
6. **服务端身份解析**：服务端不信任客户端传入的用户身份，一律由 `sessionToken` 经 `LibraryIdentityPort` 解析当前用户；普通操作要求有效会话，管理员操作要求权限 `LIBRARY_ADMIN`。
7. **借阅规则外置**：最大在借数、借期、续借次数与天数、罚金档位全部存于 `tblLibraryPolicy`，不硬编码在服务端代码中；策略更新使用 `rowVersion` 防止管理员互相覆盖；新策略仅影响后续借阅与结算，不追溯修改既有记录的到期时间与金额。
8. **借阅不变量**：一个副本同一时间最多一条有效借阅；存在逾期借阅的用户不能新增借阅；有效在借数不得超过角色策略；只有本人可以归还或续借自己的记录；逾期、已归还、已遗失记录不能续借。
9. **动态逾期判定**：查询与限制判断在 SQL 层即时判断 `ACTIVE 且 dueAt < now`，不依赖 `OverdueMaintenanceJob` 是否被周期调度（当前 `ServerMain` 未注册周期调度器，功能不受调度延迟影响）。
10. **历史不可删除**：借阅历史永久保留，不物理删除，`tblBookLoan` 是可追溯的完整台账。
11. **罚金边界**：本模块不处理罚款支付——不调用支付、不扣减账户、不记录支付状态；仅结算并保存、展示金额，供其他模块后续按 `loanId` 读取。收款幂等、退款与缴费状态属于后续对接工作。
12. **模块边界**：模块消费用户模块的 `AuthorizationPort`，不得修改用户表、不得实现罚款支付；书目管理使用 `isbn` 唯一标识书目、`barcode` 唯一标识实体副本。
13. **界面约定**：馆藏检索与管理员借阅管理每页 20 条、支持上一页／下一页、提交新筛选回到第 1 页；切换栏目自动刷新；异步页面使用请求代次保护，较早返回的请求不会覆盖较新的页面状态；冲突、重复数据、会话过期和权限不足以醒目模态窗口展示。
14. **已知边界与演进**：不含罚款支付、预约与馆际互借；借阅策略设置页面当前仅配置学生与教师两行，管理员无个人借阅策略；书目管理、个人借阅历史的分页控件与到期提醒、逾期筛选、未结算罚金预估、损坏附注与罚金减免审批为后续优化项。
15. **构建与验证**：`mvn -pl vcampus-server,vcampus-client -am package` 构建，回归基线 191 项测试（common 1、server 152、client 38）；验收要点包括 20 人并发借同一副本仅一人成功、并发借阅不能绕过上限、存在动态或持久化逾期均不能借书、重复 `requestId` 归还返回原结果、不同请求同时归还仅一个成功、续借按角色策略计算、副本与有效借阅状态始终一致。
