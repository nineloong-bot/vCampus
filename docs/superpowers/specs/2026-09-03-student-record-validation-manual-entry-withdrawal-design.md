# 学籍校验、手动建档与申请撤回设计

## 1. 目标与范围

本轮在现有学籍管理上增加四类能力：

1. 学生编辑个人学籍资料时执行合理性校验，并在可编辑控件上提供悬停格式提示。
2. 管理员的组织管理页固定显示“新增学院、新增专业、新增班级、新增学生”四个逐级操作，并增加独立的手动学生建档接口。
3. 教师查看学生详情时不查询、不显示学籍变更记录。
4. 学生已提交的资料申请可撤回为草稿，保留上一版所有修改并继续编辑。

现有自动录取命令 `STUDENT_CREATE`、一卡通号/学号自动编号器及其序列保持不变。

## 2. 总体方案

采用独立手动建档流程，而不扩展原自动录取命令。新增 `STUDENT_CREATE_MANUAL` 命令，复用现有组织归属校验、学生账户建立、资源锁、事务、去重和变更记录基础设施。

手动建档和自动录取共享安全不变式：账户与学生档案在同一事务中创建，初始密码为 `12345678`，首次登录必须修改密码，任一写入失败均整体回滚。

学生资料校验由无 UI 依赖的共享校验器表达。客户端用它提供即时反馈和字段定位，服务端对每次命令再次执行权威校验，不信任客户端结果。

## 3. 手动建档命令

新增可序列化命令 `CreateStudentManualCommand`，包含：

- `campusCardNumber`：必填，管理员手动输入；
- `studentNumber`：必填，管理员手动输入；
- `studentName`：必填；
- `gender`：必填受控选项；
- `studentType`：必填受控选项；
- `idDocumentType`：必填受控选项；
- `idDocumentNumber`：必填；
- `birthDate`：必填，用于年龄和证件一致性校验；
- `enrollmentDate`：必填；
- `classId`：必填，来自组织树当前选中班级。

部门和专业不由客户端作为权威值提交，服务端由 `classId` 反查班级、专业和学院归属。目标三层组织均必须存在且为启用状态。学籍状态固定初始化为 `ACTIVE`，邮箱和手机号固定初始化为 `NULL`，手动建档页面不提供这两个控件。

命令仅允许 `ADMIN` 角色调用，不仅依赖可能分配给其他角色的通用写权限。一卡通号、学号和身份证件号均在事务内重新校验唯一性。一卡通号同时作为新账户登录标识。

手动建档使用锁键 `LOGIN_ID:<campusCardNumber>` 和 `STUDENT_NUMBER:<studentNumber>`，按固定顺序获取，再在事务中建立账户、学生核心档案和初始身份资料，并写入 `ADMISSION` 变更记录和请求去重结果。手动建档不读取、不修改一卡通或学号自动序列。

## 4. 校验规则

### 4.1 手动建档必填值

- 一卡通号：匹配 `^2[123]3[0-9]{6}$`，例如 `213240001`。
- 学号：匹配 `^[0-9A-Z]{3}[0-9]{5}$`，例如 `09024101`；英文字母写入前转为大写。
- 姓名：去除首尾空白后长度为 2–64，只允许中文、少数民族姓名分隔点、英文字母、单词间空格和连字符。
- 性别：受控选项“男、女”，协议使用现有性别枚举值。
- 学生类别：受控选项“本科生、硕士生、博士生”。
- 出生日期和入学日期：均为真实日历日期，不得晚于当天，且 `enrollmentDate` 必须大于或等于 `birthDate.plusYears(18)`。
- 班级：必须为当前选中的启用班级，不接受手工输入 ID。

### 4.2 身份证件

证件类型提供“居民身份证、护照、港澳台证件、其他”四类受控选项。

- 居民身份证：必须为 18 位，前 17 位为数字，末位为数字或 `X`；校验地址码非全零、出生日期可解析、校验码正确，且证件内出生日期与表单出生日期一致。
- 护照：转为大写后匹配 `^[A-Z0-9]{5,18}$`。
- 港澳台证件：转为大写后匹配 `^[A-Z0-9()]{6,20}$`。
- 其他证件：转为大写后匹配 `^[A-Z0-9-]{4,32}$`。

证件号按规范化后的值建立唯一索引；手动建档遇到重复证件号时返回明确错误，不暴露已存在学生的其他资料。

### 4.3 学生个人资料编辑

允许原本为空的非必填档案值保持为空，但任何非空值均必须满足下列规则：

- 姓名拼音：最长 128 字符，只允许英文字母、空格和连字符。
- 曾用名：最长 64 字符，沿用姓名字符规则。
- 日期：界面统一显示和输入 `yyyy-MM-dd`；出生、证件签发、入团、入党日期不得晚于当天。
- 年龄：出生日期非空时，必须满足正式入学日期已年满 18 岁。
- 证件：证件类型与证件号必须同时为空或同时非空；非空时执行 4.2 的类型化校验。
- 团员/党员：勾选时对应加入日期必填；取消勾选时提交值中对应日期必须为空。
- 证件签发日期不得早于出生日期；入团和入党日期不得早于出生日期。
- 邮箱：最长 128 字符，匹配常用邮箱格式，不允许空白或控制字符。
- 联系电话：最长 32 字符，允许 11 位大陆手机号，或带区号和可选分机号的固定电话。
- 身高：非空时为 100–280 cm 的整数。
- 体重：非空时为 20–300 kg 的整数。
- 地址和地域文本：按数据库列长度限制，拒绝纯空白、换行以外的控制字符；单行控件不保留换行。
- 特长和爱好：各最长 256 字符，拒绝控制字符。

政治面貌、民族、婚姻状态、证件类型、户口性质、港澳台侨外、健康状况和血型使用受控下拉选项。为兼容旧数据，若正式档案中存在不在新选项表中的历史值，编辑器可显示且保留该值，但用户一旦改动必须选择规范值。

## 5. 格式提示与错误反馈

学生个人资料编辑器和管理员手动建档窗口中，每个可编辑文本框、日期、数值和下拉控件都设置 `setToolTipText`。提示使用“规则＋示例”的短句，例如：

- 一卡通号：“9 位数字，例如 213240001”；
- 日期：“格式 yyyy-MM-dd，例如 2005-12-03”；
- 身高：“100–280 cm 的整数，例如 172”。

客户端保存前收集所有字段错误，页面底部显示首个可操作的中文错误，将焦点移到对应控件，且不发送网络请求。服务端校验失败返回稳定错误码和字段友好信息；客户端保留所有输入。

## 6. 组织管理界面

组织树底部固定显示四个按钮，不通过隐藏按钮表达当前层级：

| 树选择 | 唯一可用按钮 |
|---|---|
| 无选择/根节点 | 新增学院 |
| 学院 | 新增专业 |
| 专业 | 新增班级 |
| 班级 | 新增学生 |

其他按钮保持可见但设为禁用灰色。断网、加载中或写入进行中时四个按钮全部禁用。树重新加载后若无法稳定恢复原选中 ID，回到无选择状态，不将旧节点当作有效上下文。

选中班级后点击“新增学生”打开 `ManualStudentCreationDialog`。窗口顶部只读显示“学院 / 专业 / 班级”完整路径，下方排列必填建档字段，不显示邮箱和手机号。建档成功后显示一卡通号、学号和初始密码提示，关闭窗口后保持组织树的当前班级选择。

## 7. 申请撤回状态机

新增 `WithdrawStudentProfileCommand(long expectedApplicationVersion)` 和 `STUDENT_PROFILE_WITHDRAW` 命令。命令的学生目标只能从会话获取，不接受客户端传入 `studentId` 或 `applicationId`。

撤回操作在 `STUDENT:<studentId>` 锁和单一事务中：

1. 查询该学生当前开放申请；
2. 要求状态为 `PENDING` 且 `applicationVersion` 等于请求版本；
3. 将同一条申请改回 `DRAFT`，清空 `submittedAt`，增加 `applicationVersion`，保留个人资料和就读方式快照；
4. 返回最新 `StudentProfileWorkspace`。

撤回和管理员通过/驳回使用同一学生资源锁，因此必定只有一方先生效。若管理员已处理，撤回返回“申请已处理”并刷新页面，不重新打开已关闭申请。撤回命令经现有持久化去重器保证重试幂等。

学生页面操作规则：

- `DRAFT`：底部按钮为“提交审核”，编辑入口可用；
- `PENDING`：同一位置按钮改为“撤回申请”，采用次要警示样式；
- 点击“撤回申请”先显示确认对话框，只在用户确认后发送请求；
- `PENDING` 期间“个人基本信息”和“学籍信息”的编辑入口保持可见可点，但点击只提示“请先撤回审核申请后再编辑”，不打开编辑器；
- 撤回成功后页面继续显示申请快照，状态改为草稿，编辑入口和再次提交立即恢复。

## 8. 教师详情隐私边界

`StudentDetailPanel` 在教师模式下只发送有限的 `STUDENT_GET` 请求，不发送 `STUDENT_GET_PROFILE` 和 `STUDENT_GET_CHANGES`。教师界面不构建“变更记录”标题、表格、空状态或占位区域，从数据请求和视觉呈现两层都排除变更记录。

管理员模式继续请求完整正式档案和变更记录。教师权限不因拥有某个通用写权限而扩展为完整档案读取。

## 9. 错误处理

- 手动建档重复一卡通号：`STUDENT_CAMPUS_CARD_EXISTS`；
- 手动建档重复学号：`STUDENT_NUMBER_EXISTS`；
- 手动建档重复证件号：`STUDENT_ID_DOCUMENT_EXISTS`；
- 字段格式或字段间关系错误：`STUDENT_PROFILE_VALIDATION_FAILED`，消息指出第一个错误字段；
- 撤回时无待审申请：`STUDENT_PROFILE_NOT_PENDING`；
- 撤回版本冲突：`COMMON_CONCURRENT_MODIFICATION`；
- 断网或请求失败：保留表单/申请快照，恢复按钮并允许重试；
- 组织异步加载使用代次号废弃过时响应，旧响应不得覆盖新树选择。

## 10. 数据库与兼容性

`tblStudent.idDocumentNumber` 增加唯一索引。现有空值保持兼容；种子数据中的非空证件号必须唯一且通过校验。

申请撤回不新增状态值，仍使用现有 `DRAFT` 和 `PENDING`，不需要新增数据表列。旧客户端不会调用新命令，现有自动录取和审核命令的序列化结构保持不变。

## 11. 测试与验收

所有生产代码按测试先行实现，每个新行为先观察到回归测试因功能缺失而失败，再写最小实现使其通过。

服务端测试覆盖：

- 手动建档成功时一次事务生成可登录账户、完整学生档案和变更记录；
- 邮箱和手机号初始为空，学生可通过草稿申请后续补充；
- 一卡通号、学号和证件号重复，以及中途失败的整体回滚；
- 手动建档不更改自动编号序列，随后自动录取仍产生原预期编号；
- 所有字段格式、证件校验码、日期关系、入学时年满 18 岁的边界日；
- 只有管理员可手动建档；
- `PENDING -> DRAFT` 撤回保留快照，版本增加，已处理申请和并发冲突被拒绝；
- 撤回与通过/驳回竞争时只有一个结果提交；
- 新命令在 `ServerMain` 实际路由中注册。

客户端测试覆盖：

- 组织树的四种选择状态下始终只有一个新增按钮可用，且四个按钮始终可见；
- 手动建档页面不含邮箱和手机号，必填错误能定位焦点，成功请求携带正确班级；
- 每个可编辑控件有非空格式提示，非法输入不会发出网络请求；
- 待审时提交按钮变为撤回按钮，编辑入口点击后只出现提示；
- 撤回确认、取消、成功、网络失败和并发失败状态；
- 教师详情不含变更记录区域，且请求记录中不含 `STUDENT_GET_CHANGES`；
- 窄窗口、键盘焦点、鼠标悬停提示、加载/禁用态和断网态的 Swing 视觉验收。

最终运行全量 Maven 测试、干净打包和发布版真实连接冒烟测试，重建 `vCampus-release/data/vCampus.accdb`，替换客户端和服务端 JAR，并重新生成 `vCampus-release.zip`。
