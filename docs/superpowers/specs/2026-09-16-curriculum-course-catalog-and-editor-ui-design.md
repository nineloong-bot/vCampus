# 培养方案课程目录与嵌入式编辑界面设计

## 背景

课程目录目前允许课程管理员任意填写课程代码、名称、学分和总学时，导致课程目录可能出现培养方案之外的课程。课程与教学班的嵌入式编辑器同时存在大面积纯白背景、边界不清和控件横向拉伸问题。学院管理员的转专业处理页在嵌入式编辑迁移后还出现批次对象原始文本、分栏叠加和空白详情区尺寸异常。

本设计保持当前 `main` 的接口和嵌入式编辑模式，以 `nineloong` 分支原有稳定布局作为转专业页面的视觉与尺寸参考，不恢复旧的独立业务弹窗。

## 权限与数据归属

- 学院管理员在学籍模块维护培养方案及培养方案课程。
- `tblTrainingPlan`、`tblTrainingPlanCourse` 和 `tblTrainingPlanPrerequisite` 是培养方案的唯一生产数据源。
- 课程管理员不能定义培养方案之外的课程，只能将已存在的培养方案课程纳入课程目录，并为目录课程创建教学班、选择教师、设置容量和上课时间。
- 客户端限制只用于交互提示；服务端创建课程时必须在同一事务内重新确认候选课程仍存在且元数据一致。

## 培养方案课程候选

课程模块通过窄接口读取所有有效培养方案中的课程候选，不直接复用学籍模块仓储。候选至少包含：课程代码、课程名称、学分、总学时、课程性质、开课学院以及来源培养方案标识。

相同课程代码在多个培养方案中出现时按代码合并。名称、学分、总学时、课程性质或开课学院不一致即视为培养方案数据冲突：该候选不可纳入课程目录，服务端返回明确的业务错误，提示学院管理员先统一培养方案定义。

已经存在于课程目录的候选不再出现在“新建课程”候选中。编辑现有课程时，其培养方案元数据保持锁定；课程管理员只能修改启用状态，不得改变课程定义。

## 双向联想选择

课程编辑器提供“课程代码”和“课程名称”两个联想输入框，共享同一选中课程状态：

1. 在任意输入框键入内容后进行防抖检索。
2. 候选下拉项显示“课程代码 · 课程名称”，辅助信息显示开课学院、课程性质和学分。
3. 选择候选后同步填写代码和名称，并自动带入学分、总学时、课程性质和开课学院。
4. 自动带入的字段全部只读，课程代码和名称也不能脱离选中候选单独修改。
5. 用户继续编辑代码或名称时，清除旧选择并重新检索；未选择有效候选时禁止保存。

教学班编辑器继续使用现有课程和教师联想组件。其课程候选来自课程目录，教师候选来自在职教师列表。

## 服务端约束

创建课程命令改为携带培养方案课程的稳定引用，不信任客户端重复提交的课程定义。服务端从权威培养方案表读取最新元数据，创建课程目录记录并保存开课学院。若候选不存在、已被删除、存在冲突或课程代码已经入库，则拒绝操作。

更新课程不允许修改代码、名称、学分、总学时、课程性质和开课学院，只允许修改课程启用状态及目录层自身允许维护的非权威信息。现有教学班继续通过课程目录的 `courseId` 关联。

## 编辑工作区视觉

课程、教学班及同类课程管理编辑器统一使用：

- 页面背景内居中的表单卡片，卡片使用浅米色表面、细边框和明确内边距；
- 有限最大宽度，避免输入控件横跨整个窗口；
- 基础信息、容量和上课安排使用独立分组卡片；
- 底部操作栏位于表单卡片内部并保持可见；
- 编辑器打开时替换列表工作区，保存或取消后恢复列表，不创建独立窗口。

## 学院转专业处理页

转专业页面恢复 `nineloong` 分支稳定的“顶部批次工具栏 + 左侧申请列表 + 右侧详情 + 底部操作状态”结构，同时兼容主分支嵌入式编辑器：

- 为批次下拉框增加专用渲染器，仅显示批次名称、中文状态和申请时段；
- 左右两侧各有稳定的滚动容器、表面色和边框，设置合理最小宽度与分隔位置；
- 未选择申请时显示空状态，不显示空白可编辑文本区；
- 切换批次时清空旧详情和旧操作，异步响应使用请求代次保护，避免旧响应覆盖新页面；
- “维护本学院招生专业”和驳回原因等编辑操作仍在当前业务工作区内完成，关闭后恢复处理列表。

## 错误处理

- 无匹配培养方案课程：显示“请先由学院管理员在培养方案中添加课程”。
- 候选定义冲突：列出冲突课程代码，并提示回到培养方案统一数据。
- 保存期间禁用输入与保存按钮；失败后保留当前选择并显示可操作错误。
- 转专业加载失败时保留页面骨架并在状态区提示，不让原始对象或异常信息进入 UI。

## 验证

按测试驱动实现：先添加失败测试，再完成最小实现。自动化验证覆盖：

- 培养方案候选去重、冲突识别和服务端权威校验；
- 代码/名称双向检索、选择同步、字段锁定及无效手输不可保存；
- 课程与教学班编辑卡片的背景、边框、最大宽度和嵌入式开关行为；
- 转专业批次可读渲染、空状态、固定分栏和异步请求代次保护；
- 原有课程、学籍和权限回归测试。

最终使用发行脚本启动服务端和客户端，分别以课程管理员及计算机学院管理员登录，截图核对课程新建、教学班新建和转专业处理页。运行数据库和用户本地 `client.properties` 修改不纳入功能提交。
