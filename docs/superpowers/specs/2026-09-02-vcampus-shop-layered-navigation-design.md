# vCampus Shop 分层导航设计

**日期：** 2026-09-02  
**状态：** 待用户评审  
**对应问题：** `SHOP-TEST-008`、`SHOP-TEST-011`

## 1. 背景与根因

当前 `ShopNavigator` 把首页、搜索、店铺、商品、购物车、我的和结算等所有页面都追加到同一个 `Deque<ShopRoute>`，并以 `MAX_HISTORY = 20` 截断最早记录。工具页虽然另有一个内容锚点，但普通商品与店铺浏览仍然形成有限串行历史。

因此，只要用户反复执行“商品 → 购物车 → 商品 → 店铺 → 商品”，首页最终就会被历史上限移除。继续增加上限只能推迟故障，不能消除故障。

本次整改不再保存逐次点击形成的完整时间线，而是保存当前商城所处的有限语义层。相同语义层的新目标替换旧目标；返回只移除最高层。首页是不可淘汰的根层。

## 2. 目标

1. 首页始终是商城导航根层，不受访问次数影响。
2. 商品、店铺和搜索的反复跳转只更新固定语义层，不无限增加返回深度。
3. “我的”和“购物车”继续作为全局工具入口；二者互切不污染内容层。
4. 从购物车或确认订单查看商品后，返回能回到原工具/流程页。
5. 结算和支付具有独立、有限的流程层；支付完成后不能返回已经完成的确认订单。
6. 查询、页码、筛选、排序和滚动位置由所在语义层保存并恢复。
7. 点击左侧“校园商城”在离开保护允许后，强制回到默认首页第 1 页顶部，并清除此前导航状态。

## 3. 非目标

- 不修改服务端路由、数据库、购物车、订单或支付业务数据。
- 不实现浏览器式“返回到每一次点击”的完整时间线。
- 不改 Foundation、User、Socket、Router、事务框架或公共网络接口。
- 不在本次导航整改中调整商城页面的视觉样式。

## 4. 总体模型

导航状态由一个内容路径和一个可选覆盖路径组成。两者都使用固定槽位，不使用有长度上限的通用历史队列。

```text
内容路径（永久存在）
首页 Home
  └─ 发现层 Search | Storefront
       └─ 详情层 Product

覆盖路径（按需存在，覆盖在内容路径上）
工具根层 My | Cart
  └─ 工具子层 SellerApplication | SellerWorkspace | AdminWorkspace | Checkout
       └─ 临时商品预览 Product

支付完成态 PaymentResult
  └─ 返回安全的内容路径，不保留 Checkout
```

当前可见页面的优先级为：支付完成态 → 临时商品预览 → 工具子层 → 工具根层 → 内容详情层 → 内容发现层 → 首页。

固定槽位使状态规模有明确上限：内容路径最多 3 个节点，覆盖路径最多 3 个节点，另有至多 1 个支付完成态。无论用户重复操作 5 次、10 次还是 100 次，状态都不会增长，也不存在首页被淘汰的问题。

## 5. 页面归层

| 路由 | 语义位置 | 说明 |
| --- | --- | --- |
| `Home` | 内容根层 | 永久存在；保存首页查询、页码和滚动位置 |
| `Search` | 内容发现层 | 与店铺页同层；保存关键词、筛选、排序、页码和滚动位置 |
| `Storefront` | 内容发现层 | 与搜索页同层；保存店铺、页码和滚动位置 |
| `Product` | 内容详情层或临时商品预览 | 从内容页进入时属于详情层；从购物车/确认订单进入时属于覆盖路径的预览层 |
| `My` | 工具根层 | 覆盖当前内容路径 |
| `Cart` | 工具根层 | 覆盖当前内容路径 |
| `SellerApplication` | `My` 的工具子层 | 离开时继续执行未保存申请保护 |
| `SellerWorkspace` | `My` 的工具子层 | 与其他“我的”子页同层替换 |
| `AdminWorkspace` | `My` 的工具子层 | 与其他“我的”子页同层替换 |
| `Checkout` | `Cart` 的工具子层 | 独立的结算步骤，不写入内容路径 |
| `PaymentResult` | 支付完成态 | 终止并清除结算路径；只保留安全内容锚点 |

`Product` 的位置由进入上下文决定，而不是只由路由类型决定。这一条保证“购物车点击商品 → 返回购物车”和“内容列表点击商品 → 返回列表”能够同时成立。

## 6. 核心移动规则

### 6.1 内容路径

| 当前操作 | 状态变化 | 返回目标 |
| --- | --- | --- |
| 首页打开搜索 | 设置发现层为 `Search` | 首页 |
| 首页打开商品 | 设置详情层为 `Product`，发现层可为空 | 首页 |
| 搜索/店铺打开商品 | 保留发现层，设置详情层 | 原搜索/店铺状态 |
| 商品 A 打开商品 B | 替换详情层，不新增层 | 原发现层或首页 |
| 搜索切换到另一搜索条件 | 替换发现层并清除详情层 | 首页 |
| 搜索切换到店铺，或店铺切换到搜索 | 替换发现层并清除详情层 | 首页 |
| 商品进入所属店铺 | 设置发现层为该店铺并清除详情层 | 首页 |
| 店铺 A 进入店铺 B | 替换发现层 | 首页 |

同一层替换时不会保留被替换对象。例如“商品 A → 商品 B → 商品 C”只保留商品 C；返回后到发现层或首页，而不是依次返回 B、A。

### 6.2 我的与购物车

打开 `My` 或 `Cart` 时，先捕获当前内容层状态，再显示工具根层：

- `My ↔ Cart` 互切只替换工具根层，内容锚点不变。
- 重复点击当前工具入口不新增状态。
- 从工具根层返回，直接恢复内容锚点。
- 打开另一个工具根层时，清除原工具子层和临时预览。

这保持 `SHOP-TEST-008` 已确认的六种行为：无论“我的”和“购物车”互相点击多少次，一次返回都回到进入工具页之前的内容页面。

### 6.3 从购物车查看商品

购物车中的商品区域打开 `Product` 时，将商品放入临时商品预览槽，而不是内容详情槽：

- `Cart → Product → 返回`：回到 `Cart`。
- 在预览商品中点击“店铺”：结束购物车覆盖路径，在内容发现层打开对应 `Storefront`，清除旧内容详情。
- 在预览商品中再次点击“购物车”：回到同一个 `Cart` 工具根层，清除临时预览。
- 从店铺再打开商品：该商品进入内容详情层。

因此，用户提供的长链循环后，状态最多为“首页 → 当前店铺 → 当前商品 + 购物车覆盖”。连续返回的最坏路径是“购物车 → 当前商品 → 当前店铺 → 首页”，不会随循环次数增长。

### 6.4 我的子页

- `My → SellerApplication/SellerWorkspace/AdminWorkspace`：设置工具子层。
- 同类工作区之间切换时替换工具子层，不追加历史。
- 子层返回到 `My`；再返回到内容锚点。
- 在子层点击工具栏 `Cart` 或 `My`，按工具根层规则重置覆盖路径。

### 6.5 结算、商品预览与支付

- `Cart → Checkout`：在 `Cart` 下设置 `Checkout` 子层。
- `Checkout → Product → 返回`：使用临时预览槽，返回 `Checkout`。
- 结算前离开到内容页或另一个工具入口时，清除未提交的纯客户端结算导航层；服务端购物车数据不因此改变。
- 支付请求已被服务端接受后，即使用户暂时打开“我的”，异步支付结果仍可接管导航并显示 `PaymentResult`。
- 进入 `PaymentResult` 时清除 `Cart`、`Checkout` 和临时预览，绝不允许返回已完成的 `Checkout`。
- 收据页直接“返回”时回到支付开始前保存的安全内容锚点。
- “继续购物”重置为默认首页第 1 页顶部。
- “查看已支付订单”重置为默认首页内容路径，再打开 `My`；从“我的”返回首页。

失败或仍待处理的支付尝试不创建支付完成态，用户仍停留在可重试的结算流程中。只有现有业务定义的终态结果才结束结算路径。

## 7. 返回规则

`Back` 每次只移除当前最高语义层：

1. `PaymentResult` → 安全内容锚点。
2. 临时商品预览 → `Checkout`（若存在），否则 → `Cart`。
3. 工具子层 → 对应工具根层。
4. 工具根层 → 内容路径当前页。
5. 内容详情层 → 内容发现层；若发现层为空则 → 首页。
6. 内容发现层 → 首页。
7. 首页 → 不执行操作，返回按钮禁用。

返回不依赖访问次数，不扫描类型，不读取已淘汰的旧节点，也不需要 `MAX_HISTORY`。

## 8. 左侧“校园商城”固定入口

当前侧栏入口调用 `coordinator.enter()`，已有路由时只重新显示当前深层页面。本次改为独立的 `goHome()` 语义：

1. 生成默认 `HomeProductQuery`：无关键词、无分类、销量降序、第 1 页、默认每页数量。
2. 将首页滚动位置设置为顶部。
3. 清除内容发现层、内容详情层、工具根层、工具子层、临时预览和支付完成态。
4. 显示默认首页并同步购物车数量。
5. 重置后商城“返回”按钮禁用，不能返回重置前页面。

“强制回首页”指目的地和导航状态必须重置，不代表绕过数据保护。若当前页是包含未保存内容的开店申请，仍先显示保存/丢弃/取消提示：

- 保存或确认丢弃后执行重置。
- 取消离开时保持当前页面和全部导航状态。
- 多个快速点击产生的旧确认回调继续由 `transitionVersion` 丢弃，避免过期回调覆盖新状态。

## 9. 状态结构与职责

建议新增一个只在 `client/shop` 内部使用的显式状态对象：

```java
record ShopNavigationState(
        ContentPath content,
        OverlayPath overlay,
        ShopRoute.PaymentResult receipt) {}

record ContentPath(
        ShopRoute.Home home,
        ShopRoute discovery,
        ShopRoute.Product detail) {}

record OverlayPath(
        ShopRoute utilityRoot,
        ShopRoute utilityChild,
        ShopRoute.Product preview) {}
```

实现时应通过构造器或工厂方法验证合法组合，例如发现层只能是 `Search/Storefront`，工具根层只能是 `My/Cart`，`Checkout` 只能位于 `Cart` 下。不能让页面组件直接修改槽位。

`ShopNavigator` 仍是唯一导航所有者，负责：

- 在切换前调用 `ShopRouteHost.capture()` 捕获当前可见页面状态。
- 根据当前上下文把目标路由放入正确槽位。
- 执行离开保护和过期回调隔离。
- 计算当前可见路由与 `canGoBack()`。
- 发布一次完整、合法的状态变更。

页面继续只发出“打开某路由”的意图。对调用方保留 `open()`、`back()`、`replaceCurrent()`、`completeCheckout()` 等窄接口，但它们内部不再操作通用队列。新增 `resetToDefaultHome()` 供侧栏和收据“继续购物”复用。

`history()` 不再代表真实存储队列。若测试或诊断仍需要它，应返回由当前分层状态推导出的、按返回顺序展平的只读快照；业务代码不能依赖或修改该列表。

## 10. 状态捕获与恢复

- 离开当前可见 `Home/Search/Storefront` 前，先捕获其查询、页码和滚动位置，并写回对应内容槽。
- 打开工具覆盖层不销毁内容槽，因此从 `My/Cart` 返回可恢复原状态。
- 同层替换会丢弃旧目标的状态，这是用户选择新商品、新店铺或新搜索条件的明确结果。
- 侧栏强制归首页有意丢弃所有旧状态，并使用默认首页状态。
- 商品、购物车、我的和工作区当前没有需要写入路由的可恢复视图状态；未来若增加，应扩展对应路由值，而不是恢复通用串行历史。

## 11. 异常与边界处理

- 导航状态构造出非法组合时立即抛出开发期异常，不静默猜测返回目标。
- `replaceCurrent()` 只能更新当前可见页面所属的同一槽；跨层调用应改用明确的打开/重置动作。
- 首次进入商城且尚无状态时初始化默认首页。
- 重复打开当前目标时只捕获并重新发布当前状态，不增加层。
- 会话失效、协调器销毁等既有生命周期行为保持不变。
- 导航重置只影响客户端页面状态，不清空购物车、订单、店铺申请草稿或任何服务端数据。

## 12. 测试驱动实施顺序

实施必须先写失败测试并观察失败原因正确，再做最小实现：

1. **导航状态单元测试（红灯）：**
   - 首页根层不可淘汰。
   - 商品 A/B/C 同层替换。
   - Search/Storefront 同层替换。
   - `My/Cart` 六组互切路径一次返回内容锚点。
   - `Cart → Product → Back → Cart`。
   - `Checkout → Product → Back → Checkout`。
   - 用户提供的完整循环分别执行 5、10、100 次，状态规模恒定且连续返回到首页。
   - 支付完成后所有推导返回路径均不含 `Checkout`。
2. **离开保护测试（红灯）：**
   - 开店申请未保存时，侧栏归首页分别覆盖保存、丢弃、取消。
   - 过期离开回调不能覆盖更新后的导航状态。
3. **协调器与侧栏集成测试（红灯）：**
   - 任意路由点击 `navigation.shop` 后显示默认首页第 1 页顶部。
   - 重置后返回禁用，旧深层页面不可恢复。
   - 重复点击侧栏不会增长状态。
4. **支付与工具页回归：** 保留现有收据按钮、异步支付接管、购物车数量和安全退出测试。
5. **完整回归：** 运行 Common、Server、Client 全部测试；本次不应产生服务端行为差异。
6. **人工验收：** 使用真实 Demo 按用户路径循环 10 次，逐次返回并截图；再验证侧栏强制归首页、购物车商品预览、确认订单商品预览和未保存申请提示。

## 13. 验收标准

- 用户给出的长浏览链循环 10 次后，最多四次返回即可到首页；具体次数由最后可见层决定，与循环次数无关。
- 循环 100 次的自动化测试中，导航状态节点数量不增加。
- 首页根层永远存在，不再定义或使用 `MAX_HISTORY`。
- `My` 与 `Cart` 任意互切后，一次返回到进入工具页前的内容锚点。
- 从购物车查看商品后返回购物车；从确认订单查看商品后返回确认订单。
- 支付完成后不能通过任何返回路径重新进入确认订单。
- 任意商城页点击左侧“校园商城”，在离开保护允许后显示默认首页第 1 页顶部，且不能返回重置前页面。
- 原有查询、筛选、排序、页码和滚动位置在普通分层返回中正确恢复。
