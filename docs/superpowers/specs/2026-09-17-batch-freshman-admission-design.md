# 新生 CSV 批量录取与自动分班设计

## 目标

为管理员提供固定 CSV 格式的批量新生录取能力。CSV 只包含姓名、性别、身份证、学院、专业；系统负责校验组织归属、生成学号、创建本科大一学生账号与档案，并按专业独立分班。

## 已确认规则

- 分班键为入学年份加专业；不同专业不得混班。
- 任一行校验失败时整批失败，不写入任何学生、账号、班级或流水号变化。
- 学院和专业必须真实存在，且专业必须隶属于 CSV 指定学院。
- 每班最多 35 人；人数超过 35 时使用 `ceil(人数 / 35)` 个班，人数差尽量不超过 1。
- 班级名沿用 `专业名 + 年份后两位 + 两位班号`，例如 `计算机科学与技术2601班`。
- 学号在最终分班确定后生成，沿用现有专业代码、年份、班号和流水号规则；失败时由事务回滚，不保留废弃学号。
- 新生统一按大一本科生录取，沿用现有账号初始化、培养方案关联和学生变更记录约定。

## 架构与数据流

复用现有 `StudentAdmissionCoordinator`、`StudentAdmissionService`、学号生成器、组织结构仓储、批量导入命令和客户端学生管理 UI。扩展批量录取命令、预览结果和提交结果 DTO；服务端负责最终解析、校验、分班和事务提交，客户端只负责选文件、展示预览与发起确认。

数据流为：

`CSV → 客户端读取/上传 → 服务端完整校验 → 按专业生成预览 → 管理员确认 → 请求去重 → Access 单事务写入 → 返回班级和学号结果`

学院、专业和培养方案继续通过现有组织/培养方案端口访问，不复制业务数据。服务端必须重新解析客户端提交内容，不能依赖客户端校验结果。

## CSV 与校验

固定表头为 `姓名,性别,身份证,学院,专业`。校验空文件、表头、列数、必填字段、姓名、性别（男/女）、身份证格式与校验码、CSV 内身份证重复、数据库身份证重复、学院存在性、专业存在性及 `专业.departmentId == 学院.departmentId`。

预览错误返回行号和字段级错误。学院管理员只能导入其授权学院，系统管理员可导入全部学院。预览不产生持久化副作用。

## 分班算法

每个 `入学年份 + majorId` 独立计算班级数。学生先按身份证号排序，以保证相同输入产生稳定结果；男女分别维护待分配队列。每次选择当前人数最少、男女比例偏差最小且未满 35 人的班级，按班号升序打破平局；容量满后排除。目标函数依次最小化班级男女比例差异、班级人数差异，并保持确定性。

最终结果返回每个专业的班级数、班级名称、人数、男女人数、学生预分配班级和学号信息。提交时按最终班级创建/复用班级并生成学号。

## 提交、事务与错误处理

确认提交使用现有请求去重机制，并锁定组织、班级编号和相关学号流水号资源后执行 Access 单事务。事务内再次检查专业归属、权限、身份证唯一性、班级容量和流水号可用性。任一异常整体回滚，客户端不得收到 SQL、路径、堆栈或内部异常细节。

## 测试与验证

先添加失败测试，再实现生产代码。覆盖正常单班、36 人拆两班、多个专业不混班、男女极端比例、专业学院错配、CSV/数据库重复身份证、非法 CSV、权限越界、事务中途失败回滚、重复请求去重，以及预览与最终落库一致性。使用 JDK 21 和 Maven，运行相关聚焦测试后运行 `mvn test`。
