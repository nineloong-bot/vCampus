# vCampus 全系统页面内编辑工作区设计

## 背景与目标

当前客户端同时存在页面内表单、模态 `JDialog` 和 `JOptionPane` 表单。新增或编辑记录时，独立窗口遮挡列表上下文，不同模块的关闭、保存、错误展示和刷新行为也不一致。部分业务页面还在主标题下重复解释页面用途，形成不必要的视觉噪声。教学班表单则把关键字查询和下拉选择拆成两套控件，课程、教师数据多时不便使用。

本次改造目标如下：

1. 全系统所有持续性数据录入、创建、编辑、申请和审核表单改为当前页面内的编辑工作区。
2. 工作区未打开时完全隐藏且不占空间；保存或取消后收起。
3. 简单表单优先显示在列表右侧，复杂表单及窄窗口显示在列表下侧。
4. 清除所有业务页面主标题下方的解释性小字，同时保留完成操作所需的信息。
5. 教学班的课程和教师选择改成输入即匹配的联想选择。
6. 保持现有服务端接口、Access 数据库、权限边界、乐观锁和业务规则不变。

## 统一工作区架构

客户端提供一个不依赖具体业务模块的 `EmbeddedEditorHost`。它组合列表内容与当前编辑器，只负责以下通用职责：

- 默认仅显示列表内容。
- 接收一个带标题、布局偏好和脏状态的编辑器面板。
- 打开、替换和关闭当前编辑器。
- 根据编辑器布局偏好和可用宽度选择右侧或下侧布局。
- 为放弃未保存内容提供统一确认入口。
- 在编辑器打开期间保留列表的筛选条件、分页和选中项。
- 提供可测试的打开状态、布局方向和编辑器生命周期事件。

工作区不得依赖课程、学籍、图书、商城、钱包或用户模块。各模块把现有弹窗的内容拆为普通 `JPanel`，通过小型生命周期接口与工作区协作。已经采用页面内卡片或页面内编辑器的功能直接接入统一生命周期，不重新包装成弹窗。表单仍调用本模块已有的 gateway 或 service，不允许跨模块访问 repository。

每个编辑器声明 `COMPACT` 或 `WIDE`：

- `COMPACT` 在窗口宽度充足时显示在右侧，宽度不足时自动改到下侧。
- `WIDE` 始终显示在下侧，适用于教学班排课、完整学籍、培养方案等宽表单。

实现使用 `JSplitPane` 切换水平与垂直方向；收起状态移除分隔组件，不得留下空白占位、分隔条或“请选择记录”提示。

## 统一交互规则

- “新建”“编辑所选”“录入”“申请”“审核”等入口在当前页面展开工作区，不创建新的顶层窗口。
- 新建和编辑复用同一个表单组件；编辑模式只负责加载已有值和携带版本号。
- 同一页面同时只能存在一个活动编辑器。
- 打开另一编辑器前，如果当前表单已修改，必须先确认是否放弃修改。
- 保存期间禁用重复提交，并将主操作按钮改为“正在保存…”等明确状态。
- 校验或网络失败时保留编辑器及用户输入，并在表单内展示错误。
- 保存成功后收起工作区、刷新当前分页，并在可行时重新选中保存后的记录。
- 取消无修改表单时直接收起；取消已修改表单时使用简短确认框。
- 页面切换或工作区关闭后，迟到的异步响应不得重新显示编辑器或覆盖新数据。

## 自适应布局

采用已确认的布局 C：

- 课程、学期、简单图书信息、简单用户配置等短表单优先放在右侧。
- 教学班排课、学生完整档案、培养方案、批量录入等复杂表单放在下侧。
- 当页面宽度不足以同时保证列表和表单的最小可用宽度时，`COMPACT` 自动转为下侧。
- 编辑器打开时，页面可降低列表可见行数或缩小列表宽度；不得缩小字体或造成字段、表头和按钮裁切。
- 编辑器关闭后，列表恢复占用全部页面空间。

## 教学班联想选择

教学班表单保留学期下拉框。课程与教师分别改为单个联想选择控件，删除原有关键字输入、查询按钮和全量下拉框。

### 课程

- 接受课程代码或课程名称输入。
- 输入停顿约 250 毫秒后调用现有课程目录查询接口。
- 最多显示 8 条结果，展示课程代码、课程名称和开课单位。
- 只允许选择启用课程。

### 教师

- 接受教师姓名、工号或登录账号输入。
- 输入停顿约 250 毫秒后调用现有教师查询接口。
- 最多显示 8 条结果，展示教师姓名或账号、工号以及所属单位；接口当前缺少的展示字段可省略，但选择值必须是稳定的用户 ID。
- 只允许选择当前在职教师。

### 共同规则

- 支持鼠标以及上下键、Enter、Esc。
- 必须从结果列表确认一项，任意自由文本不能作为关联 ID 保存。
- 编辑已有教学班时预填当前选择。
- 用户修改已确认的显示文字后立即清除原关联 ID，必须重新选择。
- 每次查询带递增序号，只接受最新请求结果。
- 加载中、无匹配项和查询失败显示在控件下方，不使用弹窗。

## 页面文字规范

所有登录后可见的业务页面，无论角色，均保留：

- 面包屑与主标题；
- 页签、筛选条件、字段标签、表头、按钮；
- 字段校验错误；
- 加载中、空数据、连接失败、版本冲突和提交中等必要反馈；
- 必须理解才能正确操作的简短业务提示，可放在字段旁或工具提示中。

统一删除：

- 主标题正下方对页面用途的解释；
- 编辑工作区标题下重复说明表单用途的文字；
- 列表底部解释“新增和编辑使用统一表单”等实现或操作方式的文案；
- “已加载”“参考数据已就绪”“尚无修改申请”等正常态静态提示。

正常加载完成不显示状态文字。登录页品牌副标题“校园服务 · 学术生活”不属于业务页面说明，保留。

## 模块迁移范围

迁移判定以行为为准：凡是会创建或修改业务记录，并要求用户填写字段后提交的界面，都属于页面内工作区。源码扫描和全部角色页面遍历用于验证下列入口不存在遗漏。

### 课程中心

- 课程目录的新建与编辑；
- 学期的新建与编辑；
- 教学班的新建与编辑，包括排课行；
- 需要持续输入的选课调整表单。

### 学籍档案

- 学生手工录取、批量录取和完整档案编辑；
- 学生联系方式、考勤方式和学籍变更申请；
- 学院、专业、年级、班级及学院管理员维护；
- 培养方案、方案课程、课程库引入和跨学科课程申请/审核；
- 成绩录入、转专业批次、招生专业、申请和审核表单。

### 图书借阅

- 书目的新增与编辑；
- 馆藏副本的新增与编辑；
- 包含持续字段录入的借阅管理操作。

### 校园商城

- 开店申请的新建与编辑；
- 商品及 SKU 的新增与编辑；
- 店铺资料编辑；
- 需要填写内容的申请审核、驳回和店铺状态处理。
- 新版 commerce 商品编辑、目录导入和治理表单；已经页面化的编辑器保留页面形态并接入统一工作区行为。

### 校园钱包

- 充值及要求填写字段的余额管理操作；
- 钱包历史仅查询，不作为编辑器迁移对象。

### 用户与权限

- 用户角色和模块权限编辑；
- 用户状态、角色分配及教师账户维护中要求填写字段的表单。

## 保留弹窗的例外

以下交互不是持续性编辑工作区，继续使用系统弹窗或专用窗口：

- 删除、退出、提交、放弃修改和重置密码等简短二次确认；
- 错误、警告和一次性结果提示；
- 文件打开与保存选择器；
- 模拟支付窗口；
- 只读详情窗口；
- 首次登录强制修改密码、会话被替换等登录安全流程。

如果某个现有弹窗同时包含只读详情和持续编辑，应拆分：详情留在原页面或详情区域，编辑字段进入工作区。

## 状态与错误处理

- 表单自身持有字段和脏状态，页面持有筛选、分页与选中状态。
- 保存命令继续携带已有的幂等请求标识和乐观锁版本。
- 版本冲突不关闭表单，提示刷新后重试，并防止静默覆盖。
- 工作区、页面和联想选择分别使用异步请求守卫，忽略关闭或过期请求。
- 客户端不展示 SQL、数据库路径、堆栈或内部异常细节。
- 失败信息使用现有稳定错误码映射为可操作的中文提示。

## 代码组织与约束

- 新 Java 文件不得超过 200 个物理行。
- 修改现有超过 200 行的弹窗类时，必须按表单视图、参考数据加载、提交协调或排课子面板拆分，不得继续增加职责。
- 共享工作区只包含布局、生命周期和通用脏状态协议。
- 业务校验保留在模块表单和服务边界；共享组件不得复制业务规则。
- 课程、学籍、图书、商城、钱包和用户模块继续通过各自的客户端端口通信。
- 不修改 Access 模式或种子数据，不引入 MySQL、远程数据库或新的共享基础设施。

## 测试策略

所有行为变更遵循测试先行。

### 共享组件测试

- 默认隐藏且不占空间；
- 打开、替换、保存后关闭和取消行为；
- 脏表单放弃确认；
- `COMPACT` 的右侧/下侧响应式切换；
- `WIDE` 始终位于下侧；
- 页面隐藏后忽略迟到结果。

### 联想选择测试

- 防抖后查询且最多展示 8 条；
- 只接受最新响应；
- 鼠标与键盘选择；
- 自由文本不能提交；
- 修改显示文字使旧 ID 失效；
- 编辑模式回填；
- 加载、空结果和失败状态。

### 模块回归测试

- 每个新增、编辑、录入、申请和审核入口打开页面内组件，而非顶层 `JDialog`；
- 保存命令内容、版本号、权限和刷新行为保持一致；
- 页面工作区关闭后筛选、分页和选择不丢失；
- 全部角色可达页面不再渲染页面说明小字；
- 例外清单中的确认、安全、文件、支付和只读窗口仍正常工作。

### 交付验证

- 使用 JDK 21 运行各任务的聚焦测试；
- 完成全部模块迁移后运行完整 `mvn test`；
- 执行 Java 文件物理行数检查、`git diff --check` 和精确差异审阅；
- 重新打包并验证 `vcampus-distribution/lib/vCampusClient.jar`；
- 不提交运行时改写的 Access 数据库、服务端 JAR、日志或临时文件。

## 实施分段

该改造以一个统一设计交付，但按以下可独立验证的阶段实施：

1. 共享页面内工作区与联想选择基础组件。
2. 课程中心迁移并完成教学班联想选择。
3. 学籍档案迁移。
4. 图书借阅迁移。
5. 校园商城迁移。
6. 校园钱包迁移。
7. 用户与权限迁移。
8. 全角色页面说明文字审计、发行包更新和完整验证。

每个阶段必须保持可编译、聚焦测试通过；不得等到最后再补测试或一次性拆分所有超长类。
