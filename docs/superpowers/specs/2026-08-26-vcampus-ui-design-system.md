# VCampus UI 设计系统与多人协作规范

## 1. 文档目的

本文档是 VCampus Swing 客户端的唯一 UI 设计基线，用于约束用户管理、学籍管理、选课系统、图书馆和校园商城五个并行开发模块的视觉、布局、组件、交互和验收标准。

本文档只定义客户端界面规范，不改变业务权限、消息协议、服务端规则或数据库设计。

### 1.1 规范词

- **必须**：所有模块都要遵守，不允许业务页面自行覆盖。
- **应**：默认遵守；确有业务原因时，必须登记例外。
- **可以**：在不改变公共视觉语言的前提下选择使用。
- **禁止**：不得在业务页面或私有组件中出现。

## 2. 设计方向

### 2.1 核心气质

VCampus 采用“传统学术”方向：克制、可信、安静、有高校文化感，同时优先保证高密度表格、表单和管理操作的可读性。

关键词：

- 纸张米白，而非纯白或冷白。
- 学院墨绿用于导航和结构。
- 砖红用于当前主操作和关键提醒。
- 宋体/衬线排版塑造学术感。
- 直角、细线、有节制的留白，不堆叠卡片。

### 2.2 界面原则

1. **信息优先**：视觉不得干扰查询、比较、填写和确认。
2. **一屏一个主任务**：页面标题与主操作必须唯一且清晰。
3. **一致重于个性**：业务模块不使用私有配色、字体和布局语言区分自己。
4. **状态必须明确**：加载、空结果、错误、断线、提交中和并发冲突不得使用空白页面表达。
5. **颜色不单独传意**：状态必须同时包含文字、图标或结构差异。
6. **异步不打断**：网络等待期间保留已有内容，只锁定受影响的操作区域。

## 3. 设计令牌

业务代码必须从公共令牌类取值，禁止直接写入颜色、字号、间距、圆角和边框数值。令牌实现建议分为 `UiColors`、`UiTypography`、`UiSpacing`、`UiDimensions` 和 `UiBorders`。

### 3.1 颜色令牌

| 令牌 | 色值 | 用途 | 禁止用法 |
|---|---|---|---|
| `BACKGROUND_PAGE` | `#FBF7EF` | 全局页面、表格内容行 | 不用于墨绿文字的禁用态 |
| `BACKGROUND_SUBTLE` | `#ECE3D1` | 筛选区、说明区、表格表头 | 不用于大面积导航 |
| `BACKGROUND_NAV` | `#E3D8C2` | 左侧导航默认底色 | 不用于主按钮 |
| `PRIMARY` | `#163B33` | 顶栏、导航选中、结构强调 | 不用于普通正文大段铺色 |
| `PRIMARY_HOVER` | `#214C43` | 墨绿交互态 | 不得代替砖红主操作 |
| `ACCENT` | `#AD4432` | 当前区域唯一主操作、阶段提醒 | 不用于导航栏或多个并列按钮 |
| `ACCENT_HOVER` | `#963A2B` | 砖红交互态 | 不得用于非交互装饰 |
| `TEXT_PRIMARY` | `#2E2C26` | 标题、正文、表格数据 | 不得在墨绿底色上使用 |
| `TEXT_SECONDARY` | `#6D6556` | 辅助说明、时间、面包屑 | 不用于错误和必读信息 |
| `TEXT_ON_PRIMARY` | `#F8F1E4` | 墨绿底色上的文字和图标 | 不用于纸张米白底色 |
| `BORDER_DEFAULT` | `#C6B896` | 控件、分隔线、表格水平线 | 禁止叠加成粗重网格 |
| `FOCUS` | `#AD4432` | 2 px 键盘焦点边框 | 焦点不得被去除 |
| `SUCCESS_BG` | `#DCE6D8` | 成功、正常、可用状态底色 | 必须搭配文字 |
| `SUCCESS_FG` | `#27533F` | 成功状态文字 | 不用于普通链接 |
| `WARNING_BG` | `#F1DFC0` | 余量少、即将到期、待审核 | 必须搭配文字 |
| `WARNING_FG` | `#76501F` | 警告文字 | 不代替高风险错误 |
| `ERROR_BG` | `#EED6D0` | 错误、禁用、失败状态底色 | 必须搭配文字 |
| `ERROR_FG` | `#7D3028` | 错误文字、危险操作 | 不用于普通提示 |
| `DISABLED_BG` | `#E4DED2` | 禁用控件底色 | 禁用状态仍需保留文字对比 |
| `DISABLED_FG` | `#8B8477` | 禁用文字 | 不用于正常辅助文字 |

禁止使用渐变、蓝紫主色、高饱和荧光色、大面积纯白 `#FFFFFF` 以及无语义的多色图标。

### 3.2 字体与排版

默认使用同一中文衬线字体完成页面标题、正文、表单和表格排版，保持传统学术质感。

字体选择顺序：

1. 随客户端分发并注册的“思源宋体”。
2. Windows 的“宋体”。
3. macOS 的“宋体-简”。
4. Java 逻辑字体 `Serif`。

| 角色 | 字号 | 字重 | 用途 |
|---|---:|---:|---|
| `DISPLAY` | 26 | 600 | 登录页产品名，每页最多一处 |
| `PAGE_TITLE` | 22 | 600 | 业务页面主标题 |
| `SECTION_TITLE` | 16 | 600 | 表单分组、详情分组 |
| `BODY` | 14 | 400 | 正文、表单、标准表格 |
| `TABLE_COMPACT` | 13 | 400 | 仅限高密度管理表格 |
| `CAPTION` | 12 | 400 | 面包屑、辅助说明、时间 |

字号为 Swing 逻辑 UI 尺寸，交由平台高 DPI 缩放。禁止使用小于 12 的可见文字，禁止用全大写英文承载必读信息。英文学术眉题只能作为短辅助标签。

### 3.3 间距、尺寸与边界

所有间距使用 4 的倍数。

| 令牌 | 数值 | 典型用途 |
|---|---:|---|
| `SPACE_1` | 4 | 图标与短文字 |
| `SPACE_2` | 8 | 相关控件内部间距 |
| `SPACE_3` | 12 | 字段标签与控件、按钮组 |
| `SPACE_4` | 16 | 表单行、小分组 |
| `SPACE_6` | 24 | 页面标准内边距、主分组 |
| `SPACE_8` | 32 | 页面标题与主内容的最大分隔 |

固定尺寸：

- 标准输入控件和按钮高度：32。
- 紧凑工具栏控件高度：28，仅限表格局部工具栏。
- 标准表格表头/内容行高：40。
- 紧凑表格表头/内容行高：34。
- 按钮水平内边距：16；图标与文字间距：8。
- 普通边框：1 px `BORDER_DEFAULT`。
- 键盘焦点：2 px `FOCUS`。
- 圆角：0 或 2 px；禁止胶囊形按钮、输入框和状态标签。
- 阴影：普通页面和内容组禁止使用；只有模态对话框可以使用一层轻微阴影。

## 4. 应用外壳

### 4.1 窗口基线

- 主窗口默认尺寸为 1280 × 800，最小尺寸为 1024 × 680。
- 用户可以放大窗口，主内容必须自适应；不得通过绝对坐标堆叠页面。
- 高 DPI 缩放下，字体、图标、行高和点击区必须一起缩放。
- 主窗口必须使用布局管理器，禁止 `null` 布局和业务页面内的 `setBounds`。

### 4.2 固定结构

```text
┌──────────────────────────────────────────────┐
│  顶部身份栏：产品名 / 当前用户 / 角色 / 连接状态  │ 56
├────────┬─────────────────────────────────────┐
│        │  面包屑 / 页面标题 / 页面主操作        │
│ 左侧   ├─────────────────────────────────────┤
│ 权限   │                                      │
│ 导航   │          CardLayout 页面内容         │
│ 184    │                                      │
│        │                                      │
├────────┴─────────────────────────────────────┤
│  底部状态栏：最近操作结果 / 后台任务 / 时间    │ 28
└──────────────────────────────────────────────┘
```

- 顶栏使用 `PRIMARY` 底色和 `TEXT_ON_PRIMARY` 文字。
- 左侧导航使用 `BACKGROUND_NAV`；选中项使用 `PRIMARY` 底色。
- 中部业务页统一使用 24 内边距和 `BACKGROUND_PAGE`。
- 底部状态栏只显示短信息，不承载需要用户确认的错误。
- 五个业务模块只能替换中部 `CardLayout` 页面，不得修改外壳的颜色、尺寸、导航或状态栏结构。

### 4.3 导航

- 一级顺序固定为：总览、学籍档案、课程中心、图书借阅、校园商城、账户设置。
- 管理员功能在对应业务模块内展开，禁止在一级导航堆叠所有管理页面。
- 无权限的入口直接隐藏；已显示但因当前状态不可用的操作应禁用并提供原因。
- 导航项文字优先，图标只用于快速识别；不得只显示无文字图标。

### 4.4 认证流程

`LoginFrame`、`RegisterDialog` 和 `InitialPasswordChangeDialog` 是唯一不使用业务外壳的页面。

- 登录窗口主体建议为 760 × 480，左侧显示产品身份，右侧显示登录表单。
- 服务器连接状态必须在登录按钮附近可见。
- 首次改密页只显示改密和登出，不显示业务导航或广告。

## 5. 公共组件

所有公共组件必须支持默认、悬停、聚焦、按下、禁用和加载状态。业务页面只能传入内容、语义状态和允许的尺寸等级，不得覆盖视觉属性。

### 5.1 按钮

| 组件 | 视觉 | 使用规则 |
|---|---|---|
| `PrimaryButton` | 砖红底、浅色文字 | 每个页面区域最多一个；用于提交、保存、确认结算 |
| `SecondaryButton` | 透明/米白底、墨绿边框 | 用于查询、返回、编辑、刷新 |
| `GhostButton` | 无底色、文字操作 | 只用于紧凑工具栏和低风险局部操作 |
| `DangerButton` | 错误深色底或错误文字边框 | 只用于注销、停用、取消订单等高风险操作 |

- 按钮使用动宾短语，例如“保存修改”，不使用含糊的“确定”作为页面主操作。
- 提交期间必须禁用重复提交，按钮文字改为“正在……”，完成后恢复。
- 按钮不得只有无标签图标；例外仅限关闭等公认操作，且必须有可访问名称。

### 5.2 表单控件

- 文本框、密码框、下拉框和日期控件高度统一为 32。
- 标签放在控件上方；只有短筛选工具栏可以使用左标签。
- 占位文字只用于示例或格式，不得代替标签。
- 必填字段使用“必填”文字或星号并在页面解释，不只使用红色。
- 字段错误显示在控件下方，内容必须说明如何修正。
- 提交失败后保留用户输入，密码字符数组按安全规则及时清理。

### 5.3 筛选区

- 一至三个条件可以与查询按钮同行。
- 超过三个条件必须放入独立筛选区，并提供“查询”和“重置”。
- 筛选区使用 `BACKGROUND_SUBTLE`、1 px 下边界和 16 内边距，不使用阴影或卡片圆角。
- 查询后在结果上方显示“共 N 条”及主要筛选摘要。

### 5.4 表格与分页

- 表格表头使用 `BACKGROUND_SUBTLE`，内容行使用 `BACKGROUND_PAGE`。
- 只保留水平分隔线，禁止全网格和斑马纹强对比底色。
- 文本左对齐；数量、金额右对齐；状态和短编号可以居中。
- 操作列位于最右侧，最多显示两个高频操作；更多操作收入“更多”菜单。
- 长文本优先限制列宽并显示省略，通过详情页查看全文；关键身份值不得被截断。
- 无记录时表头可以保留，表体显示空结果组件和下一步建议。
- 分页区统一显示总数、上一页、当前页/总页数、下一页；不得在模块中自行改变顺序。

### 5.5 状态标签

状态标签使用 2 px 圆角、8 px 水平内边距，必须显示可理解的中文文字。

| 语义 | 示例 | 配色 |
|---|---|---|
| 成功/正常 | 正常、已通过、可选、可借 | `SUCCESS_BG` + `SUCCESS_FG` |
| 警告/待处理 | 待审核、余量少、即将到期 | `WARNING_BG` + `WARNING_FG` |
| 错误/终止 | 已禁用、已拒绝、逾期、支付失败 | `ERROR_BG` + `ERROR_FG` |
| 中性/历史 | 草稿、已完成、已取消、已归还 | `BACKGROUND_SUBTLE` + `TEXT_SECONDARY` |

### 5.6 对话框

对话框固定分为标题区、正文区和操作区。

- 小型确认：420 px 宽。
- 标准表单：560 px 宽。
- 复杂对比或多分组表单：720 px 宽。
- 对话框不得超过主窗口可见区域；超长内容只滚动正文区，标题和操作区保持可见。
- 取消按钮在左，确认按钮在右。
- 高风险确认必须说明对象、影响和是否可恢复，不得只显示“是否确定”。

### 5.7 通知和反馈

- 轻量成功反馈通过 `NotificationService` 和底部状态栏呈现，3–5 秒后可自动消退。
- 需要用户决策的错误必须使用页内错误区或对话框，不能只放在状态栏。
- 通知文案使用“结果 + 对象 + 下一步”，例如“课程已选上，可在我的课表查看”。
- 不向用户显示 SQL、堆栈、类名、文件路径和内部错误码；追踪编号可以放在详情折叠区。

## 6. 五类业务页面模板

每个业务页面必须归属以下五类模板之一。业务内容不同不构成新建布局模板的理由。

### 6.1 查询列表页

结构：面包屑 → 页面标题/主操作 → 筛选区 → 结果摘要 → 表格 → 分页。

适用：账户、学生、教学班、借阅、订单、审计日志等。

### 6.2 详情页

结构：返回/面包屑 → 身份摘要 → 状态与主操作 → 2–4 个字段分组 → 关联历史。

身份摘要不使用多张统计卡片，改用单一水平摘要区。

### 6.3 编辑表单页

结构：页面标题 → 必读说明 → 分组表单 → 字段错误 → 底部操作区。

- 单列表单最大宽度 640 px。
- 双列表单只用于相关短字段，窄窗口下必须回流为单列。
- 操作区使用顶边界与表单分隔，不得将保存按钮散落在分组内。

### 6.4 管理页

管理页以查询列表为主体，新增和短编辑使用对话框；只有多分组、长流程编辑才使用独立表单页。

批量操作必须显示已选数量、作用范围和取消选择入口。

### 6.5 展示页

只有商城首页、商品搜索和商品详情可以使用图片网格。

- 商品网格使用 3–4 列自适应布局，窄窗口逐步减少列数。
- 商品图片统一比例和占位图，禁止因原图尺寸导致列表跳动。
- 商品容器可以使用 1 px 边界，但不使用大圆角、浮夸阴影和渐变。
- 价格可以使用 `ACCENT`，但不得与主操作在同一区域形成多个竞争焦点。

以下映射用于防止模块成员自行发明页面结构。对话框仍使用公共对话框结构，不单独构成页面模板。

| 模块 | 查询列表 | 详情 | 编辑表单 | 管理 | 展示 |
|---|---|---|---|---|---|
| 用户 | `UserManagementPanel`、`SecurityAuditPanel` | `AccountPanel` | — | 账户管理、角色调整对话框 | — |
| 学籍 | `StudentSearchPanel` | `MyStudentProfilePanel`、`StudentDetailPanel` | — | `OrganizationManagementPanel`、录取/联系方式/学籍变更对话框 | — |
| 选课 | `OfferingSearchPanel`、`MyEnrollmentPanel`、`AdjustmentPanel`、`RetakePanel`、`AdjustmentAuditPanel` | `OfferingDetailDialog`、`MySchedulePanel` | — | `TermManagementPanel`、`CourseCatalogPanel`、`OfferingManagementPanel`、`OutcomeImportPanel` | — |
| 图书馆 | `BookSearchPanel`、`CurrentLoansPanel`、`LoanHistoryPanel` | `BookDetailPanel` | — | `BookManagementPanel`、`CopyManagementPanel`、`LoanAdminPanel`、`LibraryPolicyPanel` | — |

## 8. 页面状态模型

每个查询和数据页面必须明确实现以下状态：

| 状态 | 呈现 | 交互要求 |
|---|---|---|
| 初始 | 显示默认查询条件和必要说明 | 不伪造结果，不显示错误 |
| 加载 | 保留旧内容，在结果区显示加载条/轻量遮罩 | 禁用相同查询或提交，其他导航仍可用 |
| 正常 | 显示完整内容、结果数和当前筛选摘要 | 保留可刷新和分页操作 |
| 空结果 | 显示“未找到……”、可能原因和下一步 | 允许重置筛选或执行合法的新建操作 |
| 错误 | 页内错误区显示用户可理解的原因 | 可重试时提供“重试”，不可重试时提供替代路径 |
| 断线 | 顶栏连接状态和页内提示同时变更 | 禁用依赖服务器的写操作，保留已加载内容 |
| 提交中 | 只锁定表单和其操作区，按钮显示进行中文案 | 禁止重复提交，不清空用户输入 |
| 并发冲突 | 说明记录已被修改，标出需要刷新 | 禁止静默覆盖；提供“刷新数据” |

`LoadingOverlay`、`EmptyStatePanel`、`ErrorStatePanel`、`DisconnectedStatePanel` 和 `ConflictStatePanel` 必须由公共 UI 层提供，业务模块不得复制实现。

## 9. 交互与文案

### 9.1 操作层级

- 页面主操作位于标题右侧或表单底部右侧。
- 同一操作区不得同时出现两个 `PrimaryButton`。
- 列表行内操作不得抢过页面主操作的视觉层级。
- 可逆的普通操作不弹出确认框；高风险、跨对象或明显不可逆操作必须确认。

### 9.2 键盘与焦点

- `Tab` 顺序必须与页面的视觉阅读顺序一致。
- `Enter` 可以触发当前表单主操作，但高风险操作不得因普通回车直接执行。
- `Esc` 关闭非阻断对话框；有未保存变更时先确认。
- 弹出对话框后焦点移入对话框，关闭后返回触发元素。

### 9.3 文案

- 标题描述用户当前处理的对象，例如“教学班查询”，不使用“页面”“系统”等空泛词。
- 按钮使用动词，状态使用完整中文，错误说明修正方式。
- 同一业务对象的名称在五个模块中必须一致，不得交替使用缩写、英文和中文别名。

## 10. 可访问性与适配

- 所有可交互组件必须支持键盘访问和可见焦点。
- 文本与其实际底色必须具有清晰对比；辅助色不得承载关键信息。
- 状态、必填、错误和选中不得只通过颜色区分。
- 图标必须有文本标签或可访问名称；纯装饰图标不获得焦点。
- 主窗口在 1024 × 680 与 150% 缩放下不得出现重叠、裁切或无法到达的主操作。
- 长姓名、长商品名、长课程名和长错误文案必须纳入截断/换行测试。

## 11. Swing 异步界面约束

- EDT 不得执行 Socket 等待、数据库访问、大文件读取或重计算。
- 页面通过客户端服务获得 `CompletableFuture`，并通过 `SwingUtilities.invokeLater` 更新组件。
- 页面离开或窗口关闭后，已返回的异步结果不得更新已失效组件。
- 相同查询连续发起时，页面只接受最新请求的结果，防止旧结果覆盖新结果。
- 提交失败不清空表单；提交成功后是刷新、返回还是保留页面，必须由业务结果明确决定。

## 12. 多人协作治理

### 12.1 所有权

- 公共设计令牌、应用外壳和公共组件由指定 UI 负责人维护。
- 五个模块负责人只拥有自己模块中的页面组装、数据绑定和业务文案。
- 业务模块不得复制公共组件后修改外观，不得在私有包中建立第二套主题。

### 12.2 变更规则

- 新建公共组件前，必须先证明现有组件无法通过组合或合法参数完成需求。
- 设计令牌或公共组件变更需要全组确认。
- 业务页面 UI 变更至少由一名非本模块成员评审。
- 禁止为了单个页面修改全局令牌。
- 例外必须在本文档的“例外登记”中写明名称、原因、适用页面、负责人和到期处理方式。

### 12.3 截图巡检

每周至少进行一次跨模块截图巡检。截图条件统一为：

- 1280 × 800 主窗口。
- 100% UI 缩放。
- 统一的演示用户、中文测试数据和连接状态。
- 每个页面至少截取正常状态；新页面还需截取加载、空结果和错误状态。

巡检时将五个模块截图并排比较，重点检查页面标题、筛选区、表格、按钮、状态标签、对话框和空白密度。

## 13. UI 验收清单

业务页面只有在以下项目全部通过后才可以合并。

### 13.1 视觉一致性

- [ ] 颜色、字体、字号、间距、尺寸和边框全部来自公共令牌。
- [ ] 页面使用纸张米白、墨绿和砖红的规定语义，无私有主色。
- [ ] 无渐变、胶囊控件、大圆角、浮夸阴影和卡片堆叠。
- [ ] 页面标题、分组标题、正文和辅助文字层级一致。

### 13.2 结构与组件

- [ ] 页面明确归属五类业务模板之一。
- [ ] 外壳、导航和底部状态栏未被业务页面修改。
- [ ] 使用公共按钮、表单、表格、分页、状态和对话框组件。
- [ ] 同一操作区只有一个主操作。
- [ ] 表格对齐、行高、操作列和分页符合公共规则。

### 13.3 状态与异常

- [ ] 实现初始、加载、正常、空结果、错误和断线状态。
- [ ] 写操作实现提交中和并发冲突状态。
- [ ] 提交失败保留输入，不静默覆盖并发修改。
- [ ] 错误文案可理解、可行动，不泄露内部实现。
- [ ] 状态不只依赖颜色表达。

### 13.4 可用性与技术约束

- [ ] 1024 × 680、1280 × 800 及 150% 缩放下无重叠、裁切和不可达操作。
- [ ] 长文本、空值、最大金额和最大页数等边界数据未破坏布局。
- [ ] 键盘焦点顺序正确，焦点可见，对话框焦点可恢复。
- [ ] EDT 不执行网络等待或重任务。
- [ ] 异步请求不会用旧结果覆盖新结果，也不会更新已销毁页面。

### 13.5 协作与评审

- [ ] 提交包含统一窗口尺寸下的正常、加载、空结果和错误截图。
- [ ] 至少一名非本模块成员完成 UI 评审。
- [ ] 未新建重复公共组件，未在私有包中建立第二套主题。
- [ ] 存在例外时已完成例外登记和团队确认。
