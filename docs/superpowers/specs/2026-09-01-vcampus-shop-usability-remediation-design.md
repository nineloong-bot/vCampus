# vCampus Shop 手工测试问题整改设计

**日期：** 2026-09-01
**状态：** 已完成逐节确认，待最终文档审阅
**依据：** `2026-09-01-vcampus-shop-manual-test-findings.md`
**覆盖范围：** `SHOP-TEST-001` 至 `SHOP-TEST-008`
**集成基线：** `origin/feat/user-management@8d53d9e`

## 1. 目标与边界

本设计解决最终四角色 Demo 手工测试中发现的 8 组、12 个可用性问题。整改以现有 Shop 分层和业务能力为基础，不重写模块，也不扩大到其他业务域。

允许修改的范围为：

- `common/shop` 的 Shop 契约、展示所需枚举和值对象。
- `server/shop` 的 Shop 查询、校验和应用服务。
- `client/shop` 的导航、状态、数据加载和 Swing 视图。
- Shop 数据库查询、Demo、测试、发布脚本及说明文档。

以下实现只作为依赖使用，不修改其实现：Foundation、User、Socket、Router、事务框架和公共网络接口。

本轮不升级数据库表结构，不新增图片表，不执行数据迁移。已有商品、订单、购物车和开店申请数据继续有效。

Shop 必须全面适配当前 User Manager 的统一登录、首次改密、账户、权限、退出和会话生命周期。适配以 `8d53d9e` 的公开类型与统一应用外壳为基线，只修改 Shop 侧安装器、组合入口、状态协作和测试，不复制或修改 User Manager 的实现。

## 2. 总体结构

整改拆分为六个边界清晰的单元：

1. User Manager 兼容层和统一启动链路。
2. 导航策略与离开页面保护。
3. 商品目录、搜索和响应式卡片。
4. 购物车、确认订单和金额展示。
5. 开店申请与管理员审核。
6. 卖家商品/SKU 工作区和预置封面。

业务请求、页面状态和 Swing 渲染保持分离：

- 导航器只决定页面关系，不保存业务表单。
- 页面状态对象维护加载、编辑、脏数据和提交状态。
- 数据加载器调用现有 Shop 客户端服务并产出视图模型。
- Swing 组件只渲染视图模型并发出用户意图。

这一边界使最终 UI 可以被其他组员替换，而无需重写导航规则、业务校验或网络调用。

## 3. User Manager 当前版本适配

### 3.1 基线与所有权

适配目标是 `origin/feat/user-management` 当前最新提交 `8d53d9e`，包括：

- `LoginFrame` 的登录、教师账户申请、锁定提示和安全错误信息。
- `InitialPasswordChangeDialog` 的首次登录改密流程。
- `MainFrame` 的统一身份头、权限导航、内容区和连接状态。
- `AccountPanel` 的个人账户、改密、账户管理、安全审计和退出确认。
- `UserUiCoordinator` 的受限会话隔离及返回登录页流程。

User Manager 拥有身份、账户、角色、权限、登录和退出；Shop 拥有商品、店铺、申请、订单、购物车及商城内部导航。Shop 不修改 User Manager、Foundation、Socket 或 Router 的实现。

当前 `SHOP` 只合入了 User Manager 至 `faded03` 的版本，尚不包含 `8d53d9e`。本设计固定最新提交为兼容目标，但不等同于授权执行 Git merge。任何直接依赖 `AccountPanel` 等最新类型的最终联合编译，必须在用户另行明确允许整合该版本后进行；此前只实施能够在当前分支独立验证的 Shop 兼容边界。

### 3.2 Shop 模块安装边界

`ShopUiInstaller` 是唯一的客户端接入点。最终应用组合入口在 User Manager 创建并配置 `MainFrame` 后调用安装器，将 Shop 内容装入既有 `page.shop`，并绑定既有 `navigation.shop`。Shop 不自行创建另一套主导航、身份头或账户页。

最新 `UserUiCoordinator` 当前没有第三方模块注册回调，因此 Shop 侧只提供可直接调用的安装器和生命周期契约；最终整合入口负责在显示窗口前调用。不得通过复制 User 协调器、反射访问私有方法或改写 User 页面来绕过该边界。

最终应用组合入口和独立 Shop Demo 组合入口都只编排 User Manager 的公开组件：登录成功且首次改密完成后创建统一 `MainFrame`，安装 User Manager 的 `AccountPanel`，再调用 `ShopUiInstaller`。组合入口可以管理跨模块交接，但不得复制账户、改密、退出或权限页面的内部实现。

安装器接收：

- 已完成登录和首次改密的 `UserView`。
- User Manager 持有的共享 `ClientConnection`。
- Shop 客户端端口。
- 单一会话失效回调。

关闭窗口、退出登录或会话失效时，Shop 协调器只释放自身异步请求和页面状态；清除令牌、关闭统一外壳及重新显示登录页由 User Manager 的会话流程执行。

### 3.3 身份、角色与权限

- Shop 只使用 `LoginResult.user()` / `UserView` 的安全身份投影，不缓存密码或自行解析会话令牌。
- 学生、教师和管理员身份来自 `UserRole`；账户必须为 `ACTIVE`。
- 管理员商城入口由 User 角色控制，并由 Shop 服务端再次鉴权。
- 店主身份由 Shop 已审核店铺记录决定，不在 User 角色中增加“店主”。
- User 权限决定账户管理和安全审计页面；Shop 不复刻这些权限页面。
- Shop 的“我的”只展示商城订单、开店申请、卖家工作区或商城管理入口，不再重复账户状态、修改密码和退出登录。

### 3.4 登录、退出与失效流程

首次登录必须先完成 User Manager 改密，成功重新登录后才安装并进入 Shop。待审核、停用、注销或受限会话不能进入商城外壳。

正常退出只从统一 `AccountPanel` 发起，使用其确认对话框和 `UserClientService.logout()`。Shop 不增加第二个退出按钮。任意 Shop 请求返回会话失效时，所有页面汇聚到同一个幂等回调，避免重复关闭窗口或重复打开登录页。

### 3.5 统一端口

最终 Demo 与普通 vCampus 配置统一使用 TCP `8888`：

- Shop Demo 服务端默认监听 `8888`。
- 客户端默认连接 `127.0.0.1:8888`。
- BAT、PowerShell 脚本、发布包、联机说明和端口诊断统一使用 `8888`。
- 服务端和客户端仍允许通过显式启动参数覆盖端口。
- 自动化测试继续使用动态临时端口，避免并行执行互相占用。
- 启动说明明确同一台机器不能同时运行两个占用 `8888` 的服务端。

## 4. 导航与未保存内容保护

### 4.1 内容页与工具页

商城页面分成两类：

- **内容页：** 首页、搜索结果、分类结果、店铺页、商品详情等。
- **工具页：** “我的”和“购物车”。

导航器保留正常的内容页历史，同时单独维护当前工具区的内容页锚点。首次从内容页进入“我的”或“购物车”时记录锚点；工具页之间切换只替换当前工具页，不追加历史。重复打开当前工具页是幂等操作。

从工具页点击“返回”时，一次返回锚点内容页。必须满足：

- 首页 → 我的 → 返回 → 首页。
- 首页 → 购物车 → 返回 → 首页。
- 首页 → 我的 → 购物车 → 我的 → 返回 → 首页。
- 搜索 → 购物车 → 我的 → 返回 → 搜索。
- 商品详情 → 我的 → 购物车 → 返回 → 商品详情。

新的内容导航开始后，旧工具区锚点随之失效，避免跨流程返回到过期页面。

### 4.2 页面离开守卫

Shop 导航器提供客户端内部的页面离开守卫。所有可能离开当前页面的入口，包括返回、我的、购物车和内容导航，都先询问守卫；不修改公共 Router。

开店申请页载入或成功保存后记录业务字段快照。当前字段值与快照不同时视为存在未保存修改。焦点变化、控件展开等非业务变化不产生脏状态。

存在未保存修改时，离开页面弹出三个选项：

- 保存并离开。
- 不保存并离开。
- 取消。

“保存并离开”必须等待服务端确认成功后再执行原导航；失败时留在申请页并保留全部输入。“不保存并离开”只放弃本次页面修改。“取消”关闭提示且不改变页面状态。

## 5. 开店申请

“保存草稿”和“提交审核”是两个独立的用户意图。完整填写并通过客户端校验后，可以直接提交审核，不要求用户先手工保存草稿。

直接提交流程为：

1. 校验当前表单。
2. 使用页面最新内容保存新草稿或更新现有草稿。
3. 取得服务端返回的申请 ID 和最新版本号。
4. 立即提交该版本审核。
5. 成功后刷新申请状态和表单快照。

保存失败时不进行提交。保存成功但提交失败时保留已保存草稿，并显示提交失败原因，用户无需重新填写。被驳回申请修改后使用相同流程重新提交。

保存或提交期间禁用相关按钮，防止重复请求；响应完成后根据结果恢复可操作状态。

## 6. 商品目录与搜索

### 6.1 可替换商品卡

商品卡采用固定宽度和固定基础高度，外层根据视口宽度计算列数。窗口变宽时增加每行卡片数量，变窄时减少，不出现横向滚动。

整个卡片作为一个可聚焦、可键盘触发的详情入口。移除底部重复展示商品名称和价格的按钮，并提供一致的悬停、聚焦和按压反馈。

同一个卡片组件通过展示配置适配不同场景：

| 场景 | 店铺名称 | 点击区域 |
| --- | --- | --- |
| 商城首页 | 隐藏 | 整张卡片 |
| 搜索与分类结果 | 显示 | 整张卡片 |
| 店铺商品页 | 隐藏冗余店铺名 | 整张卡片 |

### 6.2 首次布局修复

商品异步加载完成后，根据真实商品数、固定卡片尺寸和当前视口宽度重新计算行数及内容首选高度，并执行布局失效、重新布局和重绘。视口尺寸变化和翻页后走同一条布局路径。

首页初次进入、翻页返回和窗口缩放因此具有相同的高度计算结果，不再依赖用户翻页来纠正滚动范围。

### 6.3 搜索交互

搜索区采用以下固定规则：

- 搜索栏按钮名称为“搜索”。
- 分类、最低价、最高价和排序方式直接显示。
- 不提供筛选区域展开或收起按钮。
- 分类和价格变化只更新待应用条件。
- 点击“应用筛选”后统一请求并回到第一页。
- 排序方式改变后立即请求并回到第一页。

搜索词由“搜索”按钮提交；筛选条件由“应用筛选”提交，两者职责清楚且不存在同义按钮。

## 7. 购物车与确认订单

### 7.1 购物车

购物车采用固定尺寸卡片组成的响应式多列、多行网格。页面变宽时每行显示更多卡片，变窄时减少列数；卡片内部信息纵向排列，不产生横向滚动。

每张卡片依次显示：

- 商品图片、名称和 SKU 描述。
- 单价。
- 数量。
- 商品小计。
- 更新和删除操作。

图片、商品名称和 SKU 描述构成独立的详情点击区。数量控件、更新和删除按钮不冒泡为详情导航。

页面汇总区显示商品总数量和购物车总价。数量更新或删除成功后，以服务端返回的购物车视图为准同步刷新单项小计、总数量和总价。金额统一显示两位小数，并明确标注“单价”“小计”“总计”。

### 7.2 确认订单

确认订单采用只读纵向清单，而不是购物车网格。每个条目显示商品、SKU、单价、数量和小计；页面底部在提交按钮附近突出显示商品总数量和订单总价。

商品信息区域可以进入详情，但查看详情不修改结算快照。提交期间禁用重复提交；失败时保留确认页数据，成功时进入支付或订单结果页。

显示金额来自服务端购物车或结算模型，客户端只负责格式化和一致性校验，不独立生成最终支付金额。

## 8. 管理员开店审核

开店审核拆分为两个页签：

- **未处理：** 仅显示 `PENDING`，默认打开。
- **已处理：** 显示 `APPROVED` 和 `REJECTED`。

未处理列表按提交时间倒序；已处理列表按审核时间倒序。时间相同时使用申请 ID 作为稳定的次级排序键。状态分组和排序由服务端查询完成，客户端不在单页结果上过滤，保证分页完整。

未处理列表展示提交时间；已处理列表展示提交时间、审核时间、审核状态和审核意见。审核成功后刷新两侧数据，使记录立即从未处理页签移到已处理页签。

## 9. 卖家与管理员商品工作区

### 9.1 主从编辑布局

卖家商品管理采用主从布局：左侧为商品列表，右侧为所选商品的编辑区域。选择商品时在右侧加载详情；新建时右侧进入空白编辑状态。

左侧只展示经营摘要：商品名称、状态、SKU 数、最低价、总库存、预留库存和销量。技术字段不作为店主的主要操作信息。

管理员商品管理复用商品列表和编辑组件，外层增加店铺选择与管理员权限操作，避免形成两套行为不一致的编辑器。

### 9.2 SKU 编辑

主界面中的 SKU 表格是只读摘要，只显示：

- 规格名称。
- 单价。
- 库存。
- 启用状态。
- 添加或编辑入口。

添加和编辑使用紧凑表单。店主只填写规格名称、单价、库存和启用状态。SKU ID 与版本号由系统生成和维护，不显示，也不允许手工输入。

创建命令不携带用户提供的 SKU ID。更新时由页面状态在后台保留已选 SKU 的 ID 和版本号，并映射到更新命令。版本冲突时刷新商品详情并提示用户重新确认修改。

## 10. 内置预置封面

### 10.1 资源目录

五个商品分类各提供 4 个内置封面，共 20 个选择：

- 文具。
- 图书。
- 生活用品。
- 药品。
- 其他。

另提供统一默认占位图。图片使用简单图形或符号表达分类和用途，随客户端与发布包一起分发，不依赖网络。

### 10.2 稳定标识与校验

Common Shop 契约维护统一的预置封面目录，包括稳定标识、所属分类和展示名称。标识示例为 `builtin://shop/books/reading-1`。

编辑器根据当前分类展示对应的 4 个缩略图。店主点击选择，不输入 URL。切换分类后，如果原封面不属于新分类，则恢复默认占位状态并要求重新选择。

服务端验证内置标识是否存在且与商品分类匹配，非法值返回 `SHOP_COVER_IMAGE_URL_INVALID`。现有 `coverImageUrl` 文本字段继续保存该标识，因此不改变数据库结构。

历史兼容规则为：

- `null` 或空值显示默认占位图。
- 已有 HTTPS 封面仍可读取和显示。
- 新建及重新编辑时，界面只向店主提供内置图片选择。

## 11. 错误处理与状态一致性

- 异步操作期间只禁用相关操作，不冻结整个工作区。
- 请求失败后保留当前表单、购物车或确认订单状态。
- 页面离开保存失败时阻止导航，避免静默丢失数据。
- 商品加载失败、空列表和无搜索结果使用独立状态视图，不以异常空白高度表达。
- 非法封面、越权操作、版本冲突和无效状态流转转换为可理解的业务提示。
- 页面刷新以服务端返回数据为准，避免客户端预测状态与持久化结果不一致。

## 12. 测试驱动实施批次

每批严格先新增失败测试并确认失败原因正确，再做最小实现和定向验证。

### 批次零：User Manager 当前版本兼容与端口

- 以 `8d53d9e` 的公开 User 类型和统一 `MainFrame` 验证 Shop 安装器契约。
- 验证登录、首次改密、账户页、退出及会话失效只存在一条统一流程。
- 验证学生、教师、管理员和已审核店主的身份映射及服务端二次鉴权。
- 验证 Shop“我的”不重复账户、改密和退出功能。
- 验证服务端、客户端、脚本、发布包和说明默认端口均为 `8888`，显式覆盖仍有效。

### 批次一：导航与初始布局

- 工具页锚点、互换、重复点击和一次返回。
- 商品网格初次异步渲染、翻页和缩放后的高度。

### 批次二：开店申请

- 新申请直接提交和驳回后直接重提。
- 保存失败与提交失败的状态保留。
- 未保存离开的三个选择以及所有导航入口。

### 批次三：商品目录与搜索

- 首页隐藏店铺、搜索和分类结果显示店铺。
- 整卡鼠标与键盘点击、子控件事件隔离。
- 条件延迟应用、排序立即刷新和页码重置。

### 批次四：购物车与确认订单

- 响应式多列购物车及卡片内部纵向信息。
- 单价、数量、小计、商品总数量和总价。
- 商品详情入口、更新/删除隔离和重复提交保护。
- 确认订单只读纵向清单。

### 批次五：管理员审核

- 未处理与已处理状态分组。
