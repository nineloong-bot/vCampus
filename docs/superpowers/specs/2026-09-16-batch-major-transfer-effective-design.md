# 转专业批次终审并立即生效设计

## 目标

将现有“逐份终审、逐人执行、等待生效日期”的流程改为一次批次级操作。批次终审成功时，全部拟录取学生同时完成学籍变更、均衡分班、学号续编和选课清理；任一学生失败时整批回滚。

## 批次终审条件

- 批次必须为 `CLOSED`，避免终审时继续新增或修改正式申请。
- `DRAFT` 是未提交草稿，不参与终审，也不阻塞批次。
- 所有正式申请必须已经成为 `ASSESSED`、`REJECTED` 或 `CANCELLED`；`SUBMITTED`、`SOURCE_APPROVED`、`QUALIFIED`、`PENDING_EFFECTIVE`、`EXECUTION_FAILED` 均阻止终审。
- 每个选项的 `ASSESSED` 人数不得超过接收名额；超额时整批拒绝，管理员必须先处理超额申请。
- 每个目标专业和学生入学年份必须存在至少一个启用班级及已发布培养方案。
- 已终审生效的批次不可重复执行。

## 原子执行流程

新增批次命令 `FinalizeMajorTransferBatchCommand(batchId, expectedVersion)`，替代单份申请终审和个人执行入口。服务按固定顺序锁定批次、申请、学生和学号序列，并在同一个 Access 事务中执行：

1. 重新读取批次、所有正式申请、目标选项、学生学籍及目标组织数据。
2. 完成全部前置条件和乐观版本校验。
3. 按“目标专业 + 入学年份”分组，为每组查找匹配年份的启用班级。
4. 读取各班当前人数；每次选择人数最少的班级，人数相同时按班号、班级 ID 排序，使转入后的班级人数差尽量不超过 1。
5. 使用现有 `AccessStudentNumberGenerator` 按目标专业代码、入学年份、班号生成学号。序列从该班现有最大尾号之后继续，不能复用原专业学号。
6. 更新学生班级和学号，并写入 `MAJOR_TRANSFER` 学籍变更记录。
7. 通过课程模块窄端口读取新专业、同入学年份的已发布培养方案。当前学期有效选课中，课程代码不在新培养方案任一学期内的记录自动改为 `DROPPED`。
8. 每次自动退课同步减少普通教学班人数或重修名额人数，并写入 `MAJOR_TRANSFER_AUTO_DROP` 选课调整审计。
9. 将全部 `ASSESSED` 申请直接置为 `EFFECTIVE`，为每人写入终审和生效记录；为 `MajorTransferBatchStatus` 增加 `EFFECTIVE`，并将批次从 `CLOSED` 改为 `EFFECTIVE`，防止重复执行。
10. 提交事务。任一步失败时，学籍、学号序列、选课、人数、审计和申请状态全部回滚。

生效日期和公示结束日期保留为展示资料，但不再阻止批次终审执行。

## 模块边界

- 转专业服务负责批次状态机、学生分组、均衡分班、学籍和申请状态。
- 选课模块提供一个窄的 `MajorTransferEnrollmentPort`，接收当前事务连接、学生、新专业代码和入学年份，负责识别并退掉新培养方案外课程。
- 转专业服务不得直接访问选课仓储或复制培养方案查询逻辑。
- 学号继续使用现有号码序列与生成器，不增加第二套编号实现。

## 客户端

- 删除申请详情上的“终审通过”和“执行转专业”按钮。
- 在已关闭批次页面增加“批次终审并生效”按钮，并明确显示正式申请总数、拟录取数、已拒绝数、已取消数和尚未处理数。
- 尚有未处理申请、名额超限、缺少目标班级或培养方案时，按钮禁用并显示具体原因。
- 成功后刷新批次和申请列表；学生再次刷新学籍、选课、我的选课和课表时直接看到新专业及清理后的课程。

## 错误与并发

- 批次版本过期返回并发修改错误，不进行任何写入。
- 终审过程中学生班级、申请状态、目标专业、班级状态或培养方案发生变化时，整批失败。
- 锁顺序固定为批次、申请 ID、学生 ID、学号序列，避免不同批次并发产生死锁或重复学号。
- 自动退课只处理当前学期 `ACTIVE` 记录；历史选课和成绩不删除。

## 测试

- 批次存在未处理正式申请时不能终审。
- 草稿不阻塞批次终审。
- 超过接收名额时整批失败。
- 多名学生按当前班级人数均衡分配，人数相同时结果稳定。
- 新学号使用目标专业/年级/班级前缀，并从已有尾号后递增。
- 点击一次批次终审即更新所有拟录取学生，无日期限制。
- 新培养方案外课程被退选，方案内课程保留，教学班及重修人数同步。
- 任一学生缺少班级、培养方案或发生版本冲突时，整批无部分写入。
- 终审后刷新学籍、候选课程、我的选课和课表均反映新专业。
- 重复提交同一批次不会重复改学号、退课或写审计。
