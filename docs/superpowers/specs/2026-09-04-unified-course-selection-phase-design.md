# 统一选课页与手动选课阶段设计

## 1. 目标

将学生端“教学班查询”“退改补”“重修”三个入口合并为一个“选课”入口。页面根据管理员当前手动开放的阶段、学生学籍状态、历史修读结果和当前选课记录，直接展示本阶段可执行的动作。

管理员通过独立的“选课阶段”管理页面维护阶段展示标题并手动开放或关闭阶段。示例标题包括“2026-2027秋季学期选课”和“2026-2027秋季学期退改补选课”。学期管理不再通过选课时间窗决定阶段是否开放。

## 2. 范围

本次改动包括：

- 学生课程中心的导航和统一选课页面。
- 管理员独立的选课阶段管理页面。
- 服务端阶段配置、开放互斥、学生选课上下文和按学生计算的教学班动作。
- 普通选课、退选、补选、改选和重修的阶段校验切换为手动阶段校验。
- 数据库结构、演示数据、协议 DTO、客户端网关、服务端处理器和自动化测试。

本次不包括：

- 修改教师端“教学班查询”的名称或功能。
- 新增具体成绩管理；重修仍只依据 `PASSED`/`FAILED` 修读结果。
- 定时自动开放或关闭阶段。
- 同时开放多个学期或多个选课阶段。

## 3. 核心模型

新增 `tblCourseSelectionPhase`，每条记录代表一个可由管理员手动控制的选课阶段：

| 字段 | 含义 | 约束 |
| --- | --- | --- |
| `phaseId` | 阶段主键 | UUID，非空 |
| `termId` | 所属学期 | 外键，非空 |
| `phaseType` | 阶段类型 | `ENROLLMENT` 或 `ADJUSTMENT` |
| `displayTitle` | 学生端主标题 | 非空，最多 64 字符 |
| `phaseStatus` | 开放状态 | `DRAFT`、`OPEN` 或 `CLOSED` |
| `rowVersion` | 乐观锁版本 | 非负整数 |
| `createdAt` | 创建时间 | 非空 |
| `updatedAt` | 修改时间 | 非空 |

阶段状态语义如下：

- `DRAFT`：已配置但从未开放。
- `OPEN`：当前权威选课阶段。
- `CLOSED`：管理员已关闭，可保留为历史记录。

服务端在事务中保证全系统最多存在一条 `OPEN` 记录。开放阶段前还必须校验所属学期为 `ACTIVE`；学期变为 `CLOSED` 后，即使存在异常遗留的 `OPEN` 记录，所有选课写操作也必须拒绝。

一个学期允许按先后顺序创建多条同类型阶段记录，以保留不同批次的标题和开放历史。已关闭阶段不可重新编辑或重新开放；需要再次开放时创建新阶段，避免覆盖历史语义。

## 4. 学期模型调整

`tblTerm` 和学期 DTO 不再包含：

- `enrollmentStartAt`
- `enrollmentEndAt`
- `adjustmentStartAt`
- `adjustmentEndAt`

学期管理只维护学期代码、名称、起止日期和 `PLANNED`/`ACTIVE`/`CLOSED` 状态。新建或编辑学期不再展示选课及退改补时间字段。

数据库迁移采用重建演示数据库的项目既有方式，不承诺读取旧版 Access 数据库。打包脚本和演示启动数据必须同步更新。

## 5. 服务端接口

新增协议对象：

- `CreateSelectionPhaseCommand(termId, phaseType, displayTitle)`：创建 `DRAFT` 阶段。
- `UpdateSelectionPhaseCommand(phaseId, displayTitle, expectedVersion)`：只允许编辑 `DRAFT` 阶段的标题。
- `ChangeSelectionPhaseStatusCommand(phaseId, targetStatus, expectedVersion)`：只允许 `DRAFT -> OPEN` 或 `OPEN -> CLOSED`。
- `SelectionPhaseView`：返回阶段完整信息。
- `StudentSelectionContextView`：返回当前阶段、学期状态、服务器时间、学生学籍是否允许选课及不可操作原因。
- `StudentOfferingView`：包装教学班摘要，并返回当前学生对该教学班的 `actionType` 和 `actionReason`。

新增消息类型：

| 消息类型 | 权限 | 作用 |
| --- | --- | --- |
| `COURSE_SELECTION_PHASE_LIST` | 管理员 | 查询阶段记录 |
| `COURSE_SELECTION_PHASE_CREATE` | 管理员 | 创建草稿阶段 |
| `COURSE_SELECTION_PHASE_UPDATE` | 管理员 | 修改草稿标题 |
| `COURSE_SELECTION_PHASE_CHANGE_STATUS` | 管理员 | 开放或关闭阶段 |
| `COURSE_STUDENT_SELECTION_CONTEXT` | 学生 | 获取统一选课页上下文 |
| `COURSE_STUDENT_OFFERING_SEARCH` | 学生 | 获取按学生计算动作的教学班分页结果 |

教师和管理员既有教学班查询接口保持不变。既有选课写接口名称保持不变，以减少客户端和服务端变更面，但其开放校验改为读取当前 `OPEN` 阶段。

## 6. 动作计算规则

服务端为每个教学班返回下列动作之一：

- `ENROLL`：正常选课阶段，学生学籍正常、该课程无历史 `FAILED` 记录且尚未选择该课程。
- `RETAKE`：正常选课阶段，学生学籍正常、该课程至少存在一条历史 `FAILED` 记录且尚未选择该课程。
- `LATE_ADD`：退改补阶段，学生学籍正常且尚未选择该课程。
- `CHANGE_TARGET`：退改补阶段，学生已选同一课程的其他教学班，可将该班作为改选目标。
- `SELECTED`：当前已有该教学班的有效选课记录。
- `UNAVAILABLE`：没有开放阶段、学期未激活、学籍不允许选课、课程已通过、容量已满或存在其他确定性阻止条件。

`actionReason` 使用面向学生的中文原因，例如“当前未开放选课阶段”“学籍状态不允许选课”“该课程已通过，无需重修”“教学班容量已满”。时间冲突仍在提交前由服务端权威校验；若列表上下文已加载课表，可以提前返回冲突原因，但提交校验不得省略。

退选动作属于当前选课记录，而不是教学班搜索结果：

- 正常选课和退改补阶段均允许退选，与既有行为一致。
- 退改补阶段可以同时选择一条当前记录和一个 `CHANGE_TARGET` 教学班后执行原子改选。
- 阶段关闭、学期关闭或学籍不允许选课时，退选、补选和改选全部禁用。

## 7. 学生端交互

学生课程中心顶部只显示：

1. `选课`
2. `我的选课`
3. `我的课表`

统一选课页复用既有课程关键词、上课日期、分页和教学班表格。页面主标题使用当前开放阶段的 `displayTitle`，并使用比现有 `PAGE_TITLE` 大一级的统一标题字号。无开放阶段时，主标题回退为“选课”，页面保留只读查询能力并显示“当前未开放选课阶段”。

正常选课阶段：

- 表格操作按钮根据选中行显示“选择教学班”或“重修选课”。
- `RETAKE` 直接提交重修请求，不再要求跳转到独立页面再次检查。
- `UNAVAILABLE` 行可查看但不能提交，状态列显示具体原因。

退改补阶段：

- 页面在筛选区下方同时展示“当前选课”和“可选教学班”。
- 选择当前记录可退选；选择目标教学班可补选；同时选择原记录和目标班可改选。
- 改选继续使用既有确认对话框，展示原班、目标班、时间、余量和冲突结果。

请求进行中时禁用相关按钮；请求失败时保留已加载内容并显示可恢复错误。操作成功后刷新统一选课页，并把“我的选课”和“我的课表”标记为需要刷新。

## 8. 管理员端交互

管理员课程中心增加“选课阶段”标签，放在“学期管理”之后。页面包括：

- 阶段列表：学期、类型、展示标题、状态、版本和更新时间。
- “新建阶段”：选择学期、选择阶段类型、填写展示标题。
- “编辑标题”：仅草稿可编辑。
- “开放阶段”：仅草稿可开放；若已有开放阶段，服务端拒绝并提示先关闭当前阶段。
- “关闭阶段”：仅当前开放阶段可关闭，关闭前显示确认对话框。
- “刷新”：重新读取服务端权威状态。

“学期管理”表格移除正常选课窗口和退改补窗口列，编辑器移除四个时间输入框，并将说明改为只维护学期基础信息与状态。

## 9. 一致性、并发与错误

- 阶段创建、编辑、开放和关闭均要求管理员权限。
- 开放和关闭使用 `rowVersion` 乐观锁。
- 开放阶段在事务中锁定阶段控制资源并再次查询是否存在其他 `OPEN` 阶段，避免并发开放两条记录。
- 学生写操作在既有学生、教学班锁之外读取并校验当前阶段；阶段类型不匹配时分别返回 `COURSE_ENROLLMENT_NOT_OPEN` 或 `COURSE_ADJUSTMENT_NOT_OPEN`。
- 重修只在 `ENROLLMENT` 阶段开放；存在 `FAILED` 且不存在使本次重修失去意义的已通过结果时才返回 `RETAKE`。
- 客户端返回的动作只用于展示，服务端写接口必须重新执行学籍、阶段、容量、重复、历史结果和冲突校验。
- 未知阶段类型或状态视为数据错误，不默认放行。

## 10. 兼容与清理

- 删除学生导航中的“退改补”和“重修”标签。
- `AdjustmentPanel` 和 `RetakePanel` 的可复用交互逻辑迁入统一选课页或拆成该页面的内部组件；不再作为独立导航页实例化。
- `TermWindowPolicy` 替换为基于当前开放记录的 `SelectionPhasePolicy`。
- `TermPhaseView` 和 `COURSE_GET_TERM_PHASE` 在所有调用迁移完成后删除。
- 教师端 `OfferingSearchPanel` 或其等价查询视图继续显示“教学班查询”，不读取学生阶段上下文。

## 11. 测试与验收

### 服务端

- 创建、编辑、开放、关闭状态转换和乐观锁测试。
- 两个管理员并发开放阶段时最多一个成功。
- 非活动学期不能开放阶段。
- 各写操作在正确阶段成功，在错误阶段或无开放阶段失败。
- 正常、学籍异常、历史未通过、历史已通过、已选同课程、已选同教学班和容量已满等动作计算测试。
- 重修、补选和改选提交时重新校验，不能依赖客户端动作。

### 客户端

- 学生标签精确为“选课”“我的选课”“我的课表”；教师标签保持不变。
- 主标题显示管理员配置值，无开放阶段时回退为“选课”。
- 正常阶段按动作显示普通选课、重修或不可操作。
- 退改补阶段在同页完成退选、补选和改选。
- 学籍异常和无开放阶段禁用所有写操作并显示原因。
- 管理员阶段页面覆盖创建、编辑、开放冲突、关闭和异步失败状态。
- 学期编辑器不再包含选课时间窗字段。

### 集成与视觉验收

- 通过真实 socket 验证管理员开放阶段后，学生刷新即可看到新标题和对应动作。
- 生成学生正常选课、退改补、无开放阶段以及管理员阶段管理的截图。
- 在标准窗口、`1024x680` 和 150% 缩放下确认标题、双表布局、按钮和分页不截断。

## 12. 完成标准

- 学生不再看到独立“退改补”和“重修”页面。
- 学生统一从“选课”页完成当前开放阶段允许的全部选课动作。
- 页面主标题由管理员配置并随开放阶段切换。
- 管理员无需修改学期时间窗即可手动开放或关闭阶段。
- 服务端强制阶段互斥和所有业务规则，客户端不能绕过。
- 全量 Maven 测试通过，演示数据库和分发包可从干净状态启动。
