# 选课与用户登录模块集成设计

## 1. 目标与范围

本次集成在 `course` 的完整选课实现上合并 `origin/feat/user-management`，保留两个分支的提交历史。客户端必须先登录，登录成功后进入现有选课界面；服务端必须使用登录会话识别用户，并按学生、教师、管理员角色限制选课命令和页面。

本次不合并学籍模块，也不新增选课或用户领域功能。用户模块原有的教师申请、账户管理、首次登录强制改密和会话撤销行为保持不变；选课模块原有的课程、学期、教学班、选课、退改补、重修与审计规则保持不变。

## 2. 合并策略

从 `course` 创建 `codex/course-user-integration`，使用非快进合并引入 `origin/feat/user-management`。冲突解决遵循以下原则：

- 保留 `course` 新增的选课源代码、测试、文档、主题样式和分发文件；
- 保留用户分支新增的用户协议、用户服务、认证会话、登录界面、数据库 schema 与测试；
- 对两个分支共同修改的启动入口、主窗口和 Maven 配置进行人工整合，不整文件选择任一方；
- 删除与本集成无关的临时办公文档和编辑器锁文件，不把它们带入合并结果。

最终合并提交包含两个父提交，使后续 Git 合并能够识别两个模块已经集成。

## 3. 服务端组合

`ServerMain` 只创建一套应用级基础设施：

- 一个 `MessageRouter`；
- 一个指向同一 Access 数据库的 `ConnectionProvider`；
- 一个应用级 `ResourceLockManager`；
- 一个用户模块 `SessionRegistry`；
- 一套用户服务和授权服务；
- 一套选课 `CourseComposition`。

用户命令和选课命令注册到同一个路由。选课授权通过 `CourseRuntimeAdapters.authorization` 连接用户模块的 `AuthorizationPort`、`UserIdentity` 和 `UserQueryPort`：

- 无有效会话的请求被拒绝；
- `restricted=true` 的首次登录受限会话不能调用任何选课命令；
- 学生写操作要求 `STUDENT`；
- 教师身份与教学班指派通过活动账户和 `TEACHER` 角色校验；
- 管理命令要求 `ADMIN`。

JDBC URL 不启用 `immediatelyReleaseResources=true`，避免 UCanAccess 并发关闭连接时的驱动级死锁风险。用户和选课服务共享连接提供器，但各自保持清晰的仓储边界。

## 4. 临时学生资格适配

由于本次不包含学籍模块，正式的 `StudentQueryPort` 暂时不可用。经确认，本集成采用以下临时规则：

- 仅 `UserQueryPort.findActiveUser(userId)` 能查到且角色为 `STUDENT` 的账户视为具备选课资格；
- `StudentEnrollmentEligibility.studentId` 暂时等于用户模块的 `userId`；
- 临时学籍状态固定映射为 `ACTIVE`；
- 导入修读结果时的活动学生校验同样以活动 `STUDENT` 账户为准；
- 待学籍模块合并后，只替换 `CourseStudentGateway` 的组合代码，改为正式的 `StudentQueryPort.getEnrollmentEligibility` 和 `existsActiveStudent`，不得让选课领域直接访问学籍或用户仓储。

这是一项明确的过渡兼容措施，不代表 `userId` 与正式 `studentId` 在长期数据模型中等价。部署到已有真实选课数据前，必须先完成正式学生标识迁移或确认两者映射。

## 5. 客户端流程与角色页面

`ClientMain` 建立一个 `ClientConnection`，并让用户服务和选课服务共享该连接。流程如下：

1. 连接服务器后显示 `LoginFrame`；
2. 登录失败继续停留在登录窗口，并保持密码清理和非 EDT 网络调用行为；
3. `mustChangePassword=true` 时只进入首次改密流程，不创建业务主窗口；
4. 普通登录成功后关闭登录窗口，创建携带 `UserView` 与 `sessionToken` 的应用组合；
5. `CourseClientService` 的每个选课请求携带该会话令牌；
6. 主窗口按角色安装已有选课页面。

页面范围：

- `STUDENT`：教学班查询、我的选课、我的课表、退改补、重修；
- `TEACHER`：只暴露当前服务端确实支持且有权限的教师查询入口，不把管理员写操作显示给教师；
- `ADMIN`：学期管理、课程目录、教学班管理、修读结果导入、退改补审计；
- 公共只读页面只有在服务端合同允许对应角色访问时才显示。

客户端隐藏页面用于减少误操作，但服务端授权仍是安全边界。手工构造请求不得绕过角色限制。

## 6. 数据库与启动

合并结果同时保留 `vcampus-database/schema/010_user.sql` 与 `030_course.sql`，并保留用户权限种子数据。集成启动必须保证用户表先于需要用户身份的业务数据可用，选课 schema 初始化保持幂等。

如果现有分发数据库缺少可登录账户，应使用用户模块既有的受控建号或测试夹具初始化，不在客户端写死账号、密码或绕过密码哈希。

## 7. 错误处理与会话生命周期

- 登录、会话过期、首次改密限制和账户状态错误沿用用户模块错误码；
- 选课业务错误沿用选课模块错误码；
- 会话过期或账户被禁用后，后续选课请求必须失败，客户端应返回登录入口而不是继续使用缓存角色；
- 登录窗口关闭但未进入主界面时关闭共享连接；主窗口退出时关闭连接；
- 不在日志、DTO 或 UI 中暴露密码、哈希、盐或完整会话令牌。

## 8. 测试与验收

实现采用测试驱动，至少覆盖：

- 合并后的公共、服务端和客户端既有测试全部通过；
- 登录成功后创建角色对应的选课导航，未登录时不显示业务主窗口；
- 学生会话能进入学生页面并调用学生命令；
- 教师和管理员页面集合符合设计，越权命令在服务端被拒绝；
- 首次登录受限会话不能访问选课；
- 会话过期、登出或账户禁用后不能继续访问选课；
- 临时学生适配只接受活动 `STUDENT`，并验证 `studentId=userId`；
- 用户命令与选课命令通过同一真实 socket、路由和数据库完成端到端请求；
- 使用 JDK 21 运行完整 Maven 测试，涉及 socket 和 Swing 的测试需要允许本机临时端口与图形会话。

验收标准是：用户从统一客户端完成登录后直接进入与其角色相符的现有选课界面，所有选课操作由同一登录会话鉴权，且两个模块的既有功能和测试不回退。
