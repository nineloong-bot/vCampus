# 商城剩余模块与Swing整体验收实施计划

**Goal:** 完成订单/库存、商品/Excel、审核管理，接入已确认Demo对应的Swing页面并验收。
**Architecture:** 复用tblShop/tblProduct/tblProductSku/tblOrder等现有记录，新增明确归属的扩展表；新版Socket API替换生产入口，旧测试兼容接口不得绕过新版资金/权限规则。
**Tech Stack:** JDK21、Swing、Socket、Access/UCanAccess。
**Spec:** ../specs/2026-09-13-shop-admin-demo-requirements.md

## 执行边界和决策

- 保留现有未提交工作，使用feat/independent-wallet分支；禁止覆盖正在运行的Access库。
- 新Java文件<=200行，先失败测试；资金/库存与订单同事务，身份取服务端。
- 昵称：提供店铺订单所需的独立公开昵称；无昵称显示“校园用户”，不回退真实姓名、学号或电话。
- 类目采用课程模拟清单，与Demo对应；单个类目对应一种专项资质，不推断子类目继承。
- 资质过期商品在未付款订单中按当前不可购买状态懒校验；恢复前已标失效的订单行不会复活。
- 未首次校验前已重新上架的商品按当前状态允许付款；保留原订单价格。
- 库存编辑采用总库存，不能小于已预占；SKU使用稳定ID，已引用SKU只能停用，不能物理删除。
- 导入每批最多1000行，预览仅内存/客户端行数据，确认时服务端重验；确认幂等键与批次内容绑定。
- 店铺设置先允许修改介绍，主体与店名沿用审核资料；不隐式允许转让或修改主体。
- 技术决策可以迭代，以上不是额外法律规则。

## 任务与验收

1. 订单：30分钟预占、余额支付、多店原子付款、懒校验、退款、发货、确认收货、主动超时任务、库存流水。AC-04~09。
2. 商品：草稿、默认SKU、图片编号、发布限制、同名导入、软删除、结构化Excel预览确认。AC-01~03/10。
3. 管理：文字开店申请、资质、举报、警告、停业与复业、商品紧急限制与复核、审计。AC-11~14。
4. 页面：原型色彩和结构、买家导航/商品列表/搜索/多选/固定分页/购物车、我的/钱包/订单、店主、管理员两列表工作区。
5. 验收：真实Socket/Access集成、并发与恢复、完整Maven测试、JavaDoc、UI结构与截图检查、生成1000条测试数据、打包与临时库验证。

各模块拥有独立源目录和SQL资源；公共bootstrap和旧生产入口统一由主执行者接入。跨任务接口在实现前交换，禁止并行覆盖同一文件。
