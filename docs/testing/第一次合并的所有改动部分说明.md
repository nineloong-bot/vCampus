# vCampus 统一版本改动说明

## 1. 合并范围与来源

本次工作以用户管理模块为基础，将四个业务模块合并到同一套工程：

- 课程模块：合入 `course-user-management` 分支，合并提交 `64384c5`。
- 学籍模块：合入 `nineloong` 分支，合并提交 `59937b7`。
- 图书馆模块：合入 `user-library` 分支，合并提交 `8470c3f`。
- 商城模块：合入 `SHOP` 分支，合并提交 `ccca4d2`。

上述合并保留各组员模块已有实现。本说明重点区分“合入的模块功能”和“为统一程序新增的对接改动”。

## 2. 服务端统一运行时

- 将登录、学籍、课程、图书馆和商城命令注册到同一个 `MessageRouter`。
- 所有模块共用同一个端口（默认 `8888`）、数据库连接、事务管理器、会话注册表、资源锁和请求去重器。
- 生产服务端入口统一为 `edu.seu.vcampus.server.bootstrap.ServerMain`。
- 新增 `UnifiedModuleRegistry`，集中装配学籍、图书馆和商城服务，避免各模块单独启动演示服务。
- 保留 `PING`、安全审计和用户管理命令，并让业务模块使用同一登录会话。
- 课程模块原先临时使用 `userId` 作为 `studentId`；统一后改为通过学籍模块的 `StudentQueryPort` 查询真实学籍记录、学籍状态和 `studentId`，解决选课写入与学籍外键不一致的问题。

对应提交：`0979785`、`d6e3651`。

## 3. 客户端统一主界面

- `ClientMain` 只建立一条共享连接，并基于该连接创建用户、学籍、课程、图书馆和商城客户端服务。
- 登录成功后只打开一个 `MainFrame`，不再分别启动各模块演示窗口。
- 将真实的学籍、课程、图书馆和商城页面安装到统一导航；删除这些位置的占位页面用途。
- 页面内容按照登录角色和权限显示：学生、教师、管理员、店主看到各自可用的功能。
- 会话过期或认证失败时统一清除会话并返回登录界面。
- 客户端首次连接失败时仍可进入登录页查看连接状态，避免程序直接退出而无法诊断。

对应提交：`88dca5a`。

## 4. 用户、登录与权限对接

- 保留用户管理分支提供的登录、首次改密、退出、账户管理、会话替换和安全审计流程。
- 综合管理员继续使用 `ADMIN` 角色，同时补充 `USER_PASSWORD_RESET`、`STUDENT_WRITE`、`LIBRARY_ADMIN` 等权限，使同一管理员能管理用户、学籍、课程、图书馆和商城。
- 课程、图书馆和商城不再维护独立登录状态，全部读取统一会话与权限。
- 禁用不完整的在线角色变更契约，避免角色修改后各模块会话权限不一致；相关测试明确验证请求被拒绝且管理员会话不被误撤销。

## 5. 学籍模块

- 合入最新学籍详情、学生搜索、组织架构、入学、学籍异动、个人信息修改和管理员编辑能力。
- 增加管理员学生信息编辑弹窗和学籍详情展示调整。
- 为课程模块开放既有的学籍查询接口，用真实学籍状态判断能否选课。
- 修正组织架构 Swing 测试替身：按请求命令和父级 ID 返回院系、专业、班级，消除异步请求顺序导致的偶发错配。

## 6. 课程模块

- 合入学期、课程目录、教学班、选课、退课、退改补、重修、课表、结果导入和审计页面及服务端逻辑。
- 使用统一用户会话区分学生、教师和管理员课程工作区。
- 教师 ID 使用统一用户记录；学生选课使用学籍模块返回的真实学生 ID。
- 保留容量、时间冲突、重复选课、开放时间、并发修改等规则与中文错误反馈。

## 7. 图书馆模块

- 合入图书检索、详情、借阅、归还、续借、在借记录、书目管理、副本管理、借阅管理和策略管理。
- 将图书馆授权适配到统一 `AuthorizationService`。
- 管理员通过统一权限集合获得图书馆管理能力；学生和教师保留普通借阅能力。
- 图书馆事务和并发锁与其他模块共享基础设施。

## 8. 商城模块

- 合入最新 `SHOP` 版本，包括买家、店主和管理员完整流程。
- 购物车增加删除商品、部分勾选结算，并设置为默认全部不勾选。
- 开店申请改为弹窗填写，支持保存草稿、直接提交和关闭时询问是否保存；店主和管理员页面增加刷新能力。
- 管理员可单击申请行后在主界面审核，双击打开只读详情并审核。
- 商品管理分为“上架商品”和“下架商品”两列；草稿放在下架列并禁止直接上架。
- 商品编辑支持增加商品种类，例如在黑色中性笔下增加红色种类。
- 面向用户的“SKU”改为“商品种类”，内部数据库和网络字段保持兼容。
- “更新所选商品”改为“修改商品信息”，“店铺”入口改为“进入店铺”。
- 增加申请字段字数提示、剩余字数显示、可调整大小的商品弹窗，以及中文错误码映射。

## 9. 统一数据库与测试数据

- 初始化顺序覆盖公共、用户、学籍、课程、图书馆和商城六套结构脚本。
- 新增统一演示数据脚本 `060_unified_demo_data.sql`，使一个数据库可测试全部模块。
- 准备以下账号，初始密码统一为 `admin123`：
  - `ADMIN`：综合管理员，首次登录需要修改密码。
  - `TEACHER01`：教师课程与图书馆场景。
  - `213230001`：学生学籍、选课、借阅和商城买家场景。
  - `SHOPOWNER`：已开店店主，包含上架、下架、草稿和多商品种类数据。
  - `SHOPDRAFT`：开店申请草稿。
  - `SHOPPENDING`：待管理员审核的开店申请。
- 数据覆盖正常选课、满员教学班、时间冲突、图书在借/逾期、购物车部分结算、不同订单状态及开店审核。
- 生成统一 `vCampus.accdb`；合并前数据库另行保留，不放入交付包。

对应提交：`dede14b`、`d6e3651`。

## 10. 发行包与启动方式

- 服务端和客户端分别打成可执行 JAR，并放入 `lib`。
- 统一配置使用 `data/vCampus.accdb`，默认端口保持 `8888`。
- 提供 Windows 和 Linux 的服务端、客户端启动脚本及数据重置脚本。
- 数据重置只作用于交付包内的统一数据库，下次启动会重新初始化测试数据。
- 交付包排除运行日志、历史演示脚本、旧模块 JAR、合并前数据库和开发过程草稿。
- 包内同时提供 `README.md`、`人工测试指南.md` 和本改动说明。
