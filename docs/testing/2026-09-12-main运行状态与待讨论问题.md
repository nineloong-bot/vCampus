# main 运行状态、测试账号与待讨论问题

更新时间：2026-09-12。本文记录本次合并后随 `main` 提供的本地发行版现状，供组内讨论。

## 结论

`vcampus-distribution` 已随附可直接运行的服务端 JAR、客户端 JAR 和完整 Microsoft
Access 数据库 `data/vCampus.accdb`。当前阶段继续由每位组员在本机启动服务端和客户端更
合适；暂不把开发中的服务端常驻部署到 `je1ght-server`，也不连接 `100.92.179.74:18888`
所指向的数据库服务。Access 是文件数据库，把服务端和数据库放到一台机器上虽可形成统一
数据，但会让正在频繁修改协议、schema 和 seed 的组员共享同一份可变状态，调试、迁移和
故障恢复成本都会明显增加。

建议等接口冻结、数据库迁移方式稳定、权限和备份方案确定、组内进入联调/验收阶段后，再
讨论把“唯一服务端 + 唯一 Access 文件”部署到服务器。届时客户端只连接远程服务端，不应
通过网络共享目录直接打开同一个 `.accdb` 文件。

## 直接启动

要求安装 JDK 21。以下命令均从仓库根目录执行，并分别占用两个终端。

macOS / Linux 服务端：

```sh
vcampus-distribution/scripts/start-server-with-data.sh
```

macOS / Linux 客户端：

```sh
vcampus-distribution/scripts/start-client.sh
```

Windows 服务端、客户端依次双击或在终端执行：

```bat
vcampus-distribution\scripts\start-server-with-data.bat
vcampus-distribution\scripts\start-client.bat
```

默认只监听 `127.0.0.1:8888`。若脚本不便使用，也可先进入
`vcampus-distribution`，分别执行：

```sh
java -Dlogback.configurationFile=config/logback.xml -jar lib/vCampusServer.jar config/server-with-data.properties
java -Dlogback.configurationFile=config/logback.xml -jar lib/vCampusClient.jar config/client.properties
```

恢复初始数据前必须先停止服务端，再运行 `scripts/reset-data.sh`（Windows 使用
`reset-data.bat`）。该操作会删除当前运行产生的数据；不要在仍需保留测试结果时执行。

## 仍需讨论或治理的问题

1. 全仓库现有 946 个 Java 文件中，生产代码仍有 67 个、测试代码仍有 63 个超过 200 行；
   最大生产文件 968 行，最大测试文件 2834 行。因此当前版本“可运行”，但不能宣称已经完全
   符合最初的 200 行要求。根目录 `AGENTS.md` 已把新文件和后续修改的拆分要求固化下来，
   历史文件建议按模块分批偿还，避免在本次数据合并中做高风险大重构。
2. 聚合 JavaDoc 检查曾发现 `DatabaseInitializer` 注释存在 malformed HTML；公共 API 文档
   也仍有缺口。建议单列文档治理任务，不与功能合并混在一个提交中。
3. 是否部署到服务器应在接口冻结后再决定，并同时明确：服务端进程托管、端口/防火墙、
   Access 文件备份、单写入实例、日志轮转、数据库升级脚本和回滚流程。
4. 仓库中的账号密码仅用于课程演示。若部署到可被他人访问的服务器，必须更换管理员密码，
   限制监听地址与访问范围，不能沿用 `Test12345`。
