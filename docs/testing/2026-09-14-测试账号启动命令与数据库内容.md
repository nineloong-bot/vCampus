# vCampus 测试账号、启动命令与数据库内容

本文以 2026-09-14 重建的数据集和发行数据库
`vcampus-distribution/data/vCampus.accdb` 的实际读取结果为准。

## 运行环境

- JDK：21 或更高版本
- 数据库：Microsoft Access，通过 UCanAccess 访问
- 服务端地址：`127.0.0.1:8888`
- 数据库 SHA-256：`1c65fa9d83a358f7f78e1a0421f95d4ec39d8008ee130e40ccaceb852cae6f44`

当前发行版使用仓库内的本地 Access 文件，不连接远程数据库。服务端和客户端必须分别占用
一个终端，先启动服务端，再启动客户端。

## macOS / Linux 启动命令

终端一，启动服务端：

```sh
cd /Users/je1ghtxyun/code/java-summer-course
./vcampus-distribution/scripts/start-server-with-data.sh
```

保持终端一运行。看到服务端监听 `8888` 端口后，打开终端二并启动客户端：

```sh
cd /Users/je1ghtxyun/code/java-summer-course
./vcampus-distribution/scripts/start-client.sh
```

也可以直接进入发行目录运行 JAR：

```sh
cd /Users/je1ghtxyun/code/java-summer-course/vcampus-distribution
java -Dlogback.configurationFile=config/logback.xml -jar lib/vCampusServer.jar config/server-with-data.properties
```

另开终端：

```sh
cd /Users/je1ghtxyun/code/java-summer-course/vcampus-distribution
java -Dlogback.configurationFile=config/logback.xml -jar lib/vCampusClient.jar config/client.properties
```

测试结束时先关闭客户端，再在服务端终端按 `Ctrl+C`。需要恢复仓库附带的初始数据库时，
必须先停止服务端，然后执行：

```sh
cd /Users/je1ghtxyun/code/java-summer-course
./vcampus-distribution/scripts/reset-data.sh
```

重置会覆盖测试期间产生的数据，执行前应确认不需要保留测试结果。

## Windows 启动方式

从仓库根目录依次执行，或直接双击对应脚本：

```bat
cd /d C:\path\to\java-summer-course
vcampus-distribution\scripts\start-server-with-data.bat
```

另开一个终端：

```bat
cd /d C:\path\to\java-summer-course
vcampus-distribution\scripts\start-client.bat
```

## 验证结论与注意事项

- 当前数据库的 8702 项数量、关联、培养方案、普通/重修独立容量、用户可见名称、库存、金额和密码检查通过。
- 1173 个账号均已用 `Test12345` 核对密码散列，账号状态全部为 `ACTIVE`。
- 选课候选课程来自学籍模块的 `tblTrainingPlan*` 规范表，并按专业、入学年级、学年和
  `SUMMER/AUTUMN/SPRING` 学期位置计算。
- 批量教学班的重修容量统一为 5，重修人数不计入普通容量；课程管理员可在“教学班管理”
  中选中教学班并按学号添加符合重修资格的学生，人工例外会留下选退记录审计。
- 课程、教学班、教室、院系、专业、教师、图书、店铺和商品等用户可见数据已移除“测试”字样。
- 客户端配置指向 `127.0.0.1:8888`。如果提示连接失败，首先确认服务端终端仍在运行，
  其次检查 8888 端口是否被其他进程占用。
- `tblStudentChange`、`tblStudentGrade` 等空表并非缺失，适合在功能测试中创建新记录。
