## UNIFIED-TEST-001：双击服务端 BAT 文件无法启动

**影响范围：** 使用发行包启动统一版本服务端的测试人员。\
**涉及文件：** `vcampus-distribution\scripts\start-server-with-data.bat`\
**严重程度：** 高。

**操作步骤：**

1. 打开 `vcampus-distribution\scripts` 目录。
2. 双击 `start-server-with-data.bat`。
3. 观察服务端启动结果。

**预期结果：**

- 双击 BAT 文件后，服务端正常启动。
- 服务端成功监听 `8888` 端口。
- 启动失败时，窗口保留可读的错误信息，便于测试人员定位问题。

**实际结果：**

- 双击 BAT 文件无法成功启动服务端。
- 当前只能通过命令行启动服务端。

**临时绕过方式：** 在命令行中执行服务端启动命令。

**当前状态：** 已记录。具体错误信息、失败阶段和根因尚未确认；本次仅记录测试现象，不修改启动脚本。

## UNIFIED-TEST-002：商城 UI 与其他功能的视觉风格差异过大

**影响范围：** 统一客户端的商城页面、应用外壳、公共组件及跨模块视觉一致性。\
**严重程度：** 高。

**现象：**

- 商城页面的整体视觉效果未达到验收要求。
- 商城与学籍、课程、图书馆、用户管理等功能的界面风格差异明显。
- 当前统一版本缺少经过确认的全软件视觉方向，不能直接进入商城局部整改。

**期望结果：**

- 下一步制定 UI 修改计划时，先提供覆盖整个软件的 UI Demo，而不是只展示商城局部页面。
- Demo 应覆盖登录与首次改密、统一应用外壳、学籍、课程、图书馆、商城、用户与账户管理，以及公共表格、表单、弹窗、加载、空结果、错误和断线状态。
- 提供可比较的候选视觉方案，清楚展示各方案在相同页面和业务场景下的差异。
- 商城必须与其他功能共享统一的颜色、字体、间距、按钮、表格、卡片、导航和反馈语言，同时保留必要的业务识别度。

**后续工作审批门：**

1. 先梳理全软件页面清单和公共组件。
2. 制作覆盖整个软件的候选 UI Demo。
3. 由用户查看并选择视觉方案。
4. 用户明确确认后，再制定最终修改计划并开始更改界面代码。

在用户完成方案选择以前，不修改现有 UI 实现，也不以商城局部样式调整代替全软件视觉评审。

**当前状态：** 已记录，等待全软件 UI Demo 阶段。

## UNIFIED-TEST-003：开店申请获批后刷新页面未切换至卖家状态

**影响范围：** 开店申请人、管理员审核及申请人获批后的卖家身份切换。\
**关联历史问题：** [`SHOP-TEST-019`](../superpowers/specs/2026-09-01-vcampus-shop-manual-test-findings.md) 曾要求申请人与管理员页面具备主动刷新能力。\
**严重程度：** 高。

**测试参与者：**

- 客户端 01：开店申请用户。
- 客户端 02：管理员。

**复现步骤：**

1. 客户端 01 进入“开店申请”，填写完整申请内容并提交申请。
2. 客户端 01 保持在当前申请页面，并持续点击“刷新”。
3. 客户端 02 进入“店铺审核”，选择该申请并通过审核。
4. 客户端 01 继续点击“刷新”。
5. 观察申请页面是否响应审批状态和用户卖家能力变化。
6. 客户端 01 点击返回键离开申请页面，观察商城入口。

**预期结果：**

- 管理员通过申请后，客户端 01 点击“刷新”应获取最新申请状态和卖家能力。
- 当前申请页面应明确显示审核通过，并结束不再适用的开店申请流程。
- 客户端应自动切换到与新状态匹配的页面，或提供明确的“进入卖家工作区”操作，不应继续停留在已经失效的申请页面。
- 页面内容、商城入口和当前用户能力应保持一致。

**实际结果：**

- 管理员已经通过开店申请后，客户端 01 多次点击“刷新”，当前页面仍未退出或切换。
- 客户端 01 只能点击返回键离开申请页面。
- 返回后，原来的“开店申请”按钮已经变为“进入卖家工作区”，说明服务端审批结果和商城入口状态已经更新，但当前申请页面没有同步完成状态迁移。

**临时绕过方式：** 点击返回键离开申请页面，再通过“进入卖家工作区”进入卖家功能。

**初步定位边界：** 当前证据只确认页面状态迁移缺失；尚未确认问题位于申请刷新回调、用户能力刷新、页面路由协调或其组合逻辑。本次只记录测试现象，不修改实现。

**当前状态：** 已记录，待定位与整改。
