从登录线路理解 vCampus

Java 多模块桌面 C/S：Swing 客户端、Socket 协议、服务端分层和 Access 数据库。

总览

  • vcampus-client：Swing 桌面客户端
  • vcampus-common：共享协议、命令和 DTO
  • vcampus-server：Socket 服务、业务、鉴权和持久化
  • vcampus-database：Access 数据库结构和种子数据

登录-1 客户端启动

入口是 ClientMain.main()。它读取 config/client.properties，取得服务器地址、端口和超时时间，创建共享连接与各客户端服务，最后在 Swing EDT 中安装主题并启动认证协调器。

ClientConnection connection = new ClientConnection(host, port);
connection.connect(timeout);
UserClientService users = new UserClientService(
        connection, UUID.randomUUID().toString(), timeout);
SwingUtilities.invokeLater(() ->
        new UserUiCoordinator(users, connection, library).start());

现在的代码已调整为：服务器暂时连接失败也会进入登录页，连接状态显示失败；配置文件本身无效仍属于启动错误。

登录-2 展示登录窗口

UserUiCoordinator 负责认证窗口之间的流转。启动时显示 LoginFrame；成功后根据 mustChangePassword 分流。

mustChangePassword = true
  → InitialPasswordChangeDialog
  → 修改成功后返回登录页重新登录

mustChangePassword = false
  → MainFrame
  → 进入系统主界面

首次密码账户不会先看到主界面，这是客户端的第一层隔离。

登录-3 用户提交登录

LoginFrame.submitLogin() 从密码框取得 char[]，清空输入框并禁用按钮，然后异步调用登录服务。

CompletableFuture<LoginResult> response;
response = users.login(loginId.getText(), submittedPassword);
response.whenComplete((result, failure) ->
        onEdt(() -> finish(result, failure)));

CompletableFuture 代表“未来才会取得的登录结果”。网络线程不会阻塞 Swing EDT，因此窗口不会卡死；完成后再回 EDT 更新界面。

登录-4 公共登录协议与密码保护

UserClientService 使用命令名 USER_LOGIN，请求体是公共模块中的 LoginCommand：

public record LoginCommand(
        String loginId,
        char[] password,
        String clientInstanceId) implements Serializable

密码不用不可变的 String，而使用可清除的 char[]。命令构造时复制密码并清除调用者数组；访问密码时返回防御性副本；发送结束、服务端处理结束和 UI 层都会清零各自持有的数组。

登录-5 Socket 请求发送

ClientConnection 为每个请求生成 UUID，并将命令、token、请求体和时间戳包装为 Message。

Message request = new Message(
        requestId, MessageType.REQUEST, command,
        sessionToken, body, System.currentTimeMillis());

登录前 token 为空。连接内部由一个读线程接收响应，PendingRequests 按 requestId 将响应交给对应 Future；写锁保证多个线程不会把对象流写乱。

登录-6 服务端路由

MessageRouter 根据 message.command() 查找处理器。UserHandlers 把 USER_LOGIN 注册给 UserLoginHandler。

登录处理器检查消息体、调用 UserService.login()、包装成功响应、映射安全错误，并在 finally 中清除命令密码。登录结果含有效 token，因此登录请求刻意不进入持久化响应去重器。

登录-7 账户查询与同账户并发锁

AuthenticationService 先将登录标识执行 strip().toUpperCase(Locale.ROOT)，所以大小写和首尾空格不会影响查询。

AccessUserRepository 使用参数化 SQL 查询账户。账户不存在时统一返回无效凭据并写失败审计；账户存在时按 userId 获取资源锁，使同一账户的并发登录尝试串行执行，避免失败次数和锁定时间相互覆盖。

登录-8 密码验证、账户状态与锁定

重新读取账户
  → 校验密码
  → 密码错误：增加失败次数
  → 密码正确：检查账户状态和锁定状态
  → 重置失败次数并更新最后登录时间
  → 查询角色权限
  → 写成功审计

密码使用 PBKDF2-HMAC-SHA256、16 字节随机盐、120,000 次迭代和 256 位哈希，并使用 MessageDigest.isEqual() 比较。

  • 连续密码错误达到 5 次，锁定 15 分钟。
  • 锁定期间继续尝试不会继续增加次数。
  • 成功登录会把失败次数归零并清除锁定时间。
  • 数据库更新带 rowVersion 乐观锁。

登录-9 创建会话

认证成功后，SessionRegistry 使用 SecureRandom 生成 32 个随机字节并编码为 URL-safe Base64 token。

  • 会话只保存在服务端内存。
  • 默认空闲超时为 30 分钟。
  • 成功鉴权会刷新空闲时间。
  • 服务端重启后所有会话失效。
  • 修改密码会撤销该用户全部会话。

LoginResult 返回 token、用户视图、权限集合和首次改密标志，不包含密码、哈希或盐。

登录-10 客户端保存 Token 并进入主界面

客户端收到成功响应后，把 token 放进共享 ClientConnection。后续请求自动携带该 token。token 只驻留内存，不写配置或数据库，退出客户端即丢失。

普通账户进入 MainFrame。目前图书馆接入真实工作区，学籍、课程、商城和账户设置仍以占位页面为主；五个一级入口固定显示，权限主要用于图书馆内部功能过滤。

登录-11 登录后的服务端鉴权

requireSession(token) 只要求会话存在且未超时；requirePermission(token, code) 还要求会话不是首次改密受限状态，并包含指定权限。

客户端隐藏按钮只是用户体验，真正的安全边界在服务端。首次密码账户即使绕过客户端，也不能调用普通受保护功能。

登录-12 当前实现评价

做得比较扎实：模块职责清晰、异步 UI、密码数组清零、PBKDF2 加盐哈希、失败锁定、资源锁、乐观锁、服务端权限、随机内存 token、会话超时与审计。

当前限制：普通 TCP 没有 TLS；Java 原生反序列化要求两端可信；目前没有自动重连；会话不持久化；一级导航尚未真正按权限过滤；除图书馆外多数业务入口仍未完成。
