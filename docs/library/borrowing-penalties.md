# 图书管理与罚金对接说明

管理员页面为“图书管理 / 借阅管理 / 借阅策略设置 / 罚款记录”。图书管理左侧选择书目，右侧只加载该书副本；新增副本自动使用所选书目，无须再次输入 ISBN。读者页面为馆藏检索、当前借阅、借阅历史与罚款缴纳。

馆藏检索、管理员图书管理和借阅管理支持每页 20 条、上一页和下一页；提交新筛选时回到第一页。馆藏检索和借阅管理表格可横向滚动查看全部列，窄窗口下筛选与操作区分行显示。

## 计费规则

学生和教师分别保存策略及版本。默认规则可在借阅策略设置中修改，金额以元显示、最多两位小数，缴纳使用校园钱包虚拟余额；设为 0 可关闭对应罚金。

| 项目 | 默认值 |
| --- | --- |
| 逾期第 1–7 天 | 0.50 元/天 |
| 逾期第 8–30 天 | 1.00 元/天 |
| 逾期第 31 天起 | 2.00 元/天 |
| 轻度损坏 | 10.00 元 |
| 严重损坏 | 50.00 元 |
| 遗失 | 100.00 元 |

两个分档截至天数和六项金额均可修改。按实际到期时刻计算，逾期不足 24 小时按一天；各档累计，不追溯提高较早天数的单价。例如逾期 31 天为 7×0.50 + 23×1.00 + 1×2.00 = 28.50 元。损坏或遗失赔偿再与逾期罚金相加。

归还或管理员登记遗失时，由服务端使用借阅时保存的身份、当前已保存的策略计算金额，与借阅结束、副本状态变化在同一事务提交。归还损坏书籍后副本标记为“已损坏”；管理员修复后可在副本管理中恢复为可借。借阅中的金额尚未结算，借阅记录中的金额仅表示已经登记的罚金。

## 对接接口

现有服务和网络命令继续可用：

- `LIBRARY_RETURN` / `LibraryService.returnBook`：`ReturnBookCommand.condition` 支持 `NORMAL`、`MINOR_DAMAGE`、`MAJOR_DAMAGE`。
- `LIBRARY_RESOLVE_LOAN` / `LibraryService.resolveLoan`：管理员办理归还或遗失，遗失必须对应 `ReturnCondition.LOST`。
- `LIBRARY_GET_MY_LOAN_HISTORY`、`LIBRARY_SEARCH_ALL_LOANS` 及归还/遗失处理结果中的 `LoanView` 提供 `overdueFine()`、`damageFine()`、`returnCondition()`、`totalFine()`。金额使用 `BigDecimal`，借阅标识使用完整 `loanId`。
- `LIBRARY_GET_POLICIES` / `LIBRARY_UPDATE_POLICY` 的策略对象新增 `PenaltyPolicy penalties`。

### 钱包缴纳

归还或管理员认定遗失后，非零罚款自动出现在读者的“罚款缴纳”中。选择记录、确认金额后，从商店共用钱包扣款；管理员的“罚款记录”只提供查询，不可代扣。两个页面均支持分页。余额不足时仍为待缴，读者可到商店“我的钱包”充值后重试。商店资金明细将显示“图书罚款”及对应借阅标识。

| 命令 | 请求 | 响应 |
| --- | --- | --- |
| `LIBRARY_GET_MY_FINES` | `LibraryFineQuery(page, pageSize)` | `PageResult<LibraryFineView>`，仅本人 |
| `LIBRARY_GET_ALL_FINES` | 同上 | 同上，需要 `LIBRARY_ADMIN` |
| `LIBRARY_PAY_FINE` | 完整 `loanId` 字符串 | `WalletOperationResult(operationId, balanceCents)` |

`LibraryFineView` 包含已结算借阅、钱包收据号和 `paid()` 状态。请求不接受用户 ID 或扣款金额；服务端在缴费专用的 `LOAN`、`WALLET` 锁及共享事务内重新校验归属、已结束状态及已登记金额，再精确换算为整数分。与现有钱包、商城一致，缴费使用独立锁组以避免与开户流程反向获取应用锁；跨模块余额写入由同一个串行 `TransactionManager` 和账户版本校验保护。借阅未结束或罚款为零时不能缴纳。

钱包以 `F:LIBRARY:<loanId>` 作为持久化唯一业务键。重复点击、换请求号重试或服务重启均返回同一收据，不重复扣款；每次重试仍校验当前会话与借阅归属。余额更新、收据和成对流水在同一事务完成，失败整笔回滚。缴费状态直接读取钱包收据，不另存一份可能失去同步的支付状态。回执余额是原缴费时的快照，实时余额以钱包查询为准。罚款不进入商店订单托管，也不计入商家收入。

本次不提供退款或人工减免；已经结算的罚款仍不随之后的策略调整而变化。

## 数据与升级

启动时自动补齐 `tblLibraryPolicy` 的分档和金额列，以及 `tblBookLoan` 的身份、罚金和归还情况列。旧记录金额保持 0，不补算历史罚金；旧借阅身份从用户表补齐。重复启动保留管理员已修改的策略。修改策略仅影响之后的结算，已结束记录的金额不变。

客户端和服务端需同时更新并重启。现有 Java 调用的旧构造方法保留默认参数，但新旧版本跨进程混用不在本次兼容范围内。

钱包缴费复用现有 `051_shop_wallet.sql` 的账户、操作和流水表，无新增表或列。实现与测试不改动分发目录的运行数据库；测试使用临时 Access 库。

## 后续可优化项

1. 为个人借阅历史补齐分页控件，避免只显示首批结果。
2. 到期提醒、逾期筛选与未结算罚金预估，减少读者意外逾期。
3. 损坏程度附加说明或图片，以及罚金人工减免的审批与审计记录。
4. 基于缴费收据增加有审计记录的退款流程。
