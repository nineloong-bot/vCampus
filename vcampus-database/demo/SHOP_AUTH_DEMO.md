# vCampus Shop 认证买家 Demo

此 Demo 使用真实 Socket、用户模块登录、完整 Shop 客户端 UI 和 Access 持久化。请安装 JDK 21 与 Maven，并从仓库根目录启动两个 PowerShell 终端。

需要让其他组员拉取分支并通过 Tailscale 或各自本地验收时，请参阅 [Shop 认证买家 Demo 团队测试指南](SHOP_AUTH_DEMO_TEAM_TESTING.md)。

## 启动顺序

终端一先启动组合服务端：

```powershell
Set-Location -LiteralPath '<仓库根目录>'
.\vcampus-distribution\scripts\start-shop-auth-demo-server.ps1
```

看到 `Shop authenticated buyer demo server started` 后，再在终端二启动客户端：

```powershell
Set-Location -LiteralPath '<仓库根目录>'
.\vcampus-distribution\scripts\start-shop-auth-demo-client.ps1
```

登录账号：

- 登录标识：`DEMO_BUYER`
- 密码：`DemoPassword7`

订单隔离复核账号（只用于验收“我的”页面，不用于购买流程）：

- 登录标识：`DEMO_OTHER_BUYER`
- 密码：`DemoPassword7`

Demo 服务端监听本机可用网络接口的 `19090` 端口；客户端默认连接 `127.0.0.1:19090`，也可通过启动参数连接服务端主机的 Tailscale IP。服务端入口会先初始化数据库，再启动只消费该已初始化数据库的运行时。每次重新启动服务端都会恢复固定 Demo 数据。

## 固定商品目录

Demo 每次会创建四个营业店铺和恰好 100 件在售商品：校园文具店 10 件“文具”、校园书店 30 件“图书”、校园生活超市 55 件“生活用品”、校园药店 5 件“药品”。搜索结果每页 20 件，因此全量目录有 5 页，图书有 2 页（20 + 10），生活用品有 3 页（20 + 20 + 15）；文具和药品按精确数量验收。

统一关键词框会同时匹配五类字段：商品名可用 `速干`，店铺名可用 `校园书店`，分类可用 `药品`，描述可用 `宿舍卫生`，SKU 名可用 `组合装`。`组合装` 应命中每第 5 件商品，共 20 条不重复结果。价格、库存和销量均为固定且有差异的值；首页和搜索结果选择销量降序时保持非升序。

## 文件位置

以下路径均相对于仓库根目录：

- 数据库：`vcampus-database/demo/vcampus-shop-auth-demo.accdb`
- 服务端日志：`target/shop-auth-demo/logs/server.log`
- Shop 业务日志：`target/shop-auth-demo/logs/business.log`

日志只记录业务命令、结果和非敏感业务标识；不要向日志或问题报告复制会话凭据或任何真实支付资料。支付页只执行本地模拟支付。

## 人工验收清单

1. 使用 `DEMO_BUYER` 登录，确认主窗体显示当前用户；左侧原有“校园商城”是唯一商城入口，点击后进入含“← 返回 / 我的 / 购物车（数量）”的商城内部工具栏，侧栏不新增第二个商城入口。
2. 首页确认搜索栏、文具/图书/生活用品/药品四个分类入口、“猜你喜欢”和销量降序商品卡。依次进入四分类，核对数据库级固定总数为 10 / 30 / 55 / 5；在全量、图书和生活用品结果中实际点击“上一页 / 下一页”，核对 20 条页大小下分别为 5 页、20 + 10 两页、20 + 20 + 15 三页，并确认首尾页对应方向按钮禁用。
3. 使用同一个关键词框依次搜索 `速干`、`校园书店`、`药品`、`宿舍卫生`、`组合装`，分别验证商品名、店铺名、分类、描述、SKU 名五种匹配；`组合装` 返回 20 件不重复商品，命中 SKU 不应复制商品或改变卡片最低价。
4. 首次进入搜索页时确认只有主关键词操作，筛选项未展开；完成一次搜索后“筛选”出现，点击可显示分类、最低价、最高价、排序，再点一次可隐藏。设置条件并搜索后进入任一商品详情，点击“返回”，确认关键词、筛选显隐、价格/分类/排序均保留。
5. 在首页、搜索结果或店铺结果点击“下一页”、向下滚动，打开一个商品再点“← 返回”，确认回到原列表、原查询页码和原滚动位置；翻页后滚动位置应从顶部开始，且翻页不会新增商城返回历史。
6. 进入“黑色速干中性笔”详情，选择标准规格（`demo-stationery-001-sku-1`），数量 `2` 加入购物车；打开购物车核对单价、数量、合计及工具栏总数量，再点“返回”，确认回到原商品详情且数量仍正确。
7. 在开始新的结算/支付前打开“我的”，确认只显示 `DEMO-B-PAID-002`、`DEMO-B-PAID-001`，顺序从新到旧；展开明细核对固定商品、SKU、数量和金额，确认 `DEMO-B-PENDING-001` 与 `DEMO-O-PAID-001` 均不可见。订单较多时页面应可纵向滚动。
8. 关闭客户端并以 `DEMO_OTHER_BUYER` 新会话登录，打开“我的”，确认只显示 `DEMO-O-PAID-001` 和 ¥32.70，不能看到前述两笔买家订单；关闭客户端后重新以 `DEMO_BUYER` 登录继续购买。
9. 在购物车进入结算，提交后选择支付宝模拟成功；确认结果为 `SUCCEEDED`，页面不要求真实卡号、账户或验证码，并同时显示“继续购物”和“查看已支付订单”两个安全出口。
10. 点击“查看已支付订单”，确认新支付订单出现在两笔固定 PAID 之前，购物车已清空，商城“返回”不会回到已经完成的结算页。要复核另一出口，重启服务端恢复夹具并再次完成购买，点击“继续购物”，确认回到默认首页且返回也不会进入已完成结算。
11. 检查 `target/shop-auth-demo/logs/business.log`，应出现 `SHOP_GET_PAID_ORDERS`、`SHOP_CHECKOUT` 与 `PAYMENT` 事件。关闭服务端后检查数据库：买家购物车项为 `0`；本次支付尝试为 `1`；支付状态为 `SUCCEEDED`；`demo-stationery-001-sku-1` 的预留为 `CONSUMED`；库存由 `10` 降至 `8` 且 `reservedQuantity=0`；`demo-stationery-001` 的 `salesCount` 由 `500` 增至 `502`。

自动化 `ShopAuthEndToEndTest` 还会用同一个显式协议 `requestId` 重放支付，并验证库存、预留、销量和支付尝试次数全部保持 exactly once。
