# vCampus 全模块批量测试包

本包包含当前整合版客户端、服务端和独立 Access 测试数据库。数据为合成测试资料，基准日期为 2026 年 9 月 7 日。

## 启动与登录

1. 完整解压压缩包，保持 `lib`、`config`、`data`、`database` 等目录在一起。电脑需安装 Java 21 或更高版本。
2. 双击包根目录的 `start-server.bat`，等待监听 **18888** 端口，保持窗口开启。
3. 双击同一目录的 `start-client.bat`。
4. 使用下表账号登录，统一密码为 **`Test12345`**。学生账号是 9 位一卡通号。
5. 测试结束先关闭客户端，再在服务端窗口按 `Ctrl+C`。重新解压到另一个目录可恢复初始数据。

本包使用独立的 18888 端口和 `data/vCampus.accdb`；原项目服务仍使用 8888。请从本包启动客户端以连接这批数据。

## 分模块手动测试

### 学籍与用户管理

- 用 `TESTADMIN` 登录，进入学籍档案，测试姓名/一卡通/学号搜索、分页、院系—专业—班级联动筛选。
- 前 900 名学生为正常学籍；第 901–930 名休学，第 931–970 名已毕业，第 971–1000 名已退学。这些为状态筛选与权限验证样例。
- 所有生成账号均为启用状态。学籍异常的学生可以登录，但选课资格会受学籍规则限制。
- 进入账户设置 → 账户管理，查找任意学生并测试初始化密码。初始化后该账号密码变为 `12345678`，下一次登录必须改密；其余账号仍使用 `Test12345`。
- 姓名存在重名，使用唯一的一卡通号定位具体测试人员。联系邮箱使用 `example.com`，证件号为合成护照格式。

### 课程与教师

- 教师登录后查看自己的课程与课表；管理员查看全部 240 个教学班。
- `213260001` 初始有 3 条有效选课和 1 条退选历史。可测试课程078的B班正常选课，课程040的B班满员、课程002的A班时间冲突、课程120的B班关闭。
- 当前正式选课阶段为开放。需要测试退改补选时，由管理员先关闭正式选课阶段，再开放退改补选阶段。
- 精确课程、教学班 ID 与重修步骤见 [课程测试场景](课程测试场景.md)。

### 图书馆

- 搜索“测试卷”或类别，检查分页、馆藏、书籍详情。500 种书中 490 种启用、10 种停用。
- 420 条借阅覆盖：200 条有效、100 条逾期、100 条已归还、20 条遗失；教师与学生均有样例。
- 用 `213260001` 借阅条码 `TEST-LIB-0001-2` 并归还；管理员可查看全部借阅记录。
- 用 `213260201` 检查逾期记录及相应借阅限制。
- 借阅记录是固定日期的历史样例，有效借阅的初始到期日为 **2026-09-27**；历史借期为合成场景长度，新借阅按系统当前政策计算。日期推移后，系统可将样例判断为逾期。

### 商城

- 买家 `213260101` 查看购物车、继续支付待支付订单，尝试不同模拟支付结果。
- 店主 `213260001` 进入卖家工作区，检查商品、规格、库存和本店订单；商品包含上架、草稿、下架、售罄和停用规格。
- 管理员审核 `213260036` 的开店申请；检查暂停营业店铺与驳回记录。
- 待支付样例的库存预留有效至 **2026-09-14 12:00**，用于继续付款测试；日期过后需重新生成或新建订单。
- 备货、已发货、已完成是数据库状态覆盖样例，当前程序尚无对应的发货/完成操作入口。
- 详细状态分布与精确账号见 [商城测试场景](商城测试场景.md)。

## 验证与数据维护

- 全库 5,178 项数量、引用、金额、库存和密码检查通过，全部 1,057 个账号密码已核对。
- 已在数据库副本上通过真实 Socket 服务验证：五种账号场景、课程/图书/商城查询、店主权限、正常选课、借还书、购物车/订单查询、待支付订单付款及首次改密标志。
- 初始化保留一卡通流水号 1000；模拟递增为 1001 后再次启动，流水号仍为 1001，避免新增学生撞号。
- 交付数据库保持生成后的初始状态，运行验证使用另外的副本。详细证据见 [验证记录](验证记录.txt)。
- `tools` 包含生成器、生成 SQL、数量清单、构建及验证工具；每个程序工具文件不超过 200 行。生成器日期固定在本包基准日，重新制作其他日期样例时可修改 `generate.py` 中的 `now`。
- 独立包的种子脚本将流水号初始化限定为 `currentValue < 1` 时执行；原项目源码及数据库未改变。
- 恢复初始测试状态时，停止本包服务并重新解压到新目录。不要用原项目的重置脚本替换本包数据。
