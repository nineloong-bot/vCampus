# 课程模块批量数据

生成入口：`courses.generate(add, now)`。全部记录使用 `bulk-` 主键前缀，日期依据总生成器提供的时间。独立执行 `python courses.py` 可运行内存关系与规则校验。

| 表 | 新增记录 |
| --- | ---: |
| tblTerm | 2 |
| tblCourseSelectionPhase | 2 |
| tblCourse | 120 |
| tblCourseOffering | 240 |
| tblCourseSchedule | 240 |
| tblEnrollment | 2720（2700 ACTIVE，20 DROPPED） |
| tblCourseAttempt | 100（75 FAILED，25 PASSED） |
| tblEnrollmentAdjustment | 20（补选阶段未开放的失败审计） |

依赖身份：`bulk-student-0001` 至 `bulk-student-0900` 为 ACTIVE 学籍；教师用户为 `bulk-teacher-001` 至 `bulk-teacher-050`。900 名学生每人当前学期恰好 3 门课程；前 50 人第一门是有历史 FAILED 依据的 RETAKE。三组课程分别安排在周一、周二、周三，教师同日分配不同节次；师生均无重叠。每班 `enrolledCount` 等于 ACTIVE 选课数，退选不计入容量。

当前学期为 `bulk-term-current`，状态 ACTIVE，代码 `BULK-CURRENT-YYYYMMDD`；历史学期 `bulk-term-previous` 为 CLOSED，日期在一年前。服务按 termCode 降序选首个 ACTIVE 学期，BULK 代码排在原始数字代码种子学期之前。生成器不改写原种子学期。当前选课窗为生成时间前 14 天至后 30 天，退改补选窗为后 31 至 45 天。

**手动阶段决定实际选课权限**：`bulk-phase-enrollment` 为 ENROLLMENT/OPEN；`bulk-phase-adjustment` 为 ADJUSTMENT/DRAFT。全库必须仅有一个 OPEN 或 PREVIEW 阶段，原始 SQL 种子无阶段记录。管理员测试退改补选时先关闭正式选课阶段，再开放退改补选阶段；日期窗口本身不会自动切换阶段。

## 可直接复现的场景

以下均使用学生 `bulk-student-0001`（登录身份映射 `bulk-student-user-0001`）：

| 操作对象 | 预期 |
| --- | --- |
| `bulk-enrollment-0001` / `bulk-offering-001` | 已选课程001，类型 RETAKE，有 FAILED 历史；可以退选 |
| `bulk-offering-002` | 同课程另一班，重复选课被拒绝 |
| `bulk-offering-003` | 课程002与已选课程001同为周一第1–2节，时间冲突 |
| `bulk-offering-080` | 课程040 B班，11/11 满员，且与该学生当前课表不冲突 |
| `bulk-offering-240` | 课程120 B班 CLOSED、0/40，教学班未开放 |
| `bulk-offering-150` | 课程075 B班，周二第3–4节；有 FAILED 历史，允许重修选课 |
| `bulk-offering-152` | 课程076 B班；有 PASSED 历史，不能再次选课 |
| `bulk-offering-156` | 课程078 B班，周二第3–4节；无修读历史，正常选课可用 |
| `bulk-enrollment-dropped-001` / `bulk-offering-238` | 已退选历史，DROPPED；当前课程119可重新选择 |

`bulk-adjustment-001` 是学生1在正式选课期请求补选课程075被拒绝的审计，错误码 `COURSE_ADJUSTMENT_NOT_OPEN`，目标 `bulk-offering-150`。

验证涵盖：2700 个 ACTIVE 选课的学籍范围、同学生同课程唯一、同学生同班唯一、无师生时间冲突、无 CLOSED 班活动选课、人数与容量一致、重修均有 FAILED 依据、已通过课程没有活动选课、唯一开放阶段。2026-09-07 在内存执行全部断言通过；数据库整体验证由总生成器负责。
