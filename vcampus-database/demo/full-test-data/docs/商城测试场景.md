# 商城展示测试场景

商城样本由 `tools/shop.py` 生成，使用当前 `050_shop.sql` 至 `054_shop_governance.sql` 结构。店铺、商品、订单、钱包和治理记录先在内存中校验，再写入 `generated.sql`。

## 主要对象

- 6 家店铺：青禾文具铺、拾光书屋、梧桐生活馆、行知运动小铺、麦香校园食坊、晚风杂货铺。
- 72 件具体命名商品、144 个规格，使用 `book`、`pen`、`cup`、`bag`、`shirt`、`box` 预置图片编号。
- 18 个订单，覆盖待付款、待发货、待收货、已完成、取消、退款审核中和已退款。
- 4 条经营资质：通过、待审核、驳回、已到期；商品限制分别覆盖资质限制和管理员紧急下架。
- 21 条钱包操作、42 条钱包分录、12 条订单托管记录，买家付款、退款和店主收入均保留业务键。

## 账号

统一密码为 `123456`。管理员为 `TESTADMIN`；店主账号为 `213260001` 至 `213260006`；买家演示账号为 `213260101` 至 `213260105`。完整账号、余额和场景见 [商城展示数据库交付说明](../../../docs/shop/商城展示数据库交付说明.md)。

## 边界场景

1. `213260101` 演示多规格购物车、部分选择结算和多件待付款订单。
2. `213260102` 演示余额不足，`213260103` 演示零余额充值。
3. `213260104` 演示误选规格后的整单退款审核和退款到账。
4. `TESTADMIN` 演示开店申请、资质审核、商品举报、紧急下架和恢复申请。
5. 晚风杂货铺保持暂停营业；其已付款历史订单仍保留，不把店铺恢复误作为商品或资质恢复。
6. 商品目录保留一个软删除商品及其历史订单关系，普通商品列表不应再展示它。

## 导入样例

`outputs/商城展示/商品导入演示样例.xlsx` 是正常样例，`outputs/商城展示/商品导入混合校验样例.xlsx` 包含负价格、专项资质类目、无效图片编号和重复默认规格。两份样例不预写入数据库。

## 验证

运行：

```text
python3 -m unittest discover -s vcampus-database/demo/full-test-data/tools -p 'test_*.py'
```

数据库需要在临时路径构建后运行 `BuildDataset` 和 `ValidateDataset`。校验内容包括主键、外键、订单金额、规格库存、钱包分录和治理状态；通过后再替换发布数据库。
